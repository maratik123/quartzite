# GPU snapshot tests in CI

**Source:** issue #192
**Date:** 2026-05-10
**Tracked in:** #192

## Scope

Add CI coverage for the graphics path so rendering regressions are caught
on every PR. Four deliverables, each clearly bounded in this plan:

1. **Offscreen GPU render harness** (`quartzite-renderer`) — a
   `RenderHarness` type that bypasses winit, owns a `wgpu::Adapter` /
   `Device` / `Queue` configured for an offscreen `wgpu::Texture`, walks
   the widget tree calling `WidgetExt::paint`, hands the resulting
   vello scene to `vello::Renderer`, and reads pixels back into an
   `image::RgbaImage`. Public API surface: `RenderHarness::new(size)`
   (async-via-`pollster`-internally so the harness is sync at the test
   boundary) and `harness.render_widget(&widget) -> RgbaImage`.
2. **Perceptual-diff snapshot infrastructure** — a `snapshot_assert!`-style
   helper that takes (test name, `RgbaImage`), looks up the corresponding
   golden PNG under `tests/snapshots/<backend>/<test_name>.png`, runs a
   perceptual diff, and either passes (within tolerance), fails with
   uploaded artifacts, or skips entirely when `SKIP_RENDER_SNAPSHOT=1`.
3. **`gpu-tests` CI matrix job** — three OS variants in
   `.github/workflows/ci.yml` driving the snapshot suite against
   software / WARP / Metal backends, with artifact upload on failure
   and an actionlint-clean workflow.
4. **Linux-only `xvfb-run` end-to-end smoke test** — one test that
   opens a real winit `EventLoop` + window inside `xvfb-run`, renders
   one frame through the production code path (not the offscreen
   harness), and exits cleanly. Catches surface-creation, event-loop,
   and windowed-resize regressions that the offscreen harness cannot
   exercise. The smoke test does **not** snapshot the frame — exit
   code is the assertion.

The widget-side snapshot suite covers **5 primitives**: `Label`,
`Button`, `LineEdit`, `BoxLayout`, `GridLayout`. Canvases are 64×64 or
128×128.

**Renderer-readiness note:** `VelloPainter` is currently a no-op skeleton
(its `Painter` methods do nothing) and no widget overrides
`WidgetExt::paint`. This plan lands the harness now: goldens encode the
clear-colour state and are regenerated by follow-up render PRs as
widget paint code lands. (Resolved Q1.)

## Out of scope

- Implementing actual rendering inside `VelloPainter` (its `Painter`
  methods are currently no-ops). That is its own work item; this plan
  produces snapshots of *whatever the renderer emits today*, which for
  `Label` / `Button` / etc. is currently the clear colour. Goldens are
  regenerated by follow-up PRs as render code lands.
- Implementing `WidgetExt::paint` overrides on `Label`, `Button`, etc.
  Same reason as above.
- Conformance / fuzz testing of the renderer (vello upstream's job).
- Performance / benchmark CI (separate issue).
- A `quartzite-widgets`-side benchmarking pass against snapshots.
- Snapshotting / pixel-asserting the `xvfb-run` end-to-end frame
  (frame content is exercised by the offscreen suite; the windowed
  test asserts on clean startup + clean shutdown, not pixels).

## Key decisions

| Question | Decision |
|---|---|
| Land snapshot harness now (vs block on real rendering)? | **Land now** (Q1 resolved). Build the harness + 5 widget snapshots against today's no-op renderer. Goldens encode the clear-colour state and get regenerated by later render PRs. |
| Snapshot storage? | **In-repo PNGs** (Q2 resolved). Goldens committed under `quartzite-widgets/tests/snapshots/`. No git-LFS, no separate assets repo. Per-backend subdirs keep the per-PR diff small even when one backend regenerates. |
| `xvfb-run` end-to-end winit test in this plan? | **Yes, in v1** (Q3 resolved). One Linux-only test wrapped in `xvfb-run` that opens a real winit `EventLoop` + window, renders one frame, and exits. Lives in the renderer crate (covers the windowed pipeline the offscreen harness cannot). Asserts only on clean startup + clean exit (no pixel comparison). |
| Perceptual-diff crate? | **`nv-flip` 0.1.** Per issue body preference and use by wgpu/vello. Acknowledge staleness (see Deferred); revisit once renderer emits real pixels. `image-compare` 0.5 is the documented fallback if `nv-flip` proves blocking. |
| Linux software backend? | **`mesa-vulkan-drivers` + `lavapipe`** via apt on `ubuntu-latest`. `WGPU_BACKEND=vulkan` + `WGPU_ADAPTER_NAME=llvmpipe` + `LIBGL_ALWAYS_SOFTWARE=1`. **Fallback if mesa-shipped lavapipe is too old for vello compute:** kisak-mesa PPA first (simplest, single `add-apt-repository` step); `jakoch/install-vulkan-sdk-action` only if PPA also lags. `vulkaninfo --summary` runs as a sanity step before the test job so log output diagnoses driver issues quickly. |
| Windows backend? | WARP — `WGPU_BACKEND=dx12`, `WGPU_ADAPTER_NAME=Microsoft`. No driver install needed on `windows-latest`. |
| macOS backend? | Real Metal GPU — `WGPU_BACKEND=metal`. No fallback configured (Metal is hardware on `macos-latest`). |
| Per-backend snapshot dirs? | `quartzite-widgets/tests/snapshots/{vulkan,dx12,metal}/<test_name>.png`. One dir per `WGPU_BACKEND` value used in CI. |
| `SKIP_RENDER_SNAPSHOT` env var? | **Yes.** When set to any non-empty value, snapshot tests `eprintln!` a skip notice and return `Ok(())` without GPU work. Pattern from xilem PR #233. The `xvfb-run` smoke test honours the same env var. |
| Failure artifacts? | On snapshot mismatch, write `<test_name>.actual.png` and `<test_name>.diff.png` next to the golden, then `actions/upload-artifact@v7` (verify live tag at design time) the directory. Test fails with a message pointing reviewers at the artifact URL. |
| `scripts/update-snapshots.sh`? | Yes; takes optional `--backend {vulkan,dx12,metal}` flag (default: all available locally). Sets a `QUARTZITE_REGENERATE_SNAPSHOTS=1` env var; the snapshot helper writes the new golden in that mode instead of comparing. Script does **not** run the `xvfb-run` smoke test (no goldens to regenerate there). |
| Where do snapshot tests live? | `quartzite-widgets/tests/snapshots.rs` — integration test in the widget crate. The widgets crate is the natural home (it owns the primitives under test) and gains a `dev-dependencies` line on `quartzite-renderer` for the harness. Keeps `quartzite-renderer/tests/` reserved for renderer-side tests. |
| Where does the `xvfb-run` smoke test live? | `quartzite-renderer/tests/xvfb_smoke.rs` — exercises the full windowed pipeline, including the production `Application` boot path. Belongs in the renderer crate, not widgets. Test is gated on `cfg(target_os = "linux")` so non-Linux platforms compile cleanly and skip it. |
| Where does the `xvfb-run` test run in CI? | Inside the existing **Linux** lane of the `gpu-tests` matrix job, as a step that runs **after** the offscreen snapshot tests, wrapped in `xvfb-run -a cargo test -p quartzite-renderer --test xvfb_smoke`. Avoids a separate matrix dimension; reuses driver setup. The step has its own diagnostic-logs collection on failure. |
| Test-side gating? | Snapshot tests and the `xvfb-run` smoke test are **NOT** `#[ignore]`-gated. The `gpu-tests` CI job runs them by default. Local contributors without a usable GPU run with `SKIP_RENDER_SNAPSHOT=1`. The existing `cargo test --workspace` job in CI sets `SKIP_RENDER_SNAPSHOT=1` so non-GPU lanes stay fast. |
| Crate-feature gate on `nv-flip` / harness? | None for v1. Both the harness and the perceptual-diff dep are unconditional `dev-dependencies` of `quartzite-widgets`. If wasm or a no-default-features lane breaks, design phase introduces a feature gate. |

## Technical constraints

- `nv-flip` 0.1 (verified current 2026-05-10 — `max_stable_version 0.1.2`)
  is the perceptual-diff crate; track upstream via the deferred item above.
- `image` 0.25 (verified current 2026-05-10) for `RgbaImage` + PNG IO.
- `image-compare` 0.5 (verified current 2026-05-10) is the documented
  fallback in the design; not added to `Cargo.toml` unless `nv-flip` proves
  blocking.
- `winit` 0.30, `wgpu` 29, `vello` 0.8 (already pinned in
  `quartzite-renderer/Cargo.toml`).
- Pinning rule: `0.x` form per AGENTS.md § *Dependency Versions*.
- The `gpu-tests` CI job follows the existing CI patterns in
  `.github/workflows/ci.yml`: `dorny/paths-filter` gate, `Swatinem/rust-cache@v2`
  with `shared-key`, `mozilla-actions/sccache-action`, a corresponding
  `gpu-tests-pass` aggregator that treats `skipped` as success. Live tags
  for `actions/upload-artifact` and `actions/checkout` queried at design time.
- Workflow file MUST pass `actionlint .github/workflows/ci.yml` before
  `git add` (AGENTS.md axiom).
- `RenderHarness` must construct synchronously at the test boundary
  (uses `pollster::block_on` internally for the `wgpu::Instance`
  request_adapter call). Tests that call `RenderHarness::new(size)`
  must not need to be `#[tokio::test]` or similar.
- Existing renderer test pattern (one process = one Application
  singleton) does NOT apply to the offscreen suite: the harness does
  NOT construct a `quartzite_runtime::Application`; it operates on a
  widget tree directly. This is critical because the snapshot suite
  must run many tests in one process. The `xvfb-run` smoke test, in
  contrast, **does** construct a real `Application` + `EventLoop` and
  therefore must run as its own process invocation (`cargo test
  --test xvfb_smoke` runs alone — the test binary contains a single
  test fn).
- `xvfb-run` smoke test constraints: gated on `cfg(target_os =
  "linux")`; honors `SKIP_RENDER_SNAPSHOT=1`; uses the same
  `WGPU_BACKEND=vulkan` + `WGPU_ADAPTER_NAME=llvmpipe` env as the
  offscreen Linux lane; runs **after** the offscreen suite in the same
  job (driver install is shared); a hard 60-second test timeout
  applies (event-loop hangs would otherwise consume the whole job
  quota — `xvfb-run` itself does not timeout the inner process).
- Linux apt step pins lavapipe to a single source (`mesa-vulkan-drivers`
  default first, kisak-mesa fallback). Driver source MUST be visible in CI
  logs (`vulkaninfo --summary` step output).
- Linux apt step also installs `xvfb` (one extra package; available in
  the default Ubuntu repos).
- `quartzite-widgets/tests/snapshots/` PNGs are tracked binary files
  (no LFS); contributor education in `CONTRIBUTING.md` for regeneration.
- `Cargo.lock` is committed per AGENTS.md; the `nv-flip` + `image` adds
  show up there.

## Acceptance Criteria

| #    | Criterion |
|------|-----------|
| AC1  | `quartzite-renderer` exposes a public `RenderHarness` type whose `RenderHarness::new(width: u32, height: u32)` returns `Result<Self, RendererError>` and whose `render_widget(&self, widget: &impl WidgetExt) -> RgbaImage` (or equivalent — design phase finalises the trait bound) renders the widget offscreen and returns the readback. |
| AC2  | A snapshot helper (e.g. `quartzite_widgets::test_support::snapshot_assert(name, image)`) compares against `quartzite-widgets/tests/snapshots/<backend>/<name>.png` using `nv-flip` (or the documented fallback) and fails with `actual.png` + `diff.png` written next to the golden on mismatch. The backend dir name is derived from `WGPU_BACKEND` and falls back to `auto` when unset. |
| AC3  | `quartzite-widgets/tests/snapshots.rs` contains five passing snapshot tests covering `Label`, `Button`, `LineEdit`, `BoxLayout`, `GridLayout`. Goldens are committed under `quartzite-widgets/tests/snapshots/<backend>/`. The five tests pass in the `gpu-tests` CI job on at least one backend at PR merge time. |
| AC4  | `SKIP_RENDER_SNAPSHOT=1` causes every snapshot test (and the `xvfb-run` smoke test) to skip with a clear `eprintln!` notice and pass. The existing `cargo test --workspace` matrix in CI sets this env so its runtime is unaffected. |
| AC5  | A new `gpu-tests` matrix job in `.github/workflows/ci.yml` runs on `ubuntu-latest` (vulkan/lavapipe), `windows-latest` (dx12/WARP), and `macos-latest` (metal). Each platform installs the necessary drivers per the *Technical constraints* section, runs `vulkaninfo --summary` on Linux for diagnostics, and executes `cargo test -p quartzite-widgets --test snapshots`. The new job is wired into a `gpu-tests-pass` aggregator that treats `skipped` as success. |
| AC6  | On snapshot test failure, `actions/upload-artifact` uploads `quartzite-widgets/tests/snapshots/**/*.actual.png` and `**/*.diff.png` so reviewers see what changed. Successful runs upload nothing. |
| AC7  | `scripts/update-snapshots.sh` regenerates goldens locally. The script accepts an optional `--backend {vulkan,dx12,metal}` flag (default: all backends discoverable locally) and writes results into the matching per-backend directory. |
| AC8  | `CONTRIBUTING.md` gains a *GPU snapshot tests* section explaining: how to run snapshots locally, how to skip via `SKIP_RENDER_SNAPSHOT=1`, how to regenerate via `scripts/update-snapshots.sh`, what to do when a snapshot diff is intentional (review the `.actual.png` artifact, run the regen script, commit), and how the `xvfb-run` Linux smoke test fits in. |
| AC9  | `actionlint .github/workflows/ci.yml` passes; `cargo fmt -- --check`, `cargo clippy --workspace -- -D warnings`, `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace`, and `cargo build -p quartzite --no-default-features` all succeed. |
| AC10 | `Cargo.lock` is updated and committed; the `nv-flip` 0.1 and `image` 0.25 (or fallback `image-compare` 0.5) versions in the workspace match the live `crates.io` `max_stable_version` at the time of merge per AGENTS.md § *Dependency Versions*. |
| AC11 | `quartzite-renderer/tests/xvfb_smoke.rs` contains a `#[cfg(target_os = "linux")]` test that constructs an `Application` + winit `EventLoop`, renders **one** frame through the production windowed pipeline, and exits with code 0. The test is invoked via `xvfb-run -a cargo test -p quartzite-renderer --test xvfb_smoke` in the Linux lane of the `gpu-tests` job, **after** the offscreen snapshot step. The Linux apt install step gains `xvfb`. The test honours `SKIP_RENDER_SNAPSHOT=1` (skip + pass) and has a 60-second hard timeout. |

## Open questions

- Once `VelloPainter` emits real pixels, perceptual-diff tolerance will
  need real-world calibration (current default lands as a single number
  in design). False-positive rate after first real-render PR will tell us
  whether a per-test threshold is needed.
- `nv-flip` 0.1.2 was last published in June 2023. It still works, but
  its compute-shader path may lag wgpu major-version bumps. If it blocks
  a future wgpu upgrade, switch to `image-compare` 0.5; the design notes
  this contingency. Tracking decision belongs in a follow-up issue once
  the renderer emits real pixels.
- The `gpu-tests-pass` aggregator's `skipped`-as-success policy mirrors
  the existing `*-pass` aggregators in `ci.yml`; review during
  implementation in case the path-filter gate changes shape (e.g. if a
  future PR introduces a snapshot-only paths filter).
- Whether the `xvfb-run` smoke test should later snapshot its frame
  (currently exit-code-only) is parked in *Deferred* — design phase may
  surface details about the production windowed-frame format that
  affect that future decision.
