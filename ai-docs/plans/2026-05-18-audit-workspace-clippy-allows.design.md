# Design: Audit all workspace clippy `allow`s from #423

**Issue:** #477 (closes #443–#453)
**Date:** 2026-05-18

## Approach

The spec already provides a full survey (441 hits across 15 lints), the decision framework (Keep / Narrow / Fix), and the scoping primitives (workspace allow vs per-crate `[lints.clippy]` vs per-item `#[allow(reason = "…")]`). The design's job is to (a) commit to a concrete decision per lint up-front so implementation is mechanical, (b) bundle the 11 audits into ≤ 7 logically-grouped subtasks so the work fits the project decomposition ceiling, and (c) order subtasks so each one ends with a green `--all-targets` clippy run (no half-resolved warnings sit in the tree across subtask boundaries).

### Audit-to-subtask grouping

The 11 audits map to 7 subtasks. The grouping clusters audits by **decision class + touched-file overlap**, so each subtask is one focused commit that leaves `cargo clippy --workspace --all-targets -- -D warnings` green:

- Subtask 1 — reconnaissance + workspace-allow → warn flip survey rerun (sanity-check the spec's hit counts against the live tree; no `Cargo.toml` edits).
- Subtask 2 — Keep-only audits (#4 `must_use_candidate`, #5 `return_self_not_must_use`, #6 `significant_drop_in_scrutinee`, #8 `redundant_pub_crate`, #9 `missing_const_for_fn`, #14 `type_complexity`): refresh comments in root `Cargo.toml` with surveyed counts and corrected file lists. Tree must still be green (no allow removed yet).
- Subtask 3 — Cast family Narrow (#1, #2, #3): per-crate `quartzite-widgets` block + per-item `#[allow]`s + remove the three workspace allow lines. Run clippy gate.
- Subtask 4 — `items_after_statements` Narrow (#11) + `option_if_let_else` Fix (#12): per-crate `quartzite-style` block + per-item `#[allow]`s + the 8 case-by-case rewrites; remove both workspace allow lines.
- Subtask 5 — `significant_drop_tightening` Narrow + partial Fix (#7) + `needless_pass_by_value` Fix (#13) + `struct_excessive_bools` Narrow (#15): per-crate `quartzite-runtime` block (covering 8 prod-side runtime hits); `drop(guard)` rewrites in `widgets/tests/support_internals.rs`; per-item `#[allow]`s on the cited sites (incl. 2 in `core/connect.rs`); remove the three workspace allow lines.
- Subtask 6 — `float_cmp` Narrow (#10): per-crate `quartzite-paint-api` + `quartzite-style` blocks; `# #[allow(clippy::float_cmp)]` hide-markers in doctest blocks; remove the workspace allow line. **Doc gate (AC10) executed end-of-subtask.**
- Subtask 7 — final verification gauntlet (AC4 / AC8 / AC9 / AC10 / AC11 simultaneously) + PR body composition (per-lint table + AC checklist + `Closes #443 #444 …` line).

### Rejected alternatives

1. **One subtask per audit (11 subtasks).** Exceeds the 7-task ceiling stated in the design-agent rules; spec also explicitly batches all 11 into one PR. Rejected.
2. **One subtask per decision class (3 subtasks: Keep, Narrow, Fix).** Over-coarse — the Narrow bucket would touch 6+ crates in one commit, making review hard and bisect useless if a regression slips in. Rejected.
3. **Pure ε-tolerance doctest rewrite for `float_cmp`.** Loses the "exact representable value" contract the assertions document; pulls a comparison helper into a leaf crate that's currently helper-free. Rejected.
4. **Workspace allow → `warn` posture flip without per-crate narrowing.** Would leave the 441 hits unresolved at workspace level; not what the spec asks for. Rejected (only listed for completeness).

## Handoff plan

`M = 7` subtasks → three groups (3 + 3 + 1):

- **Group A:** subtasks 1–3 — reconnaissance, Keep-only comment refresh, Cast-family Narrow. Entry: spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). This is the initial implementation chunk; subtask 3 is the first one that removes workspace allow lines, so it ends with a real clippy gate.
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group B with fresh context.
- **Group B:** subtasks 4–6 — Style + macros tidy, drop/by-value/bool-struct narrowing, `float_cmp` resolution. Each ends with the clippy gate; subtask 6 additionally runs the doc gate.
- **Handoff after Group B:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group C with fresh context.
- **Group C:** subtask 7 — terminal group (1 subtask; within the 1..=3 range). Enters under the handoff named after Group B above. Final verification + PR body composition.

## Risks

- **Risk: Subtask 3 / 4 / 5 / 6 may discover a per-item rewrite that triggers a cascading lint elsewhere (e.g. `option_if_let_else` rewrite into `map_or_else` triggers `redundant_closure_for_method_calls`).** Mitigation: each subtask ends with `cargo clippy --workspace --all-targets -- -D warnings`; if a new warning appears, prefer per-item `#[allow]` with a `reason = "…"` over chaining rewrites. Spec already authorises case-by-case judgement for `option_if_let_else`.
- **Risk resolved (Group A, subtask 3): Per-crate `[lints.clippy]` blocks are impossible when `[lints] workspace = true` is set — Cargo 1.95 rejects the combination.** Resolution: all narrows use per-item `#[allow(clippy::..., reason = "…")]` instead. No per-crate `Cargo.toml` edits are needed; all subtask file lists updated accordingly. AC11 (no-default-features build) remains unchanged since no `Cargo.toml` lint table modifications occur.
- **Risk resolved (Group A, subtask 1): `float_cmp` hits in `paint-api/color.rs` (23) and `paint-api/font.rs` (3) are all in `#[cfg(test)]` blocks, not doctest blocks.** Resolution: no doctest hide-markers needed; all 51 float_cmp hits receive per-item `#[allow]`. Doc gate (AC10) still runs at end-of-Subtask 6 as a verification pass.
- **Risk: `drop(guard)` rewrites in `widgets/tests/support_internals.rs` change snapshot test ordering and break a snapshot.** Mitigation: Subtask 5 runs the test suite end-of-subtask, not just clippy. Snapshot test helpers should not depend on lock-release ordering in deterministic fashion; if a snapshot does break, the rewrite caused a latent ordering bug worth fixing.
- **Risk: `type_complexity` comment refresh (Subtask 2) loses context that the original PR #423 author had for citing `connect.rs` / `factory.rs`.** Mitigation: the new comment names the surveyed sites (`object_tree.rs` / `wrapped_handler.rs`) explicitly; if `factory.rs` or `connect.rs` ever regains a hit, the comment is correctable in a future audit pass.
- **Risk: PR diff is too large for review (15 lints, multi-crate).** Mitigation: subtask-per-commit granularity gives the reviewer a per-decision diff to walk. PR body table maps each lint to its commit hash if helpful.
- **Risk: API change in Subtask 5 (`wrapped_handler.rs` signature change for `needless_pass_by_value`) is a breaking API change.** Mitigation: AGENTS.md *API Stability* axiom — pre-publish, clean breaks are policy. Renames cascade to call sites in the same commit (the subtask file list already covers it).

## Test Design

This task is entirely lint-driven and does not introduce new logic; the verification surface is **the existing gate stack** rather than new tests.

- **Per-subtask gate**: `cargo clippy --workspace --all-targets -- -D warnings` after each of subtasks 3, 4, 5, 6. Must exit 0.
- **End-of-subtask-6 doc gate**: `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features` — verifies the `# #[allow(clippy::float_cmp)]` doctest hide-markers compile and render correctly (AC10).
- **End-of-subtask-5 test gate**: `cargo test --workspace` — verifies the `drop(guard)` rewrites in `widgets/tests/support_internals.rs` did not break snapshot tests (AC8).
- **End-of-subtask-7 final gauntlet** (AC4, AC8, AC9, AC10, AC11):
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo test --workspace`
  - `cargo fmt -- --check`
  - `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features`
  - `cargo build -p quartzite --no-default-features --features libm`

The only "new" test surface that could be argued is regression tests against the `option_if_let_else` rewrites (Subtask 4) and the `wrapped_handler.rs` signature change (Subtask 5). Both areas already have unit tests in the crates' existing `#[cfg(test)]` modules (`quartzite-core/src/signal.rs` covers signal flow; `quartzite-renderer/src/wrapped_handler.rs` has its own test mod). The full `cargo test --workspace` run is sufficient regression coverage; no new test files are warranted by the YAGNI principle.
