# Design: Docs cleanup post-#197 — `all-features = true` propagation, intra-doc-link audit, and bare-backtick conversion

**Issue:** [#199](https://github.com/maratik123/quartzite/issues/199)
**Date:** 2026-05-10
**Spec:** [`2026-05-10-docs-cleanup-197.spec.md`](2026-05-10-docs-cleanup-197.spec.md)

## Approach

Mostly-mechanical docs/metadata change. Four parts that share a single root
cause (intra-doc references render or link as silently as the build
configuration permits) are bundled into one PR per the spec's *Key decisions*
table. The new substantive work is **Part C** — an audit + conversion pass
across `src/**/*.rs` for backticked identifier mentions in prose. Parts A, B,
and D are unchanged from the prior design round.

### Part A — `all-features = true` propagation

Insert `all-features = true` as the **first** line of every leaf-crate
`[package.metadata.docs.rs]` block, matching the byte-shape already present in
`Cargo.toml` (umbrella) and `quartzite-core/Cargo.toml`:

```toml
[package.metadata.docs.rs]
all-features = true
rustdoc-args = ["--cfg", "docsrs"]
rustc-args = ["--cfg", "docsrs"]
```

Verified by direct file inspection that all 11 leaf crates currently carry the
identical 3-line block (no `features` / `all-features` line). The diff is
therefore `+1 line` per crate, with zero edits to `rustdoc-args` /
`rustc-args` (spec *Out of scope*).

**Why "everywhere," even for crates with no `[features]` table today?**
Decision recorded in spec *Key decisions*: the convention is "everywhere" per
`ai-docs/doc-convention.md` § *Feature-gated documentation*; a no-op today
guarantees no future contributor adds an optional feature without docs.rs
picking it up. The change is one line per crate; the cost of *not* doing it is
a future silent regression.

**Rejected alternative:** apply only to crates with `[features]` today
(`quartzite-runtime`, `quartzite-geometry`). Rejected because it leaves a
booby-trap for future maintainers and contradicts the convention that landed
in #197.

### Part B — crate-prefixed intra-doc-link audit (no source edits)

Spec records that the audit pass was completed during interview and all
candidate intra-doc links target a direct dep of their linking crate.
Re-verified during this design pass: `rg -c '\[`?\w+`?\]\(quartzite_\w+::'
--type rust` reports `src/lib.rs:17`, `quartzite-style-types/src/color_role.rs:1`,
`quartzite-renderer/src/lib.rs:1`, `quartzite-renderer/src/render_harness.rs:1`
(17/1/1/1 line-counts across the 4 known files; `rg -o … | wc -l` returns 24
total occurrences because several lines in `src/lib.rs` carry multiple links).
The direct-dep claim was spot-checked against `quartzite-renderer/Cargo.toml`
and `quartzite-style-types/Cargo.toml` (both list the linked crates as direct
path-deps). **No source files change.** AC6 re-runs the same `rg -c` post-edit
as the verification artefact.

### Part C — bare-backtick → intra-doc-link conversion across `src/**/*.rs`

Audit + conversion pass over every doc comment in the workspace
(`find . -name '*.rs' -path '*/src/*' -not -path './target/*'` reports **99
files**, ~8 055 doc-comment lines, ~25 882 total source lines). Two patterns
to convert:

- **Bare TitleCase identifier** in prose: `` `Object` `` → `` [`Object`] `` (when
  in scope per the spec's *Conversion criteria* table).
- **Bare qualified path with crate prefix** in prose:
  `` `quartzite_runtime::snapshot::capture_object` `` →
  `` [`quartzite_runtime::snapshot::capture_object`] `` (when the leading crate
  is a direct dep).

The full criteria table is in spec § *Part C — Conversion criteria* and
governs every decision; this design does not duplicate it.

**Crate batching.** Audit + convert one crate at a time, running the doc gate
after each batch (12 crates total: umbrella `src/` + 11 leaves). The 12th
batch is also the AC10 final run. Per-batch sequencing isolates any bad-link
regression to one crate's diff and keeps the doc-gate signal actionable
("which crate's links broke?"). The spec's single-commit constraint is
preserved: batches are working-tree checkpoints, not git commits.

**Per-batch loop.**

1. Generate the candidate list for the crate:
   `rg -n '`[A-Z][A-Za-z0-9_]+`' <crate>/src/ --type rust` for TitleCase, plus
   `rg -n '`quartzite_[a-z_]+::[A-Za-z0-9_:]+`' <crate>/src/ --type rust` for
   qualified paths.
2. For each candidate, apply the spec's criteria table — convert in place or
   leave bare with a one-line justification when the choice is non-obvious.
3. Run `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps -p
   <crate> --all-features` (per-crate doc gate).
4. After all 12 batches, run the workspace-wide
   `cargo doc --no-deps --workspace --all-features` once (this is AC10).

**Rejected alternative — single all-files-in-one-pass.** Rejected because a
single doc-build failure across ~37–150 conversions across 12 crates would
require bisecting a large working tree to find the bad link. Per-crate
batching reduces the bisect surface to one crate at a time at zero commit
cost.

**Rejected alternative — automated converter script.** Rejected. The criteria
table requires human judgement (e.g., "English noun in TitleCase like
`Object` as a concept" vs. "type `Object` as identifier" — same token, opposite
action); a regex-based converter would either over-link (introducing broken
links the doc gate would catch but the contributor would have to undo) or
under-link (defeating the audit). Manual per-crate is faster than writing,
testing, and reviewing a converter for a one-shot job.

**Inventory bound.** Spec inventory cites ~37 candidate sites in `lib.rs`
files alone, plausibly 50–150 across `src/**/*.rs`. With 99 source files and
~8 055 doc-comment lines, the candidate density is ~0.6–1.9% of doc lines —
consistent with the spec estimate and tractable in a single PR.

### Part D — combined doc-convention paragraph (Parts B + C)

Append a single section (with **three** short before/after pairs) to the
existing **Linking and code references** section of `ai-docs/doc-convention.md`
(currently at lines 359–374), immediately after the existing fourth bullet
about cross-crate links. The section codifies three related rules per spec
§ *Part D*:

1. **Cross-crate links must target direct dependencies** (verbatim from the
   prior design round — re-route through a re-exporting direct dep, or demote
   to bare backticks).
2. **Backticked TitleCase identifiers in prose should be intra-doc links when
   in scope** (`` `Foo` `` → `` [`Foo`] `` when `Foo` is in own crate or a
   direct dep; bare for placeholders, feature names, English nouns).
3. **Bare qualified paths follow the same direct-dep rule** (`` `pkg::path::T` ``
   → `` [`pkg::path::T`] `` when `pkg` is a direct dep; bare otherwise — the
   `quartzite-core` mentioning `quartzite_runtime::*` case is the worked
   example, since the link is *structurally impossible* and a "fix" would
   introduce a broken link).

One worked before/after pair per rule (3 pairs total), each shorter than a
full Rust example because the demonstration is a single `///` line.

**Voice / structure constraints** (read from the existing section to match):

- Bulleted list at the top (existing four bullets); the three new rules join
  as bullets 5–7 to keep parallel structure.
- The before/after pairs follow the bullets as a small fenced block (one
  fenced block per pair, three blocks total). Surrounding sections
  (*Conforming example*, *Non-conforming example*) use full-fn fenced Rust
  blocks; intra-doc-link pairs are shorter and live inline.
- Imperative phrasing matching the existing fourth bullet ("Cross-crate
  links use the workspace crate name…").

the changes share a root cause and produce a single coherent diff; per-crate
commits would inflate the log with mostly-identical doc-comment edits.
Per-batch doc-gate runs (task 4) are working-tree checkpoints, **not** git
commits — the final commit (task 9) covers the entire diff.

## Risks

- **Cargo.lock drift:** metadata-only edits should not touch the lockfile, but
  AC8 explicitly checks. **Mitigation:** task 8 verifies `git diff Cargo.lock`
  is empty before commit. If non-empty, investigate (most likely cause: a
  stale local working tree). Do **not** stage `Cargo.lock` unless a real dep
  change is found.
- **Docs.rs build under `--all-features` regresses (Part A):** PR #197 already
  proved the umbrella + core compile docs under `--all-features`; the leaf
  crates individually have either no features or one optional feature already
  exercised by the umbrella's `--all-features` path. **Mitigation:** task 8
  runs the doc gate workspace-wide pre-commit. If a leaf crate's
  `--all-features` doc build fails, the failure points at a real broken link
  that escapes the current per-crate default-features build — fix in the
  same PR rather than dropping `all-features = true`.
- **Bad intra-doc link from Part C breaks the doc gate (NEW, primary Part C
  risk):** a single mis-converted link (wrong path, missing brackets, or a
  TitleCase that doesn't actually resolve in scope) trips
  `#![deny(rustdoc::broken_intra_doc_links)]` and fails AC10. With ~50–150
  conversions across 99 files, an all-at-once approach would force a manual
  bisect of a large working tree. **Mitigation (primary):** per-crate batching
  in task 4 — `cargo doc --no-deps -p <crate> --all-features` runs after each
  batch, isolating any failure to one crate's diff. **Mitigation
  (secondary):** when a candidate's resolution is ambiguous, prefer leaving
  bare over guessing; the spec criteria table treats bare as the safe
  default. **Mitigation (tertiary):** the workspace doc gate (AC10) is the
  final safety net catching any cross-crate link the per-crate gate missed
  (e.g., a re-export visibility quirk).
- **Audit miss — leaving a candidate bare that should be linked:** the doc
  gate cannot catch this (rustdoc has no "should be a link" lint, per spec
  § *Part C*). **Mitigation:** AC11 is a manual spot-check of 5 cited
  inventory sites; if any are still bare, the audit was incomplete and task 4
  re-runs for the affected crate. The acceptance bar is "in-scope candidates
  identified by the spec inventory are converted"; an exhaustive guarantee
  across 8 055 doc-comment lines is explicitly out of scope (the criteria
  table is the contract, not a 100% conversion target).
- **False-positive conversion of an English noun (e.g., `Object` as a
  concept):** the criteria table flags this case, but a converter operating
  on regex matches alone could over-link. **Mitigation:** per the design's
  rejected-alternative rationale, conversion is manual; each candidate is
  judged against the criteria table in context. Over-link errors are caught
  by the doc gate (the linked item won't resolve) or by the AC11 spot-check
  (the rendered link points at the wrong thing).
- **Doc-convention paragraph collides with existing voice (Part D):** the
  section already has four bullets and a clear imperative tone.
  **Mitigation:** drafting constraints listed in *Part D* above (bullets 5–7,
  parallel structure, imperative phrasing). Self-review during task 3
  confirms the new bullets read cohesively with the existing four.
- **AGENTS.md Workflow Axiom 1 violation:** user is currently on
  `fix/docs-features-serde` (a feature branch from prior work). **Mitigation:**
  task 1 explicitly creates `fix/docs-cleanup-197` off `master` (or off the
  current branch if the user wants to layer on top); no `Edit`/`Write` runs
  until `git branch --show-current` returns the new branch.
- **PR body sync (AGENTS.md Axiom 2):** after the first push (which opens the
  PR), subsequent pushes during review require `gh pr view <N>` reads.
  Initial push is exempt per the axiom. Post-review fixup pushes (likely with
  Part C, given the audit surface) trigger the sync rule.

## Test Design

No new `#[cfg(test)]` modules. Part A is metadata-only; Part B is verification-
only; Part C edits doc comments only (no semantic / API changes); Part D edits
a markdown file. The spec's *Acceptance criteria* are the test plan;
verification is grep + build/clippy/doc gates plus two manual spot-checks
(AC11, AC12).
