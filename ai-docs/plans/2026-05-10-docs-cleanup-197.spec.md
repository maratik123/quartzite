### Part C — convert bare-backticked identifier mentions to intra-doc links

Surfaced during implementation kickoff: doc comments across the workspace contain many backticked identifier mentions in prose that are **not** wrapped as intra-doc links. Two distinct patterns:

- **Bare TitleCase identifier** — e.g., `` `Object` `` instead of `` [`Object`] ``.
- **Bare qualified path with crate prefix** — e.g., `` `quartzite_runtime::snapshot::capture_object` `` instead of `` [`quartzite_runtime::snapshot::capture_object`] ``.

Both render as inert code-style text rather than clickable cross-references. Rustdoc has no lint for "should be a link" — these can only be caught by an audit pass.

|---|---:|---:|---:|

**Qualified `crate_name::path` references (subset; full pass on `src/**/*.rs`):**

| File | Bare qualified-path mentions in doc comments | Notes |
|---|---:|---|
| `quartzite-core/src/lib.rs` | 1 (`quartzite_runtime::snapshot`) | Forced bare — `quartzite-runtime` is downstream of `quartzite-core`, not a dep. Cannot be linked. |
| `quartzite-core/src/snapshot.rs` | 4 (`quartzite_runtime::snapshot::capture_*` / `restore_*`) | Same — forced bare. |

| `quartzite-core/src/snapshot/tree.rs` | 3 | Same. |

In every case located so far, the qualified-path target is in a crate that is **not** a direct dep of the linking crate, so the link cannot be created — bare backticks are the only valid option. Part C's deliverable for these is therefore an explicit audit confirmation, not source edits. The convention paragraph (Part D) must call out this case so a future contributor doesn't try to "fix" them by introducing broken links.

#### Conversion criteria

| Identifier shape | Action |
|---|---|
| Bare TitleCase: type / trait / macro / fn defined in this crate | Convert to `` [`Name`] `` |
| Bare TitleCase: type from a **direct** dep | Convert to `` [`Name`](direct_dep::Name) `` if disambiguation needed; else `` [`Name`] `` if the use is unambiguous |
| Bare TitleCase: type from a **transitive / non-dep** crate | Leave bare — cannot be linked from here. Document the reason in commit message if non-obvious. |
| Bare qualified path `pkg::path::Item` where `pkg` is a direct dep | Convert to `` [`pkg::path::Item`] `` (rustdoc resolves the full path) |
| Bare qualified path `pkg::path::Item` where `pkg` is **not** a direct dep | Leave bare — link is structurally impossible (e.g., `quartzite-core` mentioning `quartzite_runtime::*`). Convention text covers this case explicitly. |
| Generic placeholder (`T`, `Self`, `K`, `V`) | Leave bare — not a real item |
| Cargo feature name (`` `serde` ``, `` `std` ``, `` `derive` ``) | Leave bare — features have no doc page |
| English noun in TitleCase (`Object` as a concept, `Cargo` the tool, `OSS`, `GUI`) | Leave bare — prose, not an identifier |
| Method or field name in TitleCase prose | Leave bare unless the parent type is in scope and the method has a doc page that the link can target (rare) |

**Verification:** `cargo doc --no-deps --workspace --all-features` exits 0 (already AC3). Any link the converter writes that fails to resolve trips `#![deny(rustdoc::broken_intra_doc_links)]` immediately. Bare candidates left intentionally are documented inline (commit message or short justification) when the choice is non-obvious.

### Part D — combined doc-convention paragraph covering Parts B and C

Append a single section (with three short before/after pairs) to the existing **Linking and code references** section of `ai-docs/doc-convention.md`, codifying three related rules:

1. **Cross-crate links must target direct dependencies.** Crate-prefixed intra-doc links (`[Type](other_crate::path)`) must point at a direct dep of the linking crate. If the linked type lives in a transitive dep, either re-route through a direct dep that re-exports it (the fix used in `src/lib.rs:319-320` in #197 — `quartzite_style_types::ColorRole` → `quartzite_style::ColorRole`), or demote the link to plain backticked prose.
2. **Backticked TitleCase identifiers in prose should be intra-doc links when in scope.** When prose mentions a type/trait/macro/fn by name in backticks (`` `Foo` ``), wrap it as an intra-doc link (`` [`Foo`] ``) when the identifier resolves to an item in scope (own crate or direct dep). Leave bare when the candidate is a generic placeholder (`T`, `Self`), a feature name (`` `serde` ``), or an English noun that happens to be capitalized.
3. **Bare qualified paths follow the same direct-dep rule.** Backticked qualified paths in prose (`` `quartzite_runtime::snapshot::capture_object` ``) should be wrapped as intra-doc links (`` [`quartzite_runtime::snapshot::capture_object`] ``) when the leading crate is a direct dep of the linking crate. When it isn't (e.g., `quartzite_core` mentioning `quartzite_runtime::*` — runtime is downstream of core, not a dep), the link is structurally impossible — leave bare. Don't introduce a broken link to "match the convention"; bare backticks are the correct rendering when the dep graph forbids the link.

One worked before/after pair per rule (3 pairs total).

## Out of scope

- The `--all-features` doc-gate convention itself — landed in #197.
- A custom CI script to enforce the direct-dep rule — `rustdoc::broken_intra_doc_links` already covers any feature combination CI builds, so the convention text plus the existing lint and the `--all-features` gate are sufficient.
- Reviewing or modifying the `rustdoc-args` / `rustc-args` lines in any crate — only `all-features` is added.
- Any change to the umbrella `Cargo.toml` or `quartzite-core/Cargo.toml` (already converted in #197).
- Conversion of bare-backticked identifiers that are **not** in scope (e.g., types from optional `dev-dependencies`, or types from features not enabled in the linking crate's default feature set). These remain bare; the convention permits it.
- Method-call prose (`` `foo()` ``, `` `Foo::bar` ``) — out of audit scope unless the link target has its own rustdoc page and the conversion is unambiguous.

- `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features` must continue to pass (already passes post-#197). This is the primary safety net for Part C — any bad intra-doc link the converter writes is caught by `#![deny(rustdoc::broken_intra_doc_links)]`.

- No edits to `Cargo.lock` are expected (metadata-only and doc-comment changes don't touch lockfile resolution).
- Branch must be a feature branch (`fix/docs-cleanup-197`) — never edit on `master`. AGENTS.md *Workflow* axiom 1.
- The `ai-docs/doc-convention.md` edit triggers no Propagation Rule sync-group (it is not in any sync group); no other instruction file mirrors this convention text.
- Part C edits touch doc comments only — no code semantics, no public-API shape changes, no test additions required. Test surface is the doc-build gate.
