**Rejected alternatives:**

1. **One mega-commit covering all six surfaces.** Rejected — landing the Q-C enum mirror across `AGENTS.md`, `self-improve.md`, `learnings-escalation-audit.md`, `corrections-log.md` in the same commit as the AGENTS.md propagation greps blurs the audit trail of "is the Learning-Log group still synchronised?" Splitting by group makes the propagation rule's enforcement legible to future readers. The implementation still produces a single PR per spec § Technical constraints, but commit boundaries can mirror the subtask boundaries for clarity.
2. **Inline the `Escalated?` enum table from `learnings-escalation-audit.md` into AGENTS.md as the single source of truth.** Rejected — would invert the existing Propagation-Rule semantics (right-now: AGENTS.md is the declaration site, the two agents are parse-sites). Schema-changing the relationship is out of spec's scope; the task is to add one enum value, not restructure the surface contract.
3. **Use `.claude/rules/` as a glob in the new Agent Docs row (e.g., `.claude/rules/*.md`) rather than the specific `.claude/rules/ast-index.md` path.** Rejected — the existing `.claude/skills/spec-writer.md` etc. row pattern uses specific filenames; matching that convention keeps the table grep-friendly. When a second rule file lands, a second row will join the first (same pattern as `.claude/skills/triage/SKILL.md` + `.claude/agents/triage-runner.md`).
4. **Phase the Q-C enum into `AGENTS.md:322` only first, defer parse-site mirrors to a follow-up PR.** Rejected — directly violates the Learning-Log group propagation row at `AGENTS.md:211`. Phasing would land a `rules:[name]` value that neither agent recognises, producing immediate `❓ Ambiguous` findings during the next `/ai-audit` Phase 1 run.
5. **Drop the dedicated `.claude/rules/<file>.md` Propagation-Rule row and rely on the "Any other instruction file" fallback at `AGENTS.md:221`.** Rejected by spec § Key decisions row 6 ("**Add a dedicated row** for explicitness").
6. **Hand-edit `ai-docs/deferred/_inbox.md` to satisfy AC6.** Rejected — `AGENTS.md:185` AXIOM forbids hand-edits; `/task` Step 12's PIPEBULLET3 auto-extractor (see `.claude/skills/task/inbox-propagation.md` Shape rule 3) parses the amended spec's § Deferred row into the required form: field 1 + ` — ` + field 2 → `scripts/check-instruction-file-sizes.sh (#383) — not landed yet; must NOT include .claude/rules/ in scan list (Q-A semantics)`. AC6's grep `grep -n '#383' ai-docs/deferred/_inbox.md | grep -i 'claude/rules'` matches the auto-extracted row verbatim. Subtask 9 collapses to a verification grep.

## Handoff plan

M = 10 subtasks. With the maximum non-terminal group size of 3 consecutive subtasks and terminal-group sizing in `1..=3`, the boundary computation is 3 + 3 + 3 + 1 → four groups (grouping by theme).

- **Group A:** subtasks 1–3 — three mechanical AGENTS.md propagation edits (grep-path append + Agent Docs row + dedicated Propagation row). Initial implementation chunk; entered via the design's first `/context-reset` handoff per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry).
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group B with fresh context.
- **Group B:** subtasks 4–6 — Checklist M corpus add (`reference.md`) + start of Q-C enum propagation (AGENTS.md:322 declaration site + first parse-site mirror in `learnings-escalation-audit.md`).
- **Handoff after Group B:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group C with fresh context.
- **Group C:** subtasks 7–9 — remaining two Q-C enum mirrors (`self-improve.md` + `corrections-log.md`) + AC6 verify-only step.
- **Handoff after Group C:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group D with fresh context.
- **Group D:** subtask 10 — terminal group (1 subtask; within the 1..=3 range). Acceptance-criteria grep verifier + AC5 demonstrator. No commit produced here; outputs land in the PR body and the design-review trail. Completes Step 8 in its own `/context-reset` subagent.

## Risks

- **Risk: AGENTS.md size-cap pressure (pre/post `wc -c`).** AGENTS.md is at 35,528 chars on master — already inside the 35,000–39,999 proactive-extraction band declared by the AXIOM at `AGENTS.md:62`. This PR adds edits across subtasks 1 / 2 / 3 / 5 (Propagation grep paths × 2, Agent Docs row, dedicated Propagation row, Escalated enum value) summing to an estimated +500 to +700 chars; projected post-edit size is **~36,200 to ~36,400 chars**, still well below the 40,000 hard cap with **~3,500+ chars of headroom**. **Accepted-risk justification:** remaining headroom > 3,500 chars; no extraction warranted in-PR. **Mitigation:** AC7's instruction-file size scan line in § Test Design reports the post-edit `wc -c AGENTS.md` and confirms `< 40,000` (with explicit numeric output, not silently passing). If the actual post-edit count exceeds 36,500 chars (signalling estimation drift), flag in the PR body and consider light copy-trim before push.
- **Risk: M = 10 exceeds the 7-task design-agent guideline.** Accepted because the spec is a cross-cutting integration pass touching six distinct surfaces (AGENTS.md Propagation Rule, AGENTS.md Agent Docs, AGENTS.md Escalated enum, `reference.md` Checklist M corpus, three Learning-Log-group parse sites, deferred-row verification). Splitting violates the Learning-Log group propagation contract at `AGENTS.md:211` (Q-C enum + all four parse sites MUST land in the same PR). **Mitigation:** the 4-group handoff plan (Groups A–D, each ≤ 3 subtasks) bounds context-window pressure per `/context-reset` segment. No further split warranted.
- **Risk: AGENTS.md:62 / :70 char-cap covered file set ↔ Q-A omission.** Future readers may assume the Q-A omission is an oversight rather than a deliberate decision. **Mitigation:** the spec records Q-A's rationale (rule files are on-demand; don't pay per-invocation cost) and AC6's auto-extracted `_inbox.md` row carries the same semantics forward to `scripts/check-instruction-file-sizes.sh` (#383). No additional in-file documentation needed; the AXIOM body at `AGENTS.md:62` retains its explicit enumeration of covered files and a future reader who runs the Propagation grep on a `.claude/rules/` edit hits the new dedicated row that explains the omission.
- **Risk: enum positioning in `AGENTS.md:322`.** Inserting `rules:[name]` between `agent:[name]` and `doc-convention` clusters the per-surface-named values together (`skill:[name]` … `agent:[name]` … `rules:[name]`) versus inserting at the tail (after `code-style`). **Mitigation:** chose adjacent-to-`agent:[name]` placement because the per-surface convention (`skill:` / `agent:`) is the existing cluster and `rules:` joins it naturally; tail placement would split the cluster with the un-namespaced single-token values (`hook` / `settings` / `doc-convention` / `code-style`) in between. Trivially reversible if design-review disagrees.
- **Risk: `learnings-escalation-audit.md:60–65` Step 2 verification bullets diverge from the table at `:22–37`.** Both describe the same enum from different angles (declaration vs. parse). Subtask 6 must edit both blocks consistently. **Mitigation:** the subtask description names both line ranges explicitly and marks the bullets edit REQUIRED (not optional). Self-review checklist item: `grep -c 'rules:' .claude/agents/learnings-escalation-audit.md` should report ≥ 2 (one in the table, one in the Step 2 bullet list).
- **Risk: `corrections-log.md` field glossary insertion point.** The glossary uses sparse blockquote paragraphs separated by `>` blank lines; insertion between `code-style` (line 43) and `Superseded by:` (line 45) must preserve the existing blank-line discipline. **Mitigation:** subtask 8 specifies "immediately after the `code-style =` line and before the `Superseded by:` line"; a trial Read of the file's blank-line pattern is sufficient to nail the exact byte offset.
- **Risk: subtask 7's literal `rules:[name]` token in `self-improve.md` competes with the existing free-prose style of that paragraph.** The :200 enumeration currently uses bare slash-separated words (`AGENTS.md / skill / agent / hook / …`), without the `[name]` parametric form. **Mitigation:** subtask 7 explicitly mandates the literal backticked `rules:[name]` token (matching AGENTS.md:322's typography) so AC3's `grep -n 'rules:\[name\]' .claude/agents/self-improve.md` matches; the parenthetical clarification `(file at .claude/rules/<name>.md)` reconciles the prose style. Post-edit verification: `grep -c 'rules:\[name\]' .claude/agents/self-improve.md` ≥ 1.
- **Risk: AC4 (`/ai-audit` Checklist M zero new findings)** depends on existing `.claude/rules/ast-index.md` being authored to Patterns 1–7. The spec § Technical constraints row 4 asserts this is already true. **Mitigation:** the file's current size (verifiable via `wc -c .claude/rules/ast-index.md` — well under 40k chars) is documented in the PR body as a sanity baseline, even though Q-A exempts the file from the cap.
