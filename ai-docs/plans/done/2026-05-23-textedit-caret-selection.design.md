# Design: TextEdit caret + selection rendering

**Issue:** #317
**Date:** 2026-05-23
**Spec:** [`ai-docs/plans/2026-05-23-textedit-caret-selection.spec.md`](2026-05-23-textedit-caret-selection.spec.md)

## Approach

Build the visual contract from `design-system/proposals/caret-and-selection.md` bottom-up across four pre-existing layers, in the dependency order forced by the trait extensions:

1. **`quartzite-paint-api`** gains two object-safe `&mut dyn`-returning text-measurement methods on `Painter`, plus two new cursor traits (`TextCaretCursor`, `TextVisualLineCursor`) and a `TextVisualLine` POD. Every workspace `Painter` impl (`RecordingPainter` in `quartzite-paint-api`, `quartzite-paint-util`, `quartzite-style`, `quartzite-style-dispatch`, the `NullPainter` test fixtures in `quartzite-style/src/{style,registry,paint_widget}.rs`, the integration-test `RecordingPainter` instances in `quartzite-paint-util/tests/panic_safety.rs` + `quartzite-style/tests/third_party_paint.rs`, and the live `VelloPainter`) gains the two new methods. The test/null impls back the cursors with a fake fixed-width shaper (one cluster per `char`, 8 px advance, line-height = `font.size`). The live `VelloPainter` backs the cursors with its real `parley::Layout` in this PR (subtask 3 scope); Open Question 2 is resolved — the parley-backed implementation lands here, not in a follow-up.

   `VelloPainter` re-uses its existing `Layout<[u8; 4]>` build pipeline (lines 490–549 of `vello_painter.rs`), exposing per-cluster `(byte_offset, x, advance)` and per-visual-line `(byte_range, top, height, x_at)` through `parley::Cluster` + `parley::Line` iteration. Because the cursors borrow `&mut self`, `VelloPainter` lazily allocates a single `Layout` inside `&mut self`'s state (an `Option<Layout<[u8; 4]>>` slot reset on every cursor request) and returns a `&mut dyn` borrow into a struct that owns that `Layout` by `Box` (so the lifetime tied to `&mut self` is honoured). No new persistent state on `VelloPainter`; each cursor call rebuilds the layout (acceptable cost for the snapshot suite — the live renderer's perf optimisation lands in a later spec when real input editing arrives). R1 risk (parley wiring complexity) is accepted (see *Risks → R1*).

2. **`quartzite-style`** grows two new `Style` trait methods (`caret_visible_now`, `prefers_reduced_motion`), a new `StyleClock` struct (owns the start `Instant` + the cadence half-period + an optional pinned phase), and `DefaultStyle` gains a `StyleClock` field forwarding the two `Style` methods to the clock. `DefaultStyle` stops being a unit struct: it becomes a `#[derive(Debug)]` struct with a `StyleClock` field. The existing `#[derive(Clone, Copy, Default)]` no longer applies because `StyleClock` contains an `Instant`; `Clone + Default` are kept via explicit impls (no `Copy`). All in-tree references to `DefaultStyle` as a unit struct (`Box::new(DefaultStyle)`, `DefaultStyle.draw_widget(…)`) become `DefaultStyle::new()` / `DefaultStyle::with_clock(...)` / `DefaultStyle::default()` — a clean break per AGENTS.md *API Stability* AXIOM (pre-publish; no compat shim).

3. **`quartzite-widgets`** grows `TextEdit::caret: usize`, `TextEdit::selection_anchor: Option<usize>`, `TextEdit::selection_changed: Signal<()>`, and the two slot setters `set_caret` / `set_selection_anchor` plus the `selection_range()` inherent helper. `LineEdit` is *not* touched in this PR (#405 is the follow-up).

4. **`quartzite-style/src/default_style.rs`** `Paint<TextEdit>` body grows the caret + selection paint passes per design-proposal §§ 1–8. Helper free functions (`paint_selection`, `paint_caret`, `selection_rects_for_lines`, `caret_rect_at`) live in the same file. Total file growth ~150 lines pushes the file from 388 → ~540 lines, crossing the 500-line soft cap. Refactor strategy: extract `Paint<TextEdit>` into a new sibling module file `quartzite-style/src/default_style/text_edit.rs` (single-widget extraction; minimal API change since the impl block is the only mover); accompanies the existing `default_style_tests.rs` via `#[path]`. This is the AGENTS.md-blessed *file-size* response — refactor before merge.

5. **`quartzite-runtime` integration** lands the `Timer`-driven invalidation seam in-PR. `DefaultStyle` grows an optional `start_blink_timer(driver: Arc<dyn TimerDriver>, on_tick: Arc<dyn Fn() + Send + Sync>)` method that constructs a 530 ms-half-period `Timer` whose `tick` signal invokes the caller-supplied callback (the host/app shell wires the callback to its widget-invalidation pass). The `Timer` is owned by `DefaultStyle` (Drop-cleaned). A `MockTimerDriver` test fixture (lives in `quartzite-style/src/clock.rs` `#[cfg(test)]` plus an integration test) lets the invalidation path be exercised deterministically. **New dep edge:** `quartzite-style → quartzite-runtime` (production dep, gated by a new `runtime-blink` cargo feature **enabled by default** so the live app gets blinking carets without opt-in, while no-std / runtime-less consumers can disable; the read-side `StyleClock` works without the feature). The `runtime-blink` feature gates the `start_blink_timer` method and the runtime dep; with it off, the rest of `quartzite-style` compiles unchanged.

6. **Snapshot tests** under `quartzite-style/tests/snapshots/shared/` (4 light + 4 dark = 8 PNGs) drive `DefaultStyle::with_clock(StyleClock::pinned(true))` through `RenderHarness`. The 530 ms-half-period redraw `Timer` machinery is **not** invoked by these tests (the read-side seam is the only thing the snapshot suite exercises — the invalidation path has its own unit + integration tests using `MockTimerDriver`); the snapshot suite never starts the timer. Unit tests on the `RecordingPainter` in `default_style_tests.rs` cover the symbolic AC checks (rect ordering, rect count, brush colour under each state ladder).

**Rejected alternatives:**

- **Inline iterator returning `Box<dyn Iterator>`** (Round-2 Q2's draft): violates "no allocation on every paint call" and forces the caller to drain before continuing. The borrowed-cursor variant the spec pinned (Round-3 Q2) avoids the box and ties the lifetime to the `Painter` borrow, which is cleaner.
- **Free `caret_visible_now(now, start)` function** instead of the `Style` trait method: the paint path would have to thread the `Instant` through every `Paint<W>::paint` call, polluting every signature. The trait-method seam centralises the dependency on `Style` and lets `DefaultStyle::draw_widget` keep its current parameter list.
- **Add `StyleClock` to `quartzite-paint-api`** instead of `quartzite-style`: `Painter` is widget-agnostic; blink-phase semantics belong to the style layer. Keeps the dep direction `style → paint-api` (one-way) intact.
- **Defer `Timer`-driven invalidation to a follow-up PR**: an earlier draft of this design shipped the `StyleClock` *read-side seam* only and deferred the `Timer`/`TimerDriver` invalidation wiring to a follow-up, to avoid forcing a new `quartzite-style → quartzite-runtime` dep. **Rejected** (product-owner directive 2026-05-23): the spec pins runtime-owned `Timer` reuse (Round 2 Q1), and shipping only the read-side leaves carets static in the live app until the follow-up lands — visible regression. This design adds the `quartzite-style → quartzite-runtime` dep edge and lands invalidation in-PR (subtasks 14 + 15). The dep direction is acceptable because the existing graph already has `quartzite-renderer → quartzite-runtime` and `quartzite-style → quartzite-paint-api → quartzite-renderer` is the indirect path through dev-deps; `quartzite-style` taking a direct production dep on `quartzite-runtime` does not introduce a cycle (runtime has no style-side back-edge).

## Risks

- **R1: Live `VelloPainter` text-cursor implementation lands incomplete and the new GPU snapshot tests cannot capture goldens.** The `parley::Layout`-backed cursor needs to expose per-cluster `(byte_offset, x, advance)` and per-visual-line `(byte_range, top, height, x_at)` — both are first-class concepts in `parley::Layout` (cluster iteration via `Layout::clusters()`, line iteration via `Layout::lines()` since parley 0.3+) but the wiring code has to be written. **Status: accepted (product-owner directive 2026-05-23).** Subtask 3 carves the parley-backed `VelloPainter` impl as in-PR scope; the snapshot tests in subtask 13 depend on it. **Mitigation:** if the parley wiring hits a hard blocker mid-implementation, raise the blocker through `/task` Step 7's *Spec Amendment recipe* + `/task` Step 11's *Design Amendment recipe* (per AGENTS.md Spec-Amendment group) — do **not** silently degrade to a fake-shaper backing on `VelloPainter`. The `RecordingPainter` paths keep the fake shaper; only `VelloPainter` must back the cursor with real parley layout.
- **R2: Adding `caret_visible_now` as a required `Style` trait method (no default-impl) is a breaking change for every out-of-tree `Style` implementer.** AGENTS.md *API Stability* AXIOM permits clean breaks pre-publish, but the third-party-paint test fixture and the dispatch-test `MarkStyle` need updating. **Mitigation:** subtask 5 enumerates every in-tree `Style` impl via `ast-index implementations Style` and updates them in the same commit. Out-of-tree impls don't exist (no `cargo publish` yet). AC11 (`cargo build --workspace` + `cargo clippy --workspace --all-targets -- -D warnings`) catches missed sites.
- **R3: `DefaultStyle` ceasing to be a unit struct breaks doc-tests + every `DefaultStyle` construction site.** Pre-publish AXIOM permits clean break (no `pub use DefaultStyle as …` compat shim). **Mitigation:** subtask 6 explicitly enumerates the migration sites (`ast-index usages DefaultStyle`); the conversion is mechanical (`DefaultStyle` → `DefaultStyle::new()` everywhere). The clippy run on the full workspace catches missed sites.
- **R4: File-size cap on `quartzite-style/src/default_style.rs` is breached before the `Paint<TextEdit>` extraction lands.** **Mitigation:** subtask 7 lands the extraction *before* subtask 9 (which adds the ~150 lines). Group ordering enforces this (Group C runs 7 → 9). The subtask dependency graph also encodes it (subtask 9 `Depends on` 7).
- **R5: `Painter::text_carets`/`text_visual_lines` returning `&mut dyn` ties the cursor lifetime to the `&mut self` Painter borrow.** The caller cannot hold the cursor across two Painter calls (e.g. cannot ask `text_visual_lines` then call `painter.fill_rect` while still holding the cursor). **Mitigation:** subtask 9's `paint_selection` drains the cursor into a `Vec<TextVisualLine>` *before* calling `fill_rect`, then re-walks `text_carets` after the fills are emitted. Slight redundant work; acceptable for the paint path (paint is not on the input-event hot path).
- **R6: Pixel-snapping rules between caret-x (i32, derived from a possibly-fractional parley advance) and selection-rect edges (also i32).** Design-proposal § 1 mandates pixel-snap, no AA; § 4 also mandates integer pixel rects. **Mitigation:** the cursor traits return `i32` directly (not `f32`); each `Painter` impl is responsible for snapping its own advances to pixel boundaries internally before returning the value. Stated in the cursor-trait rustdoc (subtask 1).
- **R7: Round-trip determinism of snapshot goldens across host parley versions.** `parley` shaping can drift across minor versions, affecting the exact pixel-x of glyph clusters. **Mitigation:** the existing snapshot suite already accepts a `FLIP_TOLERANCE = 0.05` perceptual-diff slack which absorbs sub-pixel drift. If `parley` rev bumps push past tolerance, regenerate via the existing `scripts/update-snapshots.sh` pipeline (separate workflow already documented in `quartzite-style/tests/support/mod.rs`).
- **R8: New `quartzite-style → quartzite-runtime` dep edge inverts the historic dep posture.** `quartzite-style` historically had no production dep on `quartzite-runtime`. **Status: accepted (product-owner directive 2026-05-23).** The new edge is added in subtask 14 and gated behind a default-on `runtime-blink` cargo feature so no-std / runtime-less consumers can disable. **Mitigation:** verify with `cargo tree --invert quartzite-style` post-implementation that the addition does NOT introduce a cycle (`quartzite-runtime` has no back-edge to style/widgets in its current `Cargo.toml`); the read-side `StyleClock` works without the feature; downstream consumers who don't run the runtime (no-std, embedded, snapshot harness) can `default-features = false` to drop the dep. The reduced-motion fallback (steady-on) is preserved end-to-end because the path through `caret_visible_now → pinned: Some(true)` short-circuits any wall-clock reads regardless of feature state.
- **R9: AGENTS.md *Propagation Rule* fires** because the snapshot-helper sync-group (`quartzite-widgets/tests/support/mod.rs` ↔ `quartzite-style/tests/support/mod.rs`) MAY need a parallel update if the snapshot-test surface evolves. **Mitigation:** this design does NOT touch either support module; the new snapshot tests in subtask 13 use the existing `snapshot_assert` / `harness_or_skip` helpers verbatim. Confirm in the self-review checklist.
