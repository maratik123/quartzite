# Design: /triage UI-design blocker gate

**Issue:** #545
**Date:** 2026-05-23
**Spec:** [`ai-docs/plans/2026-05-23-triage-ui-design-blocker.spec.md`](2026-05-23-triage-ui-design-blocker.spec.md)

## Approach

Add an **in-band design-work classification gate** to `/triage`, firing per-row at the approval moment (Phase 6 sweep approval / Phase 7 drain promote) and fully resolved before the row reaches the Phase 7.5 bulk `gh issue create` pass. Eleven ACs map onto **five orthogonal mechanism slices**:

1. **Classification (AC1, AC2).** Hybrid keyword scan against the row's `Item ⊕ Source-spec-filename` string. On hit → y/n confirm. On no-hit → orchestrator-internal LLM auto-detect over (i) the `Item` text + (ii) the source-spec section identified by the row's `Source` link, emitting one y/n confirm with a defaulted classification + one-line reason.
2. **Umbrella discovery (AC2, AC5).** Reuse the Phase 4 bulk `gh issue list` map — extend `--json` from `number,state,title` to `number,state,title,labels,body`, map shape `{number → {state, title, labels, body}}`. Filter to `state=OPEN ∧ "ui-design" ∈ labels` at prompt time. **No new round-trip.**
3. **Umbrella selection & linking (AC3, AC4, AC11).** Numbered menu of all open `ui-design` umbrellas, **ordered by descending keyword-overlap score** (tie-break: `#N` ascending). Text options `new` / `none` / `defer`. Numbered pick + `new`: apply `blocked` + `ui-design` labels, prepend `**Blocked by:** #<umbrella>` body line, AND auto-edit the umbrella body (anchor: `## Child issues (blocked on this epic)`, idempotent, anchor-absent fallback emits warning).
4. **Gate ordering & idempotency (AC1, spec §4 + Tech #4).** Gate fires **per-row** at Phase 6 approval / Phase 7 promote — BEFORE the row joins the Phase 7.5 queue. The progress-file partition record gains a `design_link:` sub-field; resume from a partly-prompted partition does not re-prompt (mirrors Phase 4.5's per-conflict resume semantics).
5. **Propagation (AC7, AC10).** Two distinct duties — (a) **spec-merge-time** `/next` SKILL.md grep (recorded below, AC7), (b) `/triage`-runtime grep + optional edit on every umbrella mutation, with grep outcome captured in the Phase 8 run summary (AC10).

The Phase 8 run summary gains a "Design-link outcomes" sub-section (AC6).

### Why this approach

- **Minimal surface area.** Only `.claude/skills/triage/SKILL.md` + `.claude/agents/triage-runner.md` change; the spec is instruction-files-only (AC9). No Rust changes; no workflow files (no `actionlint` gate triggered).
- **Reuses existing mechanisms.** Phase 4 bulk-list reused (no new `gh issue list` call, Tech #3); Phase 4.5's per-conflict resume protocol is the model for the progress-file `design_link:` sub-field; `AskUserQuestion` mid-run is already in-character (Tech #6); the orchestrator-internal LLM call needs no plumbing (it IS the orchestrator).
- **One keyword list, two roles.** The Tech #2 list lives once in `triage-runner.md`. Role (i) trigger and role (ii) overlap signal are co-located so any future list extension keeps both surfaces in lock-step.
- **Anchor-driven body edit, not regex.** `## Child issues (blocked on this epic)` is verified verbatim against #539, #540, #541, #542 (sampled below). Append-before-next-h2 (or EOF) is structurally simple and matches the convention.

### Rejected alternatives

| Alternative | Why rejected |
|---|---|
| **Always-LLM classification (drop keyword scan).** | Spec Q1 explicitly chose hybrid; cold LLM prompt has higher false-positive rate on routine non-visual rows and roughly doubles per-row latency. |
| **Two-prompt gate (1: classify y/n; 2: pick umbrella).** | Spec Scope #2 already collapses to a single confirm on hit and a single confirm + inference on no-hit. Adding a separate "do you want to umbrella-link?" prompt doubles UX cost for the common case. |
| **Separate `gh issue list --label ui-design` call.** | Tech #3 explicitly forbids — Phase 4's existing call already paginates the workspace; adding `labels,body` to the `--json` flag is the lower-cost extension. |
| **Persistent classifier model (sidecar file).** | Out of scope; spec defers to per-run orchestrator inference. No state to persist. |
| **Backfill the 277 existing inbox rows in this PR.** | Spec § Out of scope #1 + AC8 explicit — deferred to a future `/triage --backfill-design-link` one-shot. |
| **Static spec-merge-time edit to `.claude/skills/next/SKILL.md`.** | Spec § Out of scope #2 + Tech #1 first bullet — confirmed grep-empty (below); `/next` queries umbrellas dynamically post-PR-#544 and enumerates no specific umbrella numbers. |
| **Anchor-detection via regex `^##\s+Child issues`.** | Anchor is a single, verbatim, stable string across all four extant umbrellas — substring match is sufficient and simpler. |
| **Per-row keyword-overlap recomputation against ALL umbrellas every prompt.** | At N = 4 umbrellas this is irrelevant cost; the computation is O(rows × umbrellas × keywords) ≈ O(50 × 10 × 23) per run worst-case, dominated by I/O latency on the prompts themselves. No caching needed. |

## Risks

- **R1. LLM-inference cost/latency on no-hit rows.** Per-row no-hit prompt adds one orchestrator-internal inference round (read one spec file + emit a single line). Worst case: a run with 50 design-classified candidates would add 50 spec-file reads — bounded by the 35k-char/file early-warning cap, total read budget is acceptable. **Mitigation:** the read is restricted to the ONE source-spec file the row points at (Task 4), not the whole repo; the inference output schema is one token + one line (≤ 100 chars), not free-form; the user can override the inference with `n` if it errs. The `design_link:` audit trail captures the inference + accept/flip decision so the user can audit the orchestrator's accuracy on a per-run basis.
- **R2. Brittleness of body-anchor parsing.** The anchor `## Child issues (blocked on this epic)` is convention-driven, not enforced. **Mitigation:** Tech #8 fallback path — anchor-absent emits a warning, skips the body edit, falls back to a per-umbrella reminder in Phase 8 (AC6 fallback path). Verified verbatim against all four extant umbrellas (#539–#542) in the propagation-grep step above. Future user-created umbrellas that diverge from the convention surface visibly in the Phase 8 summary rather than corrupting silently.
- **R3. Idempotency edge case — partial body-edit failure.** If `gh issue edit <N> --body-file <tmpfile>` fails mid-run (network error, transient gh API rate limit, etc.), the umbrella body could end up un-edited even though the child issue was created and labelled. **Mitigation:** order of operations is (i) create child with `**Blocked by:** #N` in body + labels, (ii) THEN umbrella body edit. A failed step (ii) is recoverable: the substring-idempotency check (Task 6) means a re-run of `/triage` over the same row would re-apply the umbrella body edit (the child issue already exists with the correct labels and back-reference, so the run wouldn't re-prompt for that row — BUT the umbrella body edit IS idempotent so a manual `/triage --backfill` future one-shot can heal it). Record the edit failure in the Phase 8 summary's separate `Body-edit failed — gh API error` sub-list (distinct from the `Body-edit skipped — anchor absent` sub-list, which is for the structural per-umbrella case; the gh-API-failure case is a transient per-run state) with the explicit `gh issue edit` error message so the maintainer can apply the edit manually.
- **R4. Ranking-tie ambiguity.** Two or more umbrellas with the same keyword-overlap score must be deterministically ordered. **Mitigation:** Spec AC11 explicit tie-break — `#N` ascending (oldest first). Both files document this. Deterministic across reruns; resumable runs produce the same menu order.
- **R5. Resume across `design_link:` partial state.** A run that crashes after writing `design_link:` for some rows but not others must resume cleanly. **Mitigation:** Per-row sub-field write happens IMMEDIATELY after the user's gate decision (mirrors Phase 4.5 per-conflict resolution write timing); Phase 1 re-read picks up exactly the rows with `design_link:` already set and skips the gate for them.
- **R6. Phase 7.5 ordering — umbrella-before-child within the `new` branch.** A row's `new`-branch entry depends on its newly-created umbrella's `#N` for the `**Blocked by:** #N` body line. **Mitigation:** Task 7 specifies that umbrella entries (kind = `umbrella`) sort before child entries (kind = `child`) within the Phase 7.5 collection-order sequence. Implementation: the Phase 7.5 loop iterates umbrellas first, then children; OR equivalently, the queue is partitioned `[umbrellas..., children...]`. This is internal ordering, not a new bulk-call.
- **R7. `triage-runner.md` size growth.** ~~Original projection: 26–28 KB.~~ **Amended 2026-05-23 (post-Group-B):** the original R7 estimate (+4–6 KB total for 10 tasks) significantly underestimated per-task density. Pre-Step-8 size 22,084 chars; post-Group-A 30,409 chars (+8,325 / 3 tasks ≈ 2.8 KB/task); post-Group-B 37,586 chars (+15,502 cumulative / 6 tasks ≈ 2.6 KB/task; **breaches 35k early-warning cap, 2,414 chars from 40k hard cap**). Group B subagent applied a ~5 KB silent compression to Tasks 4 + 6 prose to fit under the 40k cap — that compression is committed in `3f91366` and is acknowledged retroactively here as a Step 8 design-amendment trigger. **Amended mitigation (mandatory for Groups C + D):**
  - **Strict per-task char budgets** for Tasks 7–10 (see Amendment 2026-05-23 § *Group C + D budgets*).
  - **Pre-emptive extraction**: before Group C starts, the verbose Phase 4.5 bridge `Action semantics` block in `triage-runner.md` (currently lines ~157–173, ~3 KB) MUST be extracted to a new sibling reference file `ai-docs/triage-runner-bridge.md`. `triage-runner.md` retains a 2-line pointer (`See [triage-runner-bridge.md](../../ai-docs/triage-runner-bridge.md) § *Bridge action semantics*`). Net savings: ~2.8 KB → post-extraction `triage-runner.md` projected ~34.8 KB, back in the safe band.

Numbers verified in Amendment 3 against `wc -c` and `awk` measurements.
- **R8. Phase 4 dedupe-map `body` field can be large.** With ≥ 450 issues in a workspace, the `body` field per issue could push the in-memory map to several megabytes. **Mitigation:** Phase 4 already runs under the `--limit 500` watchdog (Phase 4 § lines 87–94); the map is in-memory only for the duration of a single `/triage` run; deleted at run-end. The `body` field is only consulted for umbrellas (state=OPEN ∧ label ⊇ ui-design), but the map carries it for ALL issues to preserve "one bulk call per run" — acceptable for the current N ≈ 100–200 open + closed issues. If the workspace grows past the watchdog, the next `/triage` halts with the existing pagination message anyway.
- **R9. Keyword-list noise in ranking.** A common keyword (e.g. `widget`) appearing in many umbrellas' bodies could flatten the ranking signal. **Mitigation:** the initial list of 23 keywords is curated for design-system specificity (`paint`, `palette`, `colorrole`, `caret`, `selection`, `scrollbar`, …); a future list-extension PR can re-tune. The ranking only affects ORDER — all umbrellas remain selectable.

## Test Design

This is an instruction-files-only PR (AC9). **No Rust unit tests** are introduced. The "tests" are behavioural verifications applied during PR review and during the first real `/triage` run after merge. Per CLAUDE.md / AGENTS.md, instruction-file edits do not require `#[cfg(test)]` blocks — but the deliverable must be self-verifying via the following review-time checks:
