# /task Step 8 — every-group handoff redesign

**Source:** user description (free-text, follow-up to #372 / #374 context-rot incident)
**Date:** 2026-05-16
**Tracked in:** #375

## Problem statement

Running `/task` on the sonnet model against a large multi-subtask implementation (PR #374, *Hybrid Paint<W> dispatch*) hit auto-compaction mid-workflow. The post-compaction orchestrator session exhibited **context rot**: Step 9 verify gates were skipped, Step 10 self-review was not spawned, and the N=3-of-M≥5 `/context-reset` handoff was missed. PR #372 had already pre-computed handoff groupings at design time to make the boundaries explicit — but a single long-lived orchestrator session is still the surface that decays under compaction.

The user's mitigation: **every task group (size ≤ 3) runs in its own `/context-reset` handoff subagent — including the first group, and including designs whose total subtask count is 1**. The top `/task` session never executes subtask work itself during Step 8; it stays in a pure orchestrating role (spawn group handoff → parse return → advance state → spawn next group → …). Steps 9 (verify) / 10 (self-review) / 11 (review fixes) remain in the orchestrator's own context — they are presumed short enough to not trigger compaction.

## Scope

1. Amend `/task` Step 8 so the orchestrator never executes subtask work directly. The first task group is spawned via `/context-reset` exactly the same way subsequent groups are today.
2. Replace the "N=3 of M≥5 handoff gate" language with a generalised "every-group handoff" contract: each design-defined group runs in a fresh `/context-reset` subagent, regardless of the group's position (first / middle / terminal) or the total M.
3. Update the design agent's `## Handoff plan` rules so the section is required for **every M (M ≥ 1)** — the prior `M ≥ 5 only / M ≤ 4 auto-PASS` carve-out is removed. The design agent must emit `## Handoff plan` for every decomposition.
4. Update the design-review checklist row in lockstep: the `M ≤ 4 designs auto-PASS` branch is removed; absence of `## Handoff plan` is `major` for any M ≥ 1.
5. Update `/context-reset`'s "When triggered" wording to remove the `N=3, M>=5` trigger pair (replaced by "every group per design's `## Handoff plan`, or compaction detected").
6. Update the orchestrator's per-group bookkeeping: between group returns the orchestrator reads the subagent's progress-file delta (`current_step`, `last_passed_gate`, `Decisions log` tail), re-validates state (branch / base_commit unchanged, no uncommitted dirt), then spawns the next group's handoff. No subtask work is performed in the orchestrator's own context during Step 8.
7. Keep Step 9 (verify), Step 10 (self-review), Step 11 (review fixes) in the orchestrator's own context. They are NOT moved to a final-handoff subagent. The redesign's scope ends at Step 8's last group return.
8. Do NOT pin the top-level `/task` orchestrator to a specific model. Model selection remains per-invocation. Document this as an explicit non-decision in `/task SKILL.md` Step 8 so future readers don't re-litigate it.
9. Synchronise the Task/Design Propagation sync group plus `/context-reset`: `.claude/skills/task/SKILL.md`, `.claude/skills/task/reference.md`, `.claude/agents/design.md`, `.claude/agents/design-review.md`, `.claude/skills/context-reset/SKILL.md`.
10. Append a learning entry to `ai-docs/learnings.md` documenting the PR #374 context-rot incident (Boundary rule 2 Exception — in-flow capture during the implementing `/task`; marked `Escalated? no`).

## Out of scope

- Changing the model assignment of the `design`, `design-review`, `self-review`, `review-findings`, or `spec-writer` subagents (they remain on their current `model:` settings).
- Pinning the top-level `/task` orchestrator to a specific model (e.g. forcing opus). Per Key Decision Q3 the orchestrator stays on whatever model the user invoked `/task` with.
- Moving Step 9 (verify), Step 10 (self-review), or Step 11 (review fixes) into dedicated handoff subagents. Per Key Decision Q2 they remain in the orchestrator's own context.
- Implementing a `SessionStart|compact` hook as an alternative to the heuristic self-detection callout (explicitly rejected upstream — see `context-reset/SKILL.md § Why a callout at all`).
- Rewriting the compaction-recovery callout variant taxonomy (Pattern 7 in `ai-docs/agent-writing-style.md`). The variants stay; only the per-group spawn frequency changes.
- Changing the `/task` Step 1–7 phases (interview, design, design-review). The redesign starts at Step 8.
- Touching `/code-review`, `/pr-commented`, `/pr-ci-failed`, `/master-ci-failed`, or `/bugfix` skill bodies, beyond cross-reference fixes if the N=3 / M≥5 language is grepped from them. (Confirm via grep at design time; out of scope if no hits.)
- Changing `ai-docs/plans/*.progress.md`'s canonical schema fields (`ai-docs/templates/progress-format.md`). The per-group subagent inherits the existing schema verbatim.

## Deferred

- Auto-detecting whether an orchestrator's *own* context is approaching compaction and proactively spinning up a fresh top-level orchestrator session | not blocking; deeper redesign, needs telemetry | yes, separate issue.
- Generalising the every-group handoff pattern to `/code-review`'s phase loop and `/pr-commented`'s round loop | scope-creep into other skills | yes, separate issue when the /task version is proven.
- Moving Steps 9–11 into dedicated handoff subagents (the user's original phrasing implied this; round-1 narrowed it). Revisit if Steps 9–11 are observed to trigger compaction in practice | not blocking now | yes, separate issue if a future incident shows the need.

## Technical constraints

- **AGENTS.md char-cap proximity.** `AGENTS.md` is currently 39,775 chars (early-warning zone: 35k–40k; hard cap: 40k). If this spec's implementation requires an AGENTS.md edit (e.g. AXIOM-level wording for the every-group rule), the implementer must keep AGENTS.md under 40,000 chars — extract verbose subsections into `ai-docs/<topic>.md` if needed (the model PR #324 used for the original AGENTS.md size reduction). The implementing PR MUST run `wc -c AGENTS.md` before commit on every code-producing turn that touches AGENTS.md.
- **Compaction-recovery callout invariants.** The Variant-A callout at the top of `task/SKILL.md` (compaction-recovery) and Variant-C callout at the top of `context-reset/SKILL.md` must continue to survive truncation. Any wording change must keep the `## Compaction recovery (re-entry)` cross-link anchor intact. See `ai-docs/agent-writing-style.md § Pattern 7`.
- **Propagation Rule** for the Task/Design sync group fires whenever any of `task/SKILL.md` / `design.md` / `design-review.md` is edited; all three must change in the same PR. `context-reset/SKILL.md` is added to the implicated set whenever the handoff-trigger contract shifts. `task/reference.md` rides with `task/SKILL.md` as part of the same skill bundle.
- **Per-skill 5,000-token truncation** at the top of each SKILL.md is enforced by the harness. Step 8 already lives within that cap in `task/SKILL.md`; the every-group rewording must not push the body over.
- **`disable-model-invocation: true`** and `allowed-tools:` block in `task/SKILL.md` frontmatter govern what tools the *top-level orchestrator* may call. The new orchestrator-only contract MUST continue to be satisfied by those tools (notably: `Agent` for spawning `/context-reset`, plus the gh / git / cargo subset). Design-time verification: confirm that orchestrator-only Step 8 needs no tool that the frontmatter denies; if it does, the frontmatter must be expanded.
- **`/context-reset` allowed-tools** is currently `Bash(cargo build)` only. If the every-group contract pushes additional work into the per-group subagent (e.g. git commit, gh issue view, full `cargo clippy/test/fmt/doc` gates), the `/context-reset` frontmatter must be widened — and the widening verified against the per-group contract. Design phase enumerates and confirms.
- **`/context-reset` "Maximum 3 handoffs per task" line.** Currently `/context-reset/SKILL.md` reads "Maximum 3 handoffs per task. If more needed — the task is too large, decompose." Under the every-group contract this cap becomes a hard upper bound on the design's total group count — which is equivalent to the existing AGENTS.md rule that any task with > 9 subtasks (3 groups × 3 subtasks/group) must decompose. Design phase decides whether to keep the line as-is, rephrase it ("Maximum 3 design-defined groups per task"), or remove it (subsumed by design-review's group-size rules).
- **Boundary rule 1 / 2** on `ai-docs/learnings.md` — only APPEND new entries; the #374 entry must be a NEW entry, not a rewrite of an existing one. In-flow capture during `/task` Steps 8–12 is permitted per the Exception.

## Open questions

These are surfaced as `## Open questions` rather than blocking the spec, because each has a defensible default the design agent can adopt while still leaving room for the user to revisit at design-review or via Design Amendment.

1. **Per-group failure-handling retry cap.** Default: inherit the existing per-step retry contract; surface to user after 3 rejected attempts at the same group with the classic three options (retry / amend design / abort). The design agent can adopt this default verbatim or propose a stricter cap if the every-group contract surfaces a new failure mode the current retry logic doesn't cover.
2. **Does `/context-reset` itself need any frontmatter / `allowed-tools` widening?** Today `Bash(cargo build)` only. The per-group subagent likely needs at minimum `git commit`, `git push` (if commits-per-subtask is preserved), and the full `cargo clippy/test/fmt/doc` gate set — none of which are currently in the allow-list. Design phase enumerates the per-group tool needs and proposes the widening.
3. **`/context-reset` "Maximum 3 handoffs per task" line.** Under the every-group contract this becomes the hard cap on design-defined groups (3 groups × 3 subtasks/group = 9 subtasks max). Design phase decides whether to keep, rephrase ("Maximum 3 design-defined groups per task"), or remove the line.
4. **Does the orchestrator need to spawn `self-review` / `review-findings` differently?** Today `self-review` is spawned at Step 10 from the orchestrator; under the redesign Steps 9–11 stay in the orchestrator, so no change is expected. Design phase confirms via grep that no Step-10 spawn site implicitly assumed Step-8 work was inline.
5. **Progress-file delta parsing under the redesign.** The orchestrator's "read the subagent's progress-file delta between group returns" contract is informal today. Design phase decides whether to formalise the delta-parsing contract (e.g. "read `current_step` and the last N `Decisions log` entries") or leave it as a free-form orchestrator read. The canonical schema at `ai-docs/templates/progress-format.md` is the source of truth either way.
6. **Cross-skill grep audit.** Design phase runs `grep -rnE 'N=3\|N == 3\|M >= 5\|M ≥ 5' .claude/agents/ .claude/skills/ AGENTS.md ai-docs/` and enumerates every hit; the implementer decides per-hit whether it's a live trigger (must rewrite) or a historical reference (must label as superseded). AC10 enforces zero binding-rule hits post-merge.
