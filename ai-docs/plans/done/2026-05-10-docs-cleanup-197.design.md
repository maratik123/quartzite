# Design: Docs cleanup post-#197 — `all-features = true` propagation, intra-doc-link audit, bare-backtick conversion, and macro-generated-doc audit

**Issue:** [#199](https://github.com/maratik123/quartzite/issues/199)
**Date:** 2026-05-10
**Spec:** [`2026-05-10-docs-cleanup-197.spec.md`](2026-05-10-docs-cleanup-197.spec.md)
**PR:** [#200](https://github.com/maratik123/quartzite/pull/200) (open on `fix/docs-cleanup-197`; Parts A–D landed in commit `60289c4`)

## Approach

Mostly-mechanical docs/metadata change. **Five** parts that share a single
root cause (intra-doc references render or link as silently as the build
configuration permits) are bundled into one PR per the spec's *Key decisions*
table. Parts A, B, C, D were implemented in commit `60289c4` and pushed; Part
E is a follow-up on the same branch.

### Part A — `all-features = true` propagation

Insert `all-features = true` as the **first** line of every leaf-crate
`[package.metadata.docs.rs]` block, matching the byte-shape already present in
`Cargo.toml` (umbrella) and `quartzite-core/Cargo.toml`:

```toml
[package.metadata.docs.rs]
all-features = true
rustdoc-args = ["--cfg", "docsrs"]
rustc-args = ["--cfg", "docsrs"]
```

Verified by direct file inspection that all 11 leaf crates currently carry the
identical 3-line block (no `features` / `all-features` line). The diff is
therefore `+1 line` per crate, with zero edits to `rustdoc-args` /
`rustc-args` (spec *Out of scope*).

**Why "everywhere," even for crates with no `[features]` table today?**
Decision recorded in spec *Key decisions*: the convention is "everywhere" per
`ai-docs/doc-convention.md` § *Feature-gated documentation*; a no-op today
guarantees no future contributor adds an optional feature without docs.rs
picking it up. The change is one line per crate; the cost of *not* doing it is
a future silent regression.

**Rejected alternative:** apply only to crates with `[features]` today
(`quartzite-runtime`, `quartzite-geometry`). Rejected because it leaves a
booby-trap for future maintainers and contradicts the convention that landed
in #197.

### Part B — crate-prefixed intra-doc-link audit (no source edits)

Spec records that the audit pass was completed during interview and all
candidate intra-doc links target a direct dep of their linking crate.
Re-verified during this design pass: `rg -c '\[`?\w+`?\]\(quartzite_\w+::'
--type rust` reports `src/lib.rs:17`, `quartzite-style-types/src/color_role.rs:1`,
`quartzite-renderer/src/lib.rs:1`, `quartzite-renderer/src/render_harness.rs:1`
(17/1/1/1 line-counts across the 4 known files; `rg -o … | wc -l` returns 24
total occurrences because several lines in `src/lib.rs` carry multiple links).
The direct-dep claim was spot-checked against `quartzite-renderer/Cargo.toml`
and `quartzite-style-types/Cargo.toml` (both list the linked crates as direct
path-deps). **No source files change.** AC6 re-runs the same `rg -c` post-edit
as the verification artefact.

### Part C — bare-backtick → intra-doc-link conversion across `src/**/*.rs`

Audit + conversion pass over every doc comment in the workspace
(`find . -name '*.rs' -path '*/src/*' -not -path './target/*'` reports **99
files**, ~8 055 doc-comment lines, ~25 882 total source lines). Two patterns
to convert:

- **Bare TitleCase identifier** in prose: `` `Object` `` → `` [`Object`] `` (when
  in scope per the spec's *Conversion criteria* table).
- **Bare qualified path with crate prefix** in prose:
  `` `quartzite_runtime::snapshot::capture_object` `` →
  `` [`quartzite_runtime::snapshot::capture_object`] `` (when the leading crate
  is a direct dep).

The full criteria table is in spec § *Part C — Conversion criteria* and
governs every decision; this design does not duplicate it.

**Crate batching.** Audit + convert one crate at a time, running the doc gate
after each batch (12 crates total: umbrella `src/` + 11 leaves). The 12th
batch is also the AC10 final run. Per-batch sequencing isolates any bad-link
regression to one crate's diff and keeps the doc-gate signal actionable
("which crate's links broke?"). The spec's single-commit constraint is
preserved: batches are working-tree checkpoints, not git commits.

**Per-batch loop.**

1. Generate the candidate list for the crate:
   `rg -n '`[A-Z][A-Za-z0-9_]+`' <crate>/src/ --type rust` for TitleCase, plus
   `rg -n '`quartzite_[a-z_]+::[A-Za-z0-9_:]+`' <crate>/src/ --type rust` for
   qualified paths.
2. For each candidate, apply the spec's criteria table — convert in place or
   leave bare with a one-line justification when the choice is non-obvious.
3. Run `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps -p
   <crate> --all-features` (per-crate doc gate).
4. After all 12 batches, run the workspace-wide
   `cargo doc --no-deps --workspace --all-features` once (this is AC10).

**Rejected alternative — single all-files-in-one-pass.** Rejected because a
single doc-build failure across ~37–150 conversions across 12 crates would
require bisecting a large working tree to find the bad link. Per-crate
batching reduces the bisect surface to one crate at a time at zero commit
cost.

**Rejected alternative — automated converter script.** Rejected. The criteria
table requires human judgement (e.g., "English noun in TitleCase like
`Object` as a concept" vs. "type `Object` as identifier" — same token, opposite
action); a regex-based converter would either over-link (introducing broken
links the doc gate would catch but the contributor would have to undo) or
under-link (defeating the audit). Manual per-crate is faster than writing,
testing, and reviewing a converter for a one-shot job.

**Inventory bound.** Spec inventory cites ~37 candidate sites in `lib.rs`
files alone, plausibly 50–150 across `src/**/*.rs`. With 99 source files and
~8 055 doc-comment lines, the candidate density is ~0.6–1.9% of doc lines —
consistent with the spec estimate and tractable in a single PR.

### Part D — combined doc-convention paragraph (Parts B + C + E)

Append a single section (with **three** short before/after pairs) to the
existing **Linking and code references** section of `ai-docs/doc-convention.md`
(currently at lines 359–374), immediately after the existing fourth bullet
about cross-crate links. The section codifies three related rules per spec
§ *Part D*:

1. **Cross-crate links must target direct dependencies** (verbatim from the
   prior design round — re-route through a re-exporting direct dep, or demote
   to bare backticks).
2. **Backticked TitleCase identifiers in prose should be intra-doc links when
   in scope** (`` `Foo` `` → `` [`Foo`] `` when `Foo` is in own crate or a
   direct dep; bare for placeholders, feature names, English nouns).
3. **Bare qualified paths follow the same direct-dep rule** (`` `pkg::path::T` ``
   → `` [`pkg::path::T`] `` when `pkg` is a direct dep; bare otherwise — the
   `quartzite-core` mentioning `quartzite_runtime::*` case is the worked
   example, since the link is *structurally impossible* and a "fix" would
   introduce a broken link).

One worked before/after pair per rule (3 pairs total), each shorter than a
full Rust example because the demonstration is a single `///` line.

**Voice / structure constraints** (read from the existing section to match):

- Bulleted list at the top (existing four bullets); the three new rules join
  as bullets 5–7 to keep parallel structure.
- The before/after pairs follow the bullets as a small fenced block (one
  fenced block per pair, three blocks total). Surrounding sections
  (*Conforming example*, *Non-conforming example*) use full-fn fenced Rust
  blocks; intra-doc-link pairs are shorter and live inline.
- Imperative phrasing matching the existing fourth bullet ("Cross-crate
  links use the workspace crate name…").

**Part E coverage.** The convention text codified above is *context-agnostic*:
a macro-emitted `#[doc = "..."]` string is just a doc string with extra steps,
so rule 2 (backticked TitleCase → intra-doc link when in scope) and rule 3
(bare qualified paths → intra-doc link when leading crate is a direct dep)
both apply transparently to macro codegen. The Part E audit (below) executes
the same rules against the codegen output. **No additional convention text
needed** — if the audit surfaces a wrinkle that warrants explicit "applies to
macro-emitted docs too" wording, that's a one-sentence amendment to the Part
D edit, not a new deliverable.

### Part E — macro-generated doc-string audit

**Why this is needed.** PR #200 (Parts A–D) landed a workspace-wide audit of
hand-written doc comments. The proc macros in `quartzite-macros` emit
`#[doc = "..."]` attributes that become rendered docs in any user's
`#[derive(Object)]` / `#[object_impl]` / `#[derive(MetaEnum)]` /
`#[derive(Extend)]` types. Bare-backticked identifiers in those generated
docs are the same class of issue as Part C — but invisible to a `grep` over
`src/**/*.rs` doc comments because they're string literals inside `quote!`
blocks. The existing AC10 doc gate
(`cargo doc --no-deps --workspace --all-features`) renders the docs for the
*macro source*, not for derived types — the macros are only expanded against
test types under `#[cfg(test)]`, which `--no-deps` rustdoc does not include.
So a missing intra-doc link in a macro-emitted doc string is invisible to
AC10 — only end users feel it when they `cargo doc` their own derived types.

**Critical resolution-context constraint.** Macro-emitted intra-doc links
resolve in the **downstream user crate** (the crate that writes
`#[derive(Object)]`), not in `quartzite-macros` itself. Conversions
must use `quartzite::*`-prefixed paths reachable from any user crate — e.g.,
`` `Auto` `` → `` [`quartzite::core::ConnectionType::Auto`] ``. Existing
emitted links like `` [`quartzite::core::ReceiverGuard`] `` /
`` [`quartzite::core::QueuedDispatcher`] `` already follow this convention
(see `quartzite-macros/src/object/codegen.rs:456,512,513`).

**Files in scope.**

| File | Static `#[doc = "literal"]` sites | Dynamic `#[doc = #ident]` sources | Notes |
|---|---:|---:|---|
| `quartzite-macros/src/object/codegen.rs` | ~14 | 4 (`bullet`, `example_doc` ×2, `parameters_doc`) | Static literals contain bare `` `Auto` `` (L449, `connect_*_auto` doc), bare `` `Queued` `` (L504, `connect_*_queued` doc), and existing intra-doc links to `[`quartzite::core::ReceiverGuard`]` / `[`quartzite::core::QueuedDispatcher`]`. Bare `` `f` `` / `` `receiver` `` are parameter names — leave bare per Part C criteria. |
| `quartzite-macros/src/extend/codegen.rs` | 0 prose (1 `#[doc(hidden)]` out of scope) | 3 (`trait_doc` L114, `acc_doc` L122, `acc_mut_doc` L130) | Dynamic strings already use `` [`{self_name}`] `` form for the type name. Audit format-string sources line by line for any other bare identifier. |
| Other codegen files (`object_part`, `meta_enum`, `object_impl`, `parse`, `mod`) | 0 | 0 | Confirmed by grep — no `#[doc = ...]` emission. AC13 re-runs the grep to defend against silent additions. |

**Conversion examples.**

- `` `Auto` `` (object/codegen.rs:449) → `` [`quartzite::core::ConnectionType::Auto`] ``
- `` `Queued` `` (object/codegen.rs:504) → `` [`quartzite::core::ConnectionType::Queued`] ``
- `` `f` ``, `` `receiver` ``, `` `arg{i}` `` — parameter names, **leave bare** (Part C criteria, "method or field name in TitleCase prose" — extended to lowercase parameter names by the same logic; they have no doc page to link to).

**Verification — AC15 design choice.**

The spec leaves the verification approach to this design pass. **Chosen:
option (b) — source-side `cargo expand`** on the existing `Counter` test
type in `quartzite-macros/tests/object.rs`. Rationale:

| Criterion | Option (a) — build-side smoke type | Option (b) — `cargo expand` (chosen) |
|---|---|---|
| Real validation of resolution from downstream crate | Yes — rustdoc + deny lint | Manual — visual confirmation that emitted strings carry the new link forms |
| New test surface | Adds a doc-only feature + smoke type to a workspace crate (`quartzite-macros` would need a `dev-dependencies` cycle on `quartzite`, which it already has — but the smoke type would still inflate the compiled `--all-features` doc surface and the `cargo test` surface) | Zero — `Counter` already exercises `#[signal]` → triggers `connect_*_auto`, `connect_*_queued`, `emit_*` wrappers; `#[derive(Extend)]` triggers `trait_doc`/`acc_doc`/`acc_mut_doc` |
| Tooling availability | `cargo doc` (always available) | `cargo-expand 1.0.121` (verified locally available; Cargo subcommand, not a workspace dep) |
| Bad-link safety net | Lint catches missing/wrong link automatically | Manual visual review; bad-link risk shifts to the audit step's care |
| Aligns with spec § *Out of scope* | Inflates compiled / test surface | No surface impact |

Option (a) was rejected on three grounds: (1) it forces a `quartzite-macros`
→ `quartzite` non-dev dep cycle (the umbrella already dev-deps `macros`), or
a separate scratch crate elsewhere in the workspace; (2) the smoke type would
land in compiled output, contradicting the spec's "no test additions" stance
for Parts A–D and inflating `cargo doc --all-features` rendering for
end-users browsing the workspace; (3) the substantive risk Part E mitigates
is *5 newly converted links* — a manual visual pass over an expanded
`Counter` is faster than designing, gating, and reviewing a doc-only smoke
type. The conservative-bias rule (Part E mitigation, see Risks) is the
secondary safeguard: when in doubt about a bare identifier, leave it bare.

**Verification procedure (AC15).**

1. Run `cargo expand -p quartzite-macros --test object` (or equivalent for the
   test that includes `#[signal]` on `Counter`) — captures the post-conversion
   token stream.
2. `grep -E '\[`(quartzite::core::ConnectionType::(Auto|Queued)|...)`\]'` the
   output to confirm each newly converted identifier appears in the expected
   intra-doc-link form (and **not** as a bare `` `Auto` ``).
3. Spot-check a representative `Counter::connect_count_changed_auto` /
   `_queued` doc block in the expansion to confirm the emitted `#[doc = ...]`
   strings carry the new link forms with no `quote!`-introduced escaping
   damage.
4. The existing `cargo doc --no-deps --workspace --all-features` (AC10) still
   runs as the workspace-wide doc gate — it does not catch the new link forms
   on derived types but does catch any `quote!`-level syntax breakage in the
   macro source itself.

## Risks

- **Cargo.lock drift:** metadata-only edits should not touch the lockfile;
  AC8 explicitly checks. **Mitigation:** T8 verified (DONE); T14 re-checks
  `git diff Cargo.lock` is empty before the follow-up commit. Part E touches
  only `*.rs` source files in `quartzite-macros` — no dep changes expected.
- **Docs.rs build under `--all-features` regresses (Part A):** PR #197
  proved the umbrella + core compile docs under `--all-features`; T8 confirmed
  for all 11 leaf crates pre-commit. **Mitigation:** AC10 gates T14 too.
- **Bad intra-doc link from Part C breaks the doc gate:** ~50–150 conversions
  across 99 files would force a manual bisect of a large working tree.
  **Mitigation (executed in T4):** per-crate batching isolated any failure to
  one crate's diff.
- **Audit miss — leaving a Part C candidate bare that should be linked:** doc
  gate cannot catch this. **Mitigation:** AC11 spot-check, AC12 negative
  spot-check (DONE in T7).
- **NEW — Bad macro-emitted intra-doc link breaks DOWNSTREAM user crate doc
  builds without our gate catching it pre-merge.** This is the primary Part
  E risk. AC10 (`cargo doc --no-deps --workspace --all-features`) renders
  *macro source* docs, not docs of derived types — so a wrong path like
  `[`quartzite::core::ConnectionType:Auto`]` (missing `:`) compiles cleanly
  in the macro source but breaks the doc build for every downstream user the
  moment they `cargo doc` their own `#[derive(Object)]` type.
  **Mitigation (primary):** T13 runs `cargo expand` on the existing
  `Counter` test, visually confirms each new link form is well-formed and
  uses a `quartzite::*` path that resolves from any user crate (the umbrella
  re-exports `core` unconditionally — verified at PR #197 time and unchanged
  since). **Mitigation (secondary):** conservative bias on what to convert —
  per the criteria table in spec § *Part C — Conversion criteria*, when in
  doubt leave bare. Bare backticks are correct rendering; a *missing* link is
  recoverable in a follow-up, a *broken* link breaks downstream builds.
  **Mitigation (tertiary):** restrict converted identifiers to those known
  to be reachable through the `quartzite::*` umbrella (`core::*` items).
  Identifiers reachable only through deep paths (e.g., `quartzite_runtime::*`
  internals) stay bare even when conceptually in scope — same forced-bare
  reasoning as Part C's qualified-path criteria.
- **NEW — `cargo-expand` not installed in CI / on a reviewer's machine.**
  AC15 verification depends on `cargo-expand` (subcommand, not a workspace
  dep). **Mitigation:** T13 captures the relevant expanded snippet in the
  commit message so reviewers can verify by reading the commit, not by
  re-running `cargo expand` locally. CI does not need `cargo-expand` —
  `cargo build --workspace` and `cargo test -p quartzite-macros` (which use
  the standard compiler-driven macro expansion) catch any `quote!`-level
  syntax breakage automatically. AC15 is a one-shot author-side gate, not a
  recurring CI check.
- **NEW — `quote!`-induced escaping damage on the converted link strings.**
  The `[` / `]` / `` ` `` characters inside an intra-doc-link form are not
  syntactically special to `quote!` (they're inside a string literal), but a
  hand-crafted format string with `quote!`-emitted bracketed content can be
  surprising. **Mitigation:** static literals (T10 — most of the surface)
  bypass `quote!` interpolation entirely — the literal string is directly
  passed to `#[doc = "…"]`. Dynamic strings (T11) build the string in Rust
  with `format!` then pass the *whole resolved string* through `quote!` as a
  single `&str` interpolation — no per-character `quote!` interpretation
  occurs. T13's `cargo expand` confirms zero escaping damage.
- **Doc-convention paragraph collides with existing voice (Part D):** DONE
  in T3.
- **AGENTS.md Workflow Axiom 1 violation:** task is ALREADY on
  `fix/docs-cleanup-197` (verified at design time). **Mitigation:** Part E
  edits land on the same branch — no `git checkout -b` needed.
- **PR body sync (AGENTS.md Workflow Axiom 2):** T14 push triggers Axiom 2.
  T15 is the explicit `gh pr view 200 --json title,body` read + conditional
  edit. **Mitigation:** T15 is in the decomposition table as a hard
