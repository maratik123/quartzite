# Lookup Performance & API Improvements

**Source:** user description
**Date:** 2026-05-02

## Scope

Three independent improvements across `quartzite-core`, `quartzite-runtime`, and `quartzite-macros`:

1. **IndexMap for `Signal<Args>` slot storage** — replace three `Vec`s with
   `IndexMap<ConnectionId, …>` for O(1) disconnect while preserving insertion-order emission.
2. **Name index in `ObjectTree`** — add `HashMap<String, Vec<ObjectId>>` alongside the existing
   `forward` map; make `ObjectBase::name` `Option<String>`; add `rename` / `clear_name` to
   `ObjectTree`.
3. **`match`-based lookup for static meta accessors** — replace `iter().find()` in `MetaObject`
   and `EnumMeta` with generated fn-pointer dispatch; `#[object_impl]` and `#[meta_enum]` macros
   generate the match functions.

## Out of scope

- Subtree-scoped `find_by_name` (flat search sufficient for now)
- Async/reactive name-change notifications (needs event system)
- Python interop

## Deferred

- `ObjectTree::find_by_name` subtree scoping | future; flat search sufficient for v1

## Key decisions

| Question | Decision |
|---|---|
| Signal slot storage | `IndexMap<ConnectionId, SlotEntry<Args>>` etc.; `ConnectionId` is the map key; `id` field removed from `SlotEntry`; `id()` removed from `DynQueuedSlot` / `DynAutoSlot` |
| SingleShot removal in `emit` | Two-pass: call all slots, then `retain(\|_, e\| e.conn_type != SingleShot)` |
| IndexMap `no_std` | `indexmap = { version = "2", default-features = false }` in `quartzite-core/Cargo.toml` |
| `ObjectBase::name` type | `Option<String>`; `None` = unnamed; `Some("")` = explicitly named `""` |
| `ObjectBase::new()` default name | `name: None` |
| Name mutation API | `ObjectTree::rename(id, impl Into<String>)` → `Some(name)`; `ObjectTree::clear_name(id)` → `None` |
| `ObjectBase::name` visibility | Private field; `pub fn name(&self) -> Option<&str>` getter |
| Duplicate names | `HashMap<String, Vec<ObjectId>>` index; all registered; insertion order within vec |
| `find_by_name` return type | `&[ObjectId]` — breaking change; existing callers (tests) updated |
| Unnamed objects in index | Not indexed (`None` → no entry in `by_name`) |
| `MetaObject` lookup | Add fn pointer fields `lookup_property`, `lookup_signal`, `lookup_method`, `lookup_enum`; generated by `#[object_impl]` |
| `EnumMeta` lookup | Add fn pointer fields `lookup_entry_by_name`, `lookup_entry_by_value`; generated by `#[meta_enum]` |

## Technical constraints

- `quartzite-core` must remain `no_std`-compatible; `indexmap` with `default-features = false`
  satisfies this (uses `hashbrown` internally)
- `MetaObject` and `EnumMeta` are `Copy + 'static`; fn pointer fields (`fn(…) -> …`) are
  `Copy + 'static` ✓
- `ObjectTree::rename` and `clear_name` must keep `by_name`, object data, and the `forward` index
  in sync within a single lock scope
- `MetaObject::new()` is used directly in hand-written tests; its construction path must
  accommodate the new fn pointer fields (design to decide: extend `new()` vs struct literal)

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | `Signal::disconnect(id)` removes the slot without scanning the full slot list (O(1) via `IndexMap::shift_remove`) |
| AC2 | Emission order after disconnect preserves original insertion order for the remaining slots |
| AC3 | A `SingleShot` slot is called exactly once per `emit` and is absent from the signal on the next `emit` |
| AC4 | `ObjectBase::new()` produces `name() == None` |
| AC5 | `ObjectBase::named("foo")` produces `name() == Some("foo")` |
| AC6 | `ObjectTree::rename(id, "bar")` sets `name()` to `Some("bar")` and makes the object findable via `find_by_name("bar")` |
| AC7 | `ObjectTree::clear_name(id)` sets `name()` to `None` and removes the object from the `by_name` index |
| AC8 | `ObjectTree::find_by_name("foo")` returns a slice containing the `ObjectId`s of all objects named `"foo"`, in insertion order |
| AC9 | `find_by_name("")` returns only objects explicitly renamed to `""`, never unnamed (`None`) objects |
| AC10 | `MetaObject::property("x")` dispatches via generated fn pointer (no linear scan) |
| AC11 | `MetaObject::signal("x")`, `method("x")`, `enum_("x")` dispatch via generated fn pointers |
| AC12 | `EnumMeta::entry_by_name("X")` dispatches via generated fn pointer |
| AC13 | `EnumMeta::entry_by_value(n)` dispatches via generated fn pointer |

## Open questions

- Should `MetaObject::new()` be extended with fn pointer params or replaced by struct literal
  construction in the macro? Decide in design phase.
- Should `ObjectTree::rename` be a no-op when called with the object's current name?
  Implementation must be correct either way; no special case required.
