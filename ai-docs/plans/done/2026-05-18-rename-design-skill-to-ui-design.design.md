# Design: Rename `design` skill to `ui-design`

**Issue:** #470
**Date:** 2026-05-18

## Approach

Mechanical, single-pass rename of one slash-discoverable skill plus a project-wide text sweep over every active and historical Markdown surface that references the old slug or path, with three explicit carve-outs (`ai-docs/learnings.md`, this rename's own `.spec.md`, this rename's own `.design.md`) that AC4 and AC4b both filter out.

Concretely:

1. Move the directory `.claude/skills/design/` to `.claude/skills/ui-design/` via `git mv`, preserving history on the single file inside (`SKILL.md`).
2. Edit the renamed file's YAML frontmatter `name: design` → `name: ui-design`. The Claude Code skill loader keys off **both** the directory slug and the frontmatter `name:` field; in-tree convention is that the two match (verified by inspection of every other `.claude/skills/<slug>/SKILL.md`). The body itself contains no self-reference by slug or by `name`, so no body edit is required. The description's contrast clause ("Distinct from `design-system/SKILL.md` (name: quartzite-design), which is not slash-discoverable") stays accurate after rename and is preserved verbatim.
3. Update `AGENTS.md` § Agent Docs table row: path-form `.claude/skills/design/SKILL.md` → `.claude/skills/ui-design/SKILL.md`, prose label `/design` → `/ui-design`. No other AGENTS.md edits — every remaining `design` occurrence in AGENTS.md refers to the `design` agent (`.claude/agents/design.md`), the Task/Design sync group, the "Steps 6 (design)" prose, or the `design-system/` folder — all OUT OF SCOPE per spec.
4. Update `ai-docs/deferred/_inbox.md`: rewrite the one row whose cell currently contains `.claude/skills/design/SKILL.md`. The AGENTS.md "_inbox.md written ONLY by `/task` Step 12 and `/triage`" AXIOM is **not** violated — this is a path-string fix inside an existing cell (no row added/removed/moved/re-classified), per spec § Key decisions row 7.
5. Update active-surface narrative refs that name the old path: `ai-docs/plans/INDEX.md` (historical row for `wire-design-system-context`), `ai-docs/context.md` (the `wire-design-system-context` § Plans list bullet), `ROADMAP.md` (the `wire-design-system-context` row).
6. Update historical `done/` artefacts per user confirmation (Round 1 Q1): `ai-docs/plans/done/2026-05-18-wire-design-system-context.spec.md` and `…design.md`. Each file contains two distinct kinds of occurrence — **path-form** `.claude/skills/design/` and **backtick-quoted name-literal** `` `name: design` `` — and both must be rewritten in the same subtask. Pattern-based substitution only; the swept files are stable historical artefacts and per-line enumeration in this design document would drift between design-time and implementation-time line numbers.
7. Verify completeness with the two acceptance-criterion grep commands (AC4 and AC4b — see § Test Design). Both must return empty.

Rejected alternatives:

- **Alias / stub the old slug.** Keep `.claude/skills/design/SKILL.md` with a single-line "moved to `ui-design/`" body. **Rejected.** AGENTS.md § API Stability AXIOM (pre-publish: clean breaks, no compat shims) applies project-wide; the same axiom rejects `pub use OldName as NewName;` in Rust and the same principle holds for skill slugs. The skill has no downstream clients beyond `/task`-spawned agents, all of which load `design-system/SKILL.md` directly via Read (not via the slash skill); no caller breakage.
- **Sweep only active surfaces; leave `done/` artefacts as historical record.** **Rejected by user** in Round 1 Q1 of the interview ("Yes — sweep all"). Spec § Key decisions row 3 makes the sweep authoritative. The deliberate carve-outs (`learnings.md`, this rename's own `.spec.md` and `.design.md`) are the only files the AC4 / AC4b greps exclude.
- **Sweep this rename's own `.spec.md` and `.design.md` along with the historical `done/` artefacts.** **Rejected** by spec § Out of scope (amended). The rename's own narrative files describe the rename itself — substituting their path-form occurrences turns `.claude/skills/design/ → .claude/skills/ui-design/` (the literal rename statement) into the nonsense `.claude/skills/ui-design/ → .claude/skills/ui-design/`, and turns AC1's verification command (which must quote the OLD path to verify its absence) into a self-contradictory check. Same principle as the `learnings.md` carve-out: the file documents a historical state and must continue to.
- **Enumerate per-line offsets for the two `done/` files in this design's subtask 5.** **Rejected** — line numbers in narrative Markdown drift between design-write time and implementation time (other edits, even unrelated, shift offsets). v2 of this design listed specific lines and the design-review found two inventory errors. Instead, subtask 5 instructs the implementer in pattern terms and gates completeness with AC4 + AC4b greps, which are line-number-independent and exhaustive.
- **Rename the `design` agent at `.claude/agents/design.md` as well, to a symmetric `ui-design` agent.** **Rejected by spec** § Out of scope. The issue body contrasts the skill (renamed) against the agent (unchanged); the agent is the generic design-document writer (this very agent producing this document), independent of the visual design-system pointer.
- **One-shot single subtask `s/design/ui-design/g`-style global sed.** **Rejected.** The substitution is too coarse — many strings in the codebase contain `design` (the unrelated agent, the `design-system/` folder, English prose like "the design under review", the existing `name: quartzite-design` frontmatter value). The decomposition below confines each edit to the specific file + cell + anchored substring form, keeping the diff auditable and the substring-collision risk controlled.

## Handoff plan

`M = 5` (two groups, 3 + 2):

- **Group A:** subtasks 1–3 — structural rename (directory move + frontmatter edit) plus the two highest-visibility text-reference fixes (`AGENTS.md` Agent Docs row, `ai-docs/deferred/_inbox.md` cell). At entry into Group A, spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry) before any edit. After this group lands, `.claude/skills/ui-design/SKILL.md` is loadable as a slash skill and the AGENTS.md Agent Docs index is consistent with the new path; only the historical narrative surfaces still reference the old path.
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group B with fresh context.
- **Group B:** subtasks 4–5 — terminal group (2 subtasks; within the 1..=3 range). Sweep active and historical narrative surfaces, then run the AC4 + AC4b verification greps. At entry into Group B, the `/context-reset` handoff from the Group A boundary fires.

## Risks

- **`` `name: design` `` substring collision with `` `name: quartzite-design` ``.** `ai-docs/plans/done/2026-05-18-wire-design-system-context.design.md` contains both `` `name: quartzite-design` `` and `` `name: design` `` in the same risks-section sentence. **Mitigation:** subtask 5's substitution targets the backtick-quoted literal `` `name: design` `` (with both leading and trailing backticks included as anchors in the Edit `old_string`), never the bare `name: design` substring. Use the Edit tool with the full backtick-quoted old string `` `name: design` `` (or, if it is non-unique within a file, include enough surrounding sentence context to make the match unique). Never `replace_all` on the bare token `design` and never use `s/design/ui-design/g`. The AC4b grep is the safety belt: it specifically targets `` `name: design` `` and zero-hit asserts that the substitution actually landed without spilling into the `quartzite-design` literal.
- **AC4 grep regex `'\.claude/skills/design[/ ]'` is not a literal-substring hazard.** The acceptance-criterion verification command uses a regex that encodes the OLD path pattern in order to test that the path has disappeared. The regex form `\.claude/skills/design[/ ]` is itself text that contains the escaped-dot prefix `\.` and a character class `[/ ]`, so it does **not** textually contain the literal substring `.claude/skills/design/` or `.claude/skills/design ` (i.e., the strings that AC4 grep matches via its regex). **Conclusion:** any prose form of the AC4 regex inside `*.md` files survives the AC4 grep against itself — the regex matches paths, not regex syntax. The two forms that must be distinguished:
  - **Regex form** (e.g., the single-quoted `'\.claude/skills/design[/ ]'` appearing inside a verification command block) — never matches itself; safe to leave verbatim.
  - **Path form** (e.g., a literal `.claude/skills/design/SKILL.md` written as a path or in backticks) — matches the AC4 regex and must be rewritten (or be inside an AC4 carve-out).
  The two rename-artefact carve-outs (this `.spec.md` and `.design.md`) are filtered out by AC4 unconditionally; the historical-sweep targets (`INDEX.md`, `context.md`, `ROADMAP.md`, the two `done/` files) contain only path-form occurrences and are rewritten in subtasks 4 and 5.
- **AC4b grep enumerates the five swept artefacts (post-amendment).** The AC4b grep does NOT scan the project tree — it explicitly enumerates `ai-docs/plans/INDEX.md`, `ai-docs/context.md`, `ROADMAP.md`, `ai-docs/plans/done/2026-05-18-wire-design-system-context.spec.md`, and `ai-docs/plans/done/2026-05-18-wire-design-system-context.design.md`. This is intentional: the backtick-quoted literal `` `name: design` `` appears in many legitimate places (the rename's own narrative, `learnings.md` historical entries, possibly other deferred / plan files describing the old skill); only these five files were authorised by the user (Round 1 Q1 "sweep all") for sweep. **Original scope was the two `done/` files only — amended after Step 8 Group B to cover the three active-surface files as well** (the spec's Key decisions row 3 explicitly covers "the `name: design` value where it appears in body prose" across active and historical surfaces; the active surface omission was caught in Step 9.5 and triggered a Design Amendment). **Implication:** subtask 4 and subtask 5 each handle the name-literal substitution for their respective files; AC4b's grep is the single final gate covering both.
- **Slash-skill loader behaviour during rename.** Claude Code's skill loader scans `.claude/skills/<slug>/SKILL.md` at session start (or skill-invocation time). A mid-session rename followed by an in-session `/ui-design` invocation in the SAME session may hit a stale cache. **Mitigation:** AC5 is a smoke check at review time — the user/reviewer invokes `/ui-design` in a fresh session after the PR merges. The implementation does NOT need to validate runtime loader behaviour; the file's correctness is verified by `grep -E '^name: ui-design$'` + body presence.
- **History preservation via `git mv` vs. `rm + add`.** `git mv` keeps blame on the single file inside the directory. If the implementation accidentally does `rm -rf .claude/skills/design && mkdir .claude/skills/ui-design && cp …`, blame breaks. **Mitigation:** subtask 1 prescribes `git mv` explicitly. Verification: `git log --follow .claude/skills/ui-design/SKILL.md` after commit should show the file's full history pre-rename.
- **`_inbox.md` AXIOM scope mismatch.** The "_inbox.md written ONLY by /task Step 12 and /triage" AXIOM is structurally about row-level edits (add / remove / re-classify). Subtask 3's intra-cell path fix is a narrow textual substitution, NOT a row-level edit. The spec § Key decisions row 7 confirms this reading. **Mitigation:** the implementation must NOT alter row count, column count, row order, or `Disposition` field. Pre/post diff should show a single-line change inside the affected cell only.
- **Subtask ordering — Group A subtask 2/3 race.** AGENTS.md and `_inbox.md` edits are independent of each other and both depend on subtask 1 (the directory rename) for visual consistency at review time. **Mitigation:** no race — subtasks 2 and 3 can run in either order; the Decomposition table marks both as depending only on 1. Implementation may serialise them in any order it chooses.
- **Pattern-based instructions vs. line-number enumeration in subtask 5.** v2 of this design enumerated specific line numbers (e.g., "lines 27, 41, 44, 65, 68, 95") for `done/*.design.md` substitutions and the design-review found two inventory errors; the user also flagged that line numbers drift between design-write time and implementation time. **Mitigation:** v3 uses pattern-based instructions (substitute every path-form / every backtick-quoted name-literal) and treats AC4 + AC4b as the authoritative completeness gate. The implementer is NOT to consult this document for line offsets — both target files are scanned exhaustively for the two anchored patterns.

## Test Design

This is a docs-and-infrastructure rename — zero new Rust tests. Verification is mechanical, gated on the two acceptance-criterion grep commands quoted verbatim from the spec:

- **AC1 verification (subtask 1):** `test -d .claude/skills/ui-design && test ! -e .claude/skills/design` — both conditions must pass.
- **AC2 verification (subtask 1):** `grep -E '^name: ui-design$' .claude/skills/ui-design/SKILL.md` — must return exactly one line.
- **AC3 verification (subtask 2):** `grep -n '/ui-design' AGENTS.md` must return the Agent Docs row; `grep -cn '\.claude/skills/design/SKILL\.md' AGENTS.md` must return zero.
- **AC4 verification (subtask 5, final — path-form sweep):**

  ```
  grep -rn '\.claude/skills/design[/ ]' --include='*.md' . | grep -v -e '^ai-docs/learnings\.md:' -e '^ai-docs/plans/2026-05-18-rename-design-skill-to-ui-design\.spec\.md:' -e '^ai-docs/plans/2026-05-18-rename-design-skill-to-ui-design\.design\.md:'
  ```

  Must return empty. The three carve-outs (`learnings.md`, this rename's own spec, this rename's own design) are intentional per spec § Out of scope. Anchors omit the `./` prefix because GNU `grep -rn` with a bare `.` search-root emits filenames without one (round-3 design-review finding).

- **AC4b verification (final — backtick-quoted name-literal sweep, all five swept files):**

  ```
  grep -nE '`name: design`' ai-docs/plans/INDEX.md ai-docs/context.md ROADMAP.md ai-docs/plans/done/2026-05-18-wire-design-system-context.spec.md ai-docs/plans/done/2026-05-18-wire-design-system-context.design.md
  ```

  Must return empty. Run after BOTH subtask 4 and subtask 5 land (subtask 4 owns the three active-surface files; subtask 5 owns the two `done/` files). Both AC4 and AC4b are independent gates — passing AC4 alone is not sufficient (the path form would be clean but the backtick-quoted name-literal form could still leak); passing AC4b alone is not sufficient (the name-literal would be clean but path-form occurrences could still leak). Both gates must clear before Step 9 verify.

- **AC5 verification (subtask 1):** body is pointer-only — `grep -E 'VISUAL FOUNDATIONS|Button\.blend\(' .claude/skills/ui-design/SKILL.md` must return zero (no design-system visual content inlined); `wc -l .claude/skills/ui-design/SKILL.md` should report the original frontmatter+body line count (preserved by `git mv`).
- **AC6 verification:** the retired `…rename-design-skill-to-ui-design.spec.md.state.md` is removed by `/interview` terminal cleanup, not by this design's implementation. Out of scope here; flagged for `/task` Step 12 housekeeping.
- **`git mv` history preservation:** `git log --follow --oneline .claude/skills/ui-design/SKILL.md` after the rename commit lands should show the file's pre-rename history; if it shows only the rename commit itself, blame is broken — the implementation used `rm + add` instead of `git mv` and must be fixed.

No `#[cfg(test)]` module added — this is the docs-only / instruction-file-only exception per AGENTS.md § Workflow (self-review optional for docs-only commits, still required per AXIOM since the commit touches a user-facing artefact — the SKILL.md frontmatter).
