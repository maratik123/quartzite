# Design: Extract oversized SKILL.md references

**Issue:** #498
**Date:** 2026-05-20

## Approach

Follow the existing `task/SKILL.md` + `task/reference.md` precedent. For each oversized skill, classify every section into one of the four spec § Scope categories — (1) static reference, (2) round-template scaffolding, (3) workflow narrative, (4) already extracted — and move ONLY category-(1) content to a sibling `reference.md` reached via anchored `§` links. Workflow-time content (Step 0 snapshot recipes, Step 2 log-fetch / classification tables, pause-trigger lists) is category-(3) and stays inline; the orchestrator consults it every invocation, so extraction would force the same extra-file-load this design rejects for the Spec Amendment recipe relocation.

After applying the stricter classification, only `ai-audit/SKILL.md` plausibly hits ≤ 200 lines (its Checklist A–N detail bodies + Sub-checks 9/10 are unambiguously category-(1) reference material — ~185 lines moved). The other three oversized skills (`master-ci-failed`, `pr-ci-failed`, `pr-commented`) retain enough load-bearing workflow narrative + round-template scaffolding that they remain > 200 lines after extraction. AC1 accepts either ≤ 200 lines OR a documented exemption; each over-target file gets its exemption comment written in the **same** subtask that performs the extraction (not deferred to a separate subtask 5).

**Why this approach (vs. alternatives):**

- **Strict category-(3) preservation** — workflow-time content stays inline. Step 0 GraphQL/REST snapshots in `pr-commented`, Step 2 log-fetch + classification + reproducer tables in `pr-ci-failed` / `master-ci-failed`, and Step 2 classification table + pause triggers in `pr-commented` are all consulted on **every** invocation of the parent step; extracting them would force a `reference.md` Read on every round, contradicting the design's own rejection rationale for Spec Amendment recipe centralisation. Only truly-static reference content (recipes consulted only when a specific detection trigger fires, edge-case tables consulted only when an edge case appears, re-invocation semantics consulted only at round boundaries) moves.
- **Per-section category annotation in every subtask** — each extraction subtask spells out which sections are category (1)/(2)/(3)/(4) so the executor and reviewer can verify the move-vs-keep decision against the spec's classification criteria without re-deriving it.
- **Single canonical sibling file name (`reference.md`) per oversized skill** — matches `task/reference.md`. A thematic name (e.g. `checklist.md` for `ai-audit`) was considered but rejected: `reference.md` keeps the cross-skill mental model consistent. One thematic exception — Spec Amendment recipe — is intentionally NOT a separate cross-skill file; the recipe lives three times (once in each of `master-ci-failed/reference.md`, `pr-ci-failed/reference.md`, `pr-commented/reference.md`) with sync-group siblings continuing to cross-link. A shared `ai-docs/templates/spec-amendment-recipe.md` was rejected: the Propagation Rule already tracks the three sites as a sync group; centralising would force every callee to load an extra file every invocation (the exact failure mode the strict category-(3) rule prevents).
- **Per-skill commit granularity within the single PR** — one commit per extracted skill (plus one final-sweep commit). AC7 mandates one PR; commit granularity inside is the design agent's choice (spec § Key decisions row 1). Per-skill commits make the diff bisect-friendly.
- **Exemption comments written in-subtask, not in a follow-up subtask** — for the three skills that remain > 200 lines after extraction (`master-ci-failed`, `pr-ci-failed`, `pr-commented`), the exemption comment is added in the **same** subtask that performs the extraction. This collapses the original subtask 5 to just the three no-extraction cases (`bugfix`, `interview`, `task`) and keeps the per-skill diff coherent (the reviewer sees both the extraction and the exemption in one commit).
- **`bugfix` + `interview` exemption (no extraction)** — both files have no clean category-(1) split. `bugfix/SKILL.md` Step 1 trace template is category (2) (orchestrator writes into it); Steps 2–7 are category (3) (workflow narrative). `interview/SKILL.md` State file YAML template is category (2); Steps 1–4 + Round/question caps are category (3). Spec § Open questions explicitly delegates this decision; the load-bearing exemption is documented inline per AC1.
- **`task/SKILL.md` exemption (already extracted; residual is category-(2)/(3))** — the 219-line residue is the four `⚡` entry-routing preambles + Step 8–12 workflow body. The prior extraction (`reference.md` + `inbox-propagation.md`) already moved every category-(1) candidate; the residue is category (2) (entry-routing preambles fire before any tool call) + (3) (workflow body executed every invocation).
- **Compaction-recovery callout stays inline where present** — spec § Key decisions row 4. Six of the seven skills carry a top-of-file compaction-recovery callout (`master-ci-failed`, `pr-ci-failed`, `pr-commented`, `bugfix`, `interview`, `task`); `ai-audit` carries `## Pre-flight: branch check` in lieu (same skill-loader contract — runs before any tool call on entry — also category (3)). Always category (3); category never reclassifies.

**Rejected alternatives:**

- _Move Spec Amendment recipe to `ai-docs/templates/spec-amendment-recipe.md`._ Rejected — adds one extra file load to every `/pr-commented` / `/pr-ci-failed` / `/master-ci-failed` invocation, contradicting the strict category-(3) rule.
- _Extract Step 2 log-fetch + classification + reproducer tables in `pr-ci-failed` / `master-ci-failed` to `reference.md` to push the file under 200 lines._ Rejected — those tables are category (3), consulted on every Step 2 execution. Same rejection rationale as Spec Amendment relocation. The honest answer is to keep them inline and document the exemption.
- _Extract `pr-commented` Step 0 GraphQL/REST snapshots and Step 2 classification table + pause triggers to `reference.md`._ Rejected — category (3); the orchestrator runs Step 0 every invocation and consults the Step 2 classification table for every unresolved thread.
- _Seven separate PRs._ Rejected by spec § Scope landing-strategy line.
- _Skip extraction entirely; document exemptions for all seven._ Rejected — `ai-audit/SKILL.md` (33,312 chars, 369 lines) is on the 35k early-warning band and has a clean category-(1) split (Checklist A–N detail bodies + Sub-checks 9/10); leaving it intact would be a missed-housekeeping decision.

## Handoff plan

`M = 6` (two groups, 3 + 3).

- **Entry into Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). The orchestrator NEVER executes subtask code in its own context — per the every-group handoff contract in `.claude/skills/task/SKILL.md` Step 8 + `.claude/skills/task/reference.md` § Every-group handoff (rationale), the first group also fans out through `/context-reset`.
- **Group A:** subtasks 1–3 — extraction of the three largest non-`task` SKILLs (`ai-audit`, `master-ci-failed`, `pr-ci-failed`). Group size = 3 subtasks (at the cap). Subtasks 1, 2, 3 are independent of each other (touch disjoint file pairs) and may be executed in any order within the group.
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` resumes in Group B with fresh context. Between groups the orchestrator re-validates branch + base_commit + clean tree per `.claude/skills/task/SKILL.md` Step 8 sub-step 5 contract.
- **Group B:** subtasks 4–6 — terminal group (3 subtasks; within the 1..=3 range). Subtask 4 extracts the last oversized skill (`pr-commented`) and writes its exemption comment; subtask 5 documents inline exemptions across the three no-extraction skills (`bugfix`, `interview`, `task`); subtask 6 is the cross-cutting verification sweep that depends on every prior subtask (per the `Depends on` column).

## Risks

- **Propagation Rule drift** — the AGENTS.md sync-group table references each SKILL.md by path; extraction does not change the SKILL path, but sibling references that previously cited a specific section heading (e.g. `pr-commented/SKILL.md § Step 4 Spec Amendment recipe`) need to re-target the new `reference.md § Spec Amendment recipe` anchor. **Mitigation:** subtask 6 runs the AGENTS.md `grep -rn "<changed-keyword>"` procedure as the explicit verification step; any dangling reference is updated in the same PR. Spec AC5 enforces this gate.
- **Skill loader cannot find compaction-recovery callout** — the callout MUST stay inline (category-(3) by spec § Key decisions row 4) because the skill is read at trigger time and the routing fires before any tool call (including the Read that would load `reference.md`). **Mitigation:** every extraction subtask explicitly retains the callout in SKILL body; subtask 6 sub-step (d) re-reads the callout and re-resolves every referenced path.
- **Round-template scaffolding accidentally extracted** — `pr-commented/SKILL.md` Step 1's `## Comment cycle round M` markdown block, `master-ci-failed/SKILL.md` Step 1's progress-file schema, and `pr-ci-failed/SKILL.md` Step 1's round-section template are category-(2) writeable surfaces. **Mitigation:** each subtask's per-section category map explicitly labels them KEEP (cat-2) and the extraction lists in subtasks 2/3/4 enumerate the category-(1) moves exhaustively, so any deviation from the list is detectable in the diff.
- **Workflow-time tables accidentally extracted** — `pr-commented/SKILL.md` Step 0 GraphQL/REST snapshots + Step 2 classification table + pause-trigger list, and `pr-ci-failed/SKILL.md` / `master-ci-failed/SKILL.md` Step 2 log-fetch + classification + reproducer tables are category-(3) workflow narrative the orchestrator consults on every invocation. Extracting them would force a `reference.md` Read per round, contradicting the same category-(3) constraint that rejected Spec Amendment recipe centralisation. **Mitigation:** subtasks 2/3/4 each explicitly enumerate these tables as KEEP (cat-3) with the workflow-time rationale spelled out; subtask 6 sub-step (b) records line-count deltas so an unexpectedly small SKILL.md (indicating a category-(3) section was wrongly moved) is detectable.
- **`task/SKILL.md` over-target with no extraction action** — at 219 lines, `task/SKILL.md` is 19 lines over the soft 200-line target, and subtask 5 only adds an exemption comment. **Mitigation:** spec § Key decisions row 3 ("200-line target — Soft") authorises documented exemptions; subtask 5's HTML comment names the four `⚡` preambles + Step 8 + Step 12 as load-bearing. AC1 explicitly accepts either ≤ 200 lines OR a load-bearing exemption.
- **`ai-audit` over-extraction risk** — counterintuitively, extracting too much from `ai-audit` could leave the SKILL body so thin that Step 2.3's checklist routing becomes a "stub linked to reference.md" that loses the skim-on-entry navigation property (AC4 mandates "every workflow step remains discoverable from SKILL.md directly or via a single hop"). **Mitigation:** subtask 1 explicitly retains Step 2.3 as a collapsed table of {letter, one-line purpose, `reference.md` link} inline — every check name + intent stays in the SKILL body; only the detail bodies move.
- **`ai-audit` under-target risk (counterpart)** — the ~171-line estimate is comfortably under 200, but the Step 2.3 collapsed-table re-write could expand the SKILL body if the table's per-letter purpose lines run long. **Mitigation:** subtask 1 authorises a defensive size-exemption comment if the final `wc -l` shows the file is over 200 by ≤ 10 lines; if > 10 over, subtask 1 surfaces to user (likely a missed category-(1) extraction).
- **AGENTS.md 40k char cap interaction** — none of the in-scope SKILL files is currently within the 35k early-warning band except `ai-audit` (33,312 chars). Adding new `reference.md` siblings does not touch the AGENTS.md cap (the cap names SKILL.md, not reference.md; same way `task/reference.md` is exempt today). **Mitigation:** subtask 6 sub-step (e) re-scans `wc -c` post-extraction to confirm.
- **PR diff size** — extracting four references in one PR yields a large diff. **Mitigation:** spec § Key decisions row 1 mandates single PR; commit granularity is one-per-skill (four extraction commits + one exemption-only commit for `bugfix`/`interview`/`task` + one verification commit = at most six commits in the PR) so reviewers can read each per-skill change as an atomic unit.
- **No skill workflow semantic change** — AC4 mandates byte-equivalent skill behaviour. **Mitigation:** every extraction is a pure relocate-with-pointer change; no rule is added, removed, or reworded. Subtask 6 sub-step (b) records line-count deltas as the AC6 cited number; if any deletion / addition crept in, the delta exceeds pure-move and the reviewer can detect it.

## Test Design

This is an instruction-file refactor (zero `.rs` diff). The verification surface is the seven AC checks the spec defines, executed manually as part of subtask 6. There is no `#[cfg(test)]` block and no integration test.

For subtask 6 (the verification sweep):

- **Location:** none in source code; verification commands run from the project root.
- **Entry point:** the AC1–AC7 checklist itself.
- **Scenarios:**
  - _AC1 — line target OR exemption._ `wc -l .claude/skills/{master-ci-failed,ai-audit,pr-ci-failed,pr-commented,bugfix,interview,task}/SKILL.md` returns each one of two satisfying states: (a) ≤ 200 lines, OR (b) an in-file `<!-- size-exemption: ... -->` comment immediately after the closing frontmatter `---`. Realistic expectation: `ai-audit/SKILL.md` is the only file that plausibly hits ≤ 200; the other six (`master-ci-failed` ~368, `pr-ci-failed` ~321, `pr-commented` ~300, `bugfix` 257, `interview` 227, `task` 219) carry the exemption comment. Verification command: `grep -L "^<!-- size-exemption:" .claude/skills/{master-ci-failed,pr-ci-failed,pr-commented,bugfix,interview,task}/SKILL.md` should print zero files; the same `grep -L` on `ai-audit/SKILL.md` is acceptable iff `wc -l` reports ≤ 200.
  - _AC2 — link integrity._ For each of the four new `reference.md` files, `realpath` resolves the relative link `../../../ai-docs/corrections-log.md` from `.claude/skills/<skill>/reference.md`. Each SKILL.md's `[reference.md](reference.md)` link resolves to a file in the same directory.
  - _AC3 — callout integrity._ Re-read the top-of-file pre-tool callout in each of the seven SKILLs (compaction-recovery callout where present — six skills — OR `## Pre-flight: branch check` in `ai-audit`). Resolve each path it cites: `.claude/skills/context-reset/SKILL.md`, the per-skill durable-state probe glob (e.g. `ai-docs/master-ci/*.progress.md`). All paths still resolve.
  - _AC4 — single-hop discoverability._ For each of the four extracted skills, walk the workflow once (read `SKILL.md` only — no Read on `reference.md`). Confirm every Step h3 is present and the workflow narrative is followable. Where the body says "see `reference.md § X`", record that as a single-hop reference (not a multi-hop).
  - _AC5 — propagation coherence._ `grep -rn "Spec Amendment recipe" .claude/agents/ .claude/skills/ AGENTS.md ai-docs/agent-writing-style.md` returns matches that ALL resolve to a real anchor in the corresponding `reference.md`.
