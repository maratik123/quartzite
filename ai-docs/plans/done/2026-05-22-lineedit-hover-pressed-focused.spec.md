# LineEdit hover / pressed / focused visual states

**Source:** issue #406 (folds in #407)
**Date:** 2026-05-22
**Tracked in:** Closes #406, Closes #407

> Surfaced by `/triage` from [`ai-docs/deferred/widget-backlog.md`](../../deferred/widget-backlog.md). Brings `impl Paint<LineEdit> for DefaultStyle` in `quartzite-style/src/default_style.rs` to parity with the four widgets that already render `hovered` / `pressed` / `focused` state — `Button` (#318 / post-#402) and `Label` / `TextEdit` / `ScrollArea` (#403, PR #524 merged 2026-05-21). Per the Round-1 fold-in decision, this spec also closes **#407 (LineEdit disabled-alpha parity with TextEdit)**: the current LineEdit impl applies `maybe_disabled` to nothing — neither its `Base`-role fill nor its `Text`-role outline nor its `Text`-role glyph brush — so disabled-LineEdit renders identically to enabled-LineEdit today. The new impl pipes every state-derived fill / text / non-focus-ring pen colour through `maybe_disabled(_, enabled)`, exactly as the post-#403 `impl Paint<TextEdit>` does. Event plumbing prerequisites are already in place: `WidgetBase` carries `hovered` / `pressed` / `focused` flags and `WidgetExt` exposes `is_hovered` / `is_pressed` / `is_focused` accessors. The `#[inline] const fn state_group(pressed: bool, hovered: bool) -> ColorGroup` selector + `maybe_disabled` helper + `FOCUS_RING_WIDTH = 2.0` const already exist in `default_style.rs` and are reused as-is. Only the `impl Paint<LineEdit>` body changes; no new public API, no `Style` / `Paint` trait surface change.
>
> LineEdit shares `TextEdit`'s idle visual idiom (`Base` fill + 1 px `Text` outline + plain-text glyphs + optional `read_only` overlay) but adds a single LineEdit-specific concern: **placeholder text rendering when `text.is_empty() && !placeholder.is_empty()`**. The current LineEdit impl dims the placeholder via `disabled(text_role_color)` — a fixed `× 0.5` alpha applied to `Text × Normal` regardless of widget enabled state. This spec preserves that placeholder-as-ghost-text idiom and folds it into the per-state text-colour resolution: the placeholder follows the state-resolved text colour, then receives the same fixed 0.5-alpha dim, mirroring how `impl Paint<TextEdit> for DefaultStyle` (post-#403) handles `read_only` text — state-resolved colour first, orthogonal modifier second.
>
> The spec is written against the two-axis palette API (`palette.color(role, ColorGroup::{Normal, Hover, Pressed})` + `ColorRole::FocusRing`) shipped by #402, and against the post-#403 `impl Paint<TextEdit> for DefaultStyle` as the closest established pattern reference. `Text`-role outline (not `WindowText`) per the existing LineEdit idle baseline.

## Scope

Add `hovered` / `pressed` / `focused` state-aware rendering AND `disabled`-axis colour dimming (parity with `TextEdit`, closing #407) to the existing `impl Paint<LineEdit> for DefaultStyle` in `quartzite-style/src/default_style.rs`. Visual idioms mirror the post-#403 `impl Paint<TextEdit>` pattern, adjusted for LineEdit's single-line / placeholder semantics. Concretely:

- `impl Paint<LineEdit> for DefaultStyle` reads `WidgetExt::is_hovered` / `is_pressed` / `is_focused` / `is_enabled` and produces the per-state visuals decided in § Key decisions. Existing idle-and-enabled behaviour (`Base`-role fill + 1 px `Text`-role outline + `Text`-role glyphs, with optional `read_only` overlay + placeholder-when-empty branch on top) is preserved as the baseline when all three new state flags are `false` AND `is_enabled() == true`. When `is_enabled() == false`, every state-derived fill / text / non-focus-ring pen colour additionally passes through `maybe_disabled(_, false)` — this is the #407 disabled-alpha parity with `TextEdit` and is a visible change from the pre-spec idle-disabled rendering.
- State resolution uses the shared `state_group(pressed, hovered)` selector that already lives in `default_style.rs` (lines 309–318). Every fill / text / non-focus-ring pen colour is `palette.color(role, group)`, with `maybe_disabled(_, enabled)` applied after lookup.
- **Pressed** swaps roles: fill = `palette.color(Highlight, Pressed)`, text = `palette.color(HighlightedText, Pressed)`, outline = `palette.color(HighlightedText, Pressed)` (matches text for legibility under the inverted fill — mirrors the post-#403 TextEdit decision).
- **Hover** keeps the LineEdit role set: fill = `palette.color(Base, Hover)`, text = `palette.color(Text, Hover)`, outline = `palette.color(Text, Hover)`.
- **Focused** widens the outline to `FOCUS_RING_WIDTH` (`2.0`) and switches its colour to `palette.color(ColorRole::FocusRing, ColorGroup::Normal)`. The FocusRing pen colour is exempt from `maybe_disabled` — it always renders at full alpha per the design-system additive-overlay rule (`design-system/README.md` § *Animation, hover, press*: "never alpha-halved"), matching shipped Button / Label / TextEdit / ScrollArea behaviour.
- **Disabled** (`!WidgetExt::is_enabled()`) passes every fill / text / non-focus-ring pen colour through `maybe_disabled` before painting, same as Button / Label / TextEdit / ScrollArea. **This closes #407** — the current LineEdit impl does NOT apply `maybe_disabled` anywhere, so disabled-LineEdit visibly changes (halved alpha on Base fill + Text outline + Text glyph brush, matching TextEdit's disabled rendering). The placeholder's existing `disabled()` dim composes orthogonally on top of `maybe_disabled` of the state-resolved text colour.
- **`read_only` overlay** stays orthogonal: the existing `read_only_overlay(palette)` fill applies on top of every state's base fill. Read-only text dimming via `text_role_color.with_alpha(READ_ONLY_TEXT_ALPHA)` continues to apply on top of the state-resolved text colour (mirrors how post-#403 TextEdit composes its `read_only` text dim).
- **Placeholder branch** stays: when `w.text.is_empty() && !w.placeholder.is_empty()`, the placeholder string is drawn at `disabled(state_resolved_text_color)` — same fixed `× 0.5` alpha currently applied to `Text × Normal`, but now applied to the state-resolved text colour (post-`maybe_disabled`) so hover/press placeholder lookups follow the design-system hover/press cells and disabled-state placeholders compose `maybe_disabled` × `disabled()` (≈ `× 0.25` alpha) on top of the role lookup.
- Recording-painter unit tests in `quartzite-style/src/default_style_tests.rs` (one per visible state, plus precedence tests for `(disabled, focused)` and `(pressed, hovered)`, plus a dedicated `(disabled, idle)` test asserting the #407 fold-in) toggle the matching flag on the widget's `WidgetBase` and assert the captured `Brush` / `Pen` matches the expected `palette.color(role, group)` value. The five existing `line_edit_*` recording-painter tests (lines 1023–1170 area in `default_style_tests.rs`) MUST still pass unchanged — the new state flags default to `false` AND the existing tests construct LineEdits with `is_enabled() == true`, so the idle-enabled path is preserved verbatim.
- Snapshot tests in `quartzite-style/tests/snapshots.rs` add **first-ever** LineEdit goldens under `quartzite-style/tests/snapshots/shared/`: `line_edit_idle.png`, `line_edit_hovered.png`, `line_edit_pressed.png`, `line_edit_focused.png`, `line_edit_disabled.png`, `line_edit_read_only.png`, `line_edit_placeholder.png` (light theme), plus `dark_line_edit_idle.png` + `dark_line_edit_focused.png` (dark theme). The `line_edit_disabled.png` golden anchors the #407 fold-in visibly. Naming mirrors the Button / Label / TextEdit / ScrollArea conventions established by #403.
- No `Style` / `Paint` trait surface redesign. No new public API on `WidgetBase` / `WidgetExt` / `DefaultStyle`. No new `ColorRole` / `ColorGroup` variants.

## Out of scope

- Adding new `ColorGroup` variants beyond `Normal` / `Hover` / `Pressed`. `Disabled` and `Focused` remain orthogonal modifiers per #402.
- Adding new `ColorRole` variants. `Base` / `Text` / `Highlight` / `HighlightedText` / `FocusRing` are all that this spec needs.
- Event plumbing (renderer → widget tree). Hit-testing, `MouseEnter` / `MouseLeave` synthesis, focus traversal, and per-widget event routing are already handled by the prior input-plumbing pass. Tests in this spec toggle `set_hovered` / `set_pressed` / `set_focused` directly on the widget's `WidgetBase`, exactly as the Button / Label / TextEdit / ScrollArea specs did.
- Cursor-shape changes on hover. Tracked under [#404](https://github.com/maratik123/quartzite/issues/404).
- LineEdit caret / selection / scroll-on-overflow rendering. The current impl paints the raw `text` string; caret and selection are not yet plumbed.
- `Container` hover / pressed / focused rendering. `Container` is a grouping widget with no inherent interactive surface; not within this issue's scope.
- `Style` / `Paint` trait surface redesign. Per the #403 precedent, per-widget state-awareness reduces to a one-line `state_group` selector plus two-axis palette lookups inside the `Paint<W>` impl. If the design phase discovers a concrete trait-level pain point, it returns NO-GO with the proposed redesign as a Design Amendment.
- Re-aligning Button / Label / TextEdit / ScrollArea paint impls. Those already ship the state-aware idiom this spec mirrors.

## Deferred

Only `dark_line_edit_idle.png` + `dark_line_edit_focused.png` ship in v1 to keep golden count proportional to the per-widget delta from #403 | follow-up only if a theme override surfaces visible divergence
- Combined-state snapshot goldens beyond single-flag coverage (e.g. `line_edit_focused_read_only.png`, `line_edit_disabled_focused.png`, `line_edit_pressed_placeholder.png`) | the Button / #403 specs capped at single-state goldens too; combinations are recording-painter-tested rather than snapshot-tested | follow-up if review flags a missing combo
- Re-paint trigger on state transition (calling `update()` after `set_hovered` / `set_pressed` / `set_focused`) | the input-plumbing pass owns the event-loop side and will set state + call `update()` together; this spec only changes paint output | input-plumbing pass

## Key decisions

| Question | Decision |
|---|---|
| Where the new render path lives | Inside the existing `impl Paint<LineEdit> for DefaultStyle` block in `quartzite-style/src/default_style.rs` (currently lines 273–303). No new modules, no new public API on `Style` / `DefaultStyle`. Mirrors the #403 decision verbatim. |
| Closest pattern reference | Post-#403 `impl Paint<TextEdit> for DefaultStyle` (lines 161–219). Same idle-baseline shape (`Base` fill + 1 px `Text` outline + plain-text glyphs + `read_only` overlay), same state-axis decisions (`Highlight × Pressed` fill + `HighlightedText × Pressed` text + outline-role swap to `HighlightedText` on press), same `FOCUS_RING_WIDTH = 2.0` focus outline rule. |
| Visual idioms — source of truth | **`design-system/README.md` § *Animation, hover, press*** + the palette derivation rule from `Palette::color`. `Hover = role × Hover` cell (default-derived as `c.blend(WindowText.Normal, 0.06)` inside `Palette::color`); `Pressed = Highlight × Pressed` fill + `HighlightedText × Pressed` text (role-swap + group lookup, both via the palette); `Focused = additive 2 px outline using `palette.color(ColorRole::FocusRing, ColorGroup::Normal)`, always full alpha; `Disabled = × 0.5 alpha applied after role/group resolution via `maybe_disabled` (unchanged). |
| Disabled-state interaction (#407 fold-in) | Apply `maybe_disabled(color, enabled)` (already defined in `default_style.rs:352`) to every state-derived fill / text / non-focus-ring pen colour before painting, same as Button / Label / TextEdit / ScrollArea. **This closes #407.** The pre-spec LineEdit impl does not call `maybe_disabled` at all, so disabled-LineEdit visibly changes — its `Base` fill, `Text` outline, and `Text` glyph brush all halve their alpha when `!is_enabled()`, reaching parity with the post-#403 `Paint<TextEdit>` impl. The placeholder's existing `disabled()` dim composes orthogonally on top of `maybe_disabled` of the state-resolved text colour: enabled-placeholder = `× 0.5` (existing fixed dim); disabled-placeholder = `× 0.5 × 0.5 = × 0.25` (placeholder dim on top of disabled dim). The FocusRing pen is exempt from `maybe_disabled` per the design-system additive-overlay rule. |
| Placeholder interaction with state | When `w.text.is_empty() && !w.placeholder.is_empty()`, the placeholder is drawn at `disabled(maybe_disabled(palette.color(text_role, group), enabled))` — the state-resolved text colour, passed through `maybe_disabled`, then dimmed by the fixed `disabled()` helper. This preserves the current placeholder-as-ghost-text idiom and extends it through hover/press cells so the placeholder visually tracks the text-axis state-group rather than staying frozen at `Text × Normal`. |
| `read_only` overlay interaction with state | The `read_only_overlay(palette)` fill applies on top of every state's base fill (orthogonal). Read-only text dimming via `text_role_color.with_alpha(READ_ONLY_TEXT_ALPHA)` continues to apply on top of the state-resolved text colour — exactly as post-#403 `Paint<TextEdit>` composes its `read_only` text dim. The placeholder branch is mutually exclusive with the `read_only` text branch (existing `if/else if/else` shape preserved). |
| Outline role mapping | **Idle / Hover:** `palette.color(Text, group)` — keeps the LineEdit-specific `Text`-role outline (LineEdit pre-#406 uses `Text`, distinct from ScrollArea's `WindowText`). **Pressed:** `palette.color(HighlightedText, Pressed)` — matches text colour for legibility under the inverted Highlight fill, mirroring post-#403 TextEdit. **Focused:** `palette.color(FocusRing, Normal)` at 2 px width, full alpha. |
| `LineEdit` visual mapping | **Idle:** `palette.color(Base, Normal)` fill + 1 px `palette.color(Text, Normal)` outline + `palette.color(Text, Normal)` glyphs (shape unchanged from current impl, with explicit `Normal`-group lookups already in place). **Hover:** fill = `palette.color(Base, Hover)`; outline width 1 px, colour = `palette.color(Text, Hover)`; text colour = `palette.color(Text, Hover)`. **Pressed:** fill = `palette.color(Highlight, Pressed)`; text colour = `palette.color(HighlightedText, Pressed)`; outline width 1 px, colour = `palette.color(HighlightedText, Pressed)`. **Focused:** outline widened to 2 px using `palette.color(FocusRing, Normal)`; fill / text follow whichever of idle / hover / pressed applies. **Read-only overlay** applies on top of every state's fill (orthogonal). **Placeholder** is drawn at `disabled(maybe_disabled(text_role_color_at_group, enabled))` when `text.is_empty() && !placeholder.is_empty()`. **Disabled:** every resolved fill / text / non-focus-ring pen colour passes through `maybe_disabled`. |
| State precedence (fill / text axis) | `disabled` > `pressed` > `hovered`. `checked` does not apply (LineEdit has no `checked` flag). `focused` remains an additive outline modifier orthogonal to the fill axis. Carries over verbatim from #403. |
| Snapshot test coverage shape | First-ever LineEdit goldens. **Light theme** under `shared/`: `line_edit_idle.png`, `line_edit_hovered.png`, `line_edit_pressed.png`, `line_edit_focused.png`, `line_edit_disabled.png`, `line_edit_read_only.png`, `line_edit_placeholder.png` (seven goldens — `line_edit_disabled.png` is the #407 fold-in anchor). **Dark theme** under the `dark_` prefix flow: `dark_line_edit_idle.png`, `dark_line_edit_focused.png`. Concrete file list pinned under § Acceptance Criteria. Dark hover/pressed goldens deferred per the #403 precedent. |
| Recording-painter test layout | Each new state per widget gets a `#[test]` in `default_style_tests.rs` alongside the existing five `line_edit_*` tests (lines 1023–1170 area). Plus `(disabled, focused)` and `(pressed, hovered)` precedence tests. Plus a `(hovered, placeholder)` interaction test asserting the placeholder colour tracks the state-resolved text colour. Plus a dedicated **`(disabled, idle)` parity test** (the #407 fold-in anchor) asserting `Brush::solid(maybe_disabled(palette.color(Base, Normal), false))` for the fill, `Pen` colour `maybe_disabled(palette.color(Text, Normal), false)` at 1 px for the outline, and `Brush::solid(maybe_disabled(palette.color(Text, Normal), false))` for the text glyph brush. Mirrors the #403 spec's AC3–AC6 shape. |
| No new public API | `WidgetBase` / `WidgetExt` / `Style` / `Paint` / `DefaultStyle` public surfaces are unchanged. Only the `impl Paint<LineEdit> for DefaultStyle` body changes. `ColorGroup`, `ColorRole::FocusRing`, two-axis `Palette::color` / `Palette::with_role`, the shared `state_group` / `maybe_disabled` / `read_only_overlay` / `disabled` helpers, and the `FOCUS_RING_WIDTH` const already exist on `master`; this spec consumes them. |

## Technical constraints

- `quartzite-style` already depends on `quartzite-widgets`; the new code reads `WidgetExt::is_hovered` / `is_pressed` / `is_focused` / `is_enabled` exactly as the shipped Button / Label / TextEdit / ScrollArea impls do. No new dependency edges.
- The two-axis `Palette::color(role, group)` and `Palette::with_role(role, group, color)` signatures are the only palette APIs used. No direct `Color::blend` arithmetic in the new paint path; the blend lives inside `Palette::color`'s default derivation.
- `state_group` (line 310), `maybe_disabled` (line 352), `read_only_overlay` (line 341), `disabled` (line 330), `brush` (line 322), and `FOCUS_RING_WIDTH` (line 23) in `default_style.rs` are reusable as-is.
- The existing `RecordingPainter` fixture in `default_style_tests.rs` is reusable as-is for per-state `Brush` / `Pen` assertions. New tests slot alongside the existing five `line_edit_*` tests.
- The existing snapshot harness (`quartzite-style/tests/snapshots.rs` + `quartzite-style/tests/support/mod.rs` mirroring `quartzite-widgets/tests/support/mod.rs`) is reusable. New tests follow the per-widget test pattern established by Button / Label / TextEdit / ScrollArea.
- Doc gate: no new public items expected; the `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features` gate must stay clean.
- Lint gate: `cargo clippy --workspace --all-targets -- -D warnings` clean.
- File-size budget: `default_style.rs` is currently 358 lines. The `Paint<LineEdit>` impl will grow modestly (the state-axis branch additions plus the placeholder-tracks-state refactor). Should comfortably stay below the 500-line soft target. If the design phase finds the file crowding 500, factoring per-widget impls into sibling modules is fine.

## Acceptance Criteria

> All ACs are written against the two-axis palette API (`palette.color(role, group)` + `ColorRole::FocusRing` + two-axis `Palette::with_role`) that already exists on `master`.

| # | Criterion |
|---|-----------|
| AC1 | **LineEdit state-aware rendering.** `impl Paint<LineEdit> for DefaultStyle` reads `is_hovered` / `is_pressed` / `is_focused` / `is_enabled`. Recording-painter tests assert: idle-enabled fill brush colour equals `palette.color(Base, Normal)` (unchanged baseline); hover-enabled fill brush colour equals `palette.color(Base, Hover)`, outline pen colour equals `palette.color(Text, Hover)`, text brush colour equals `palette.color(Text, Hover)`; pressed-enabled fill brush colour equals `palette.color(Highlight, Pressed)`, text brush colour equals `palette.color(HighlightedText, Pressed)`, outline pen colour equals `palette.color(HighlightedText, Pressed)`; focused outline pen width equals `2.0` and pen colour equals `palette.color(FocusRing, Normal)`. **Every fill / text / non-focus-ring pen value above is wrapped in `maybe_disabled(_, is_enabled())` in the implementation** — for enabled widgets this is a no-op so the assertions above remain literal; for disabled widgets the assertions become `maybe_disabled(palette.color(role, group), false)` (≈ `× 0.5` alpha). |
| AC2 | **Disabled-axis parity with TextEdit (closes #407).** A new recording-painter test `line_edit_disabled_idle_dims_base_text_outline` constructs a LineEdit with `is_enabled() == false` and asserts: fill brush equals `Brush::solid(maybe_disabled(palette.color(Base, Normal), false))`; outline pen colour equals `maybe_disabled(palette.color(Text, Normal), false)` at width `1.0`; text glyph brush equals `Brush::solid(maybe_disabled(palette.color(Text, Normal), false))`. **This is a visible change from the pre-spec LineEdit impl**, which applies `maybe_disabled` to none of these — disabled-LineEdit on `master` today renders identically to enabled-LineEdit. Post-spec, disabled-LineEdit matches the post-#403 `Paint<TextEdit>` disabled treatment. |
| AC3 | **State precedence.** `disabled` (`!is_enabled()`) overrides any other fill / text / non-focus-ring pen via `maybe_disabled`; `pressed` overrides `hovered` on the fill axis where both apply; `focused` is an additive outline modifier orthogonal to the fill axis. Recording-painter tests exercise `(disabled, focused)` to confirm the outline still fires at 2 px under disabled with the **full-alpha** `palette.color(FocusRing, Normal)` pen colour (the FocusRing pen is exempt from `maybe_disabled` — it is never alpha-halved, per the design-system additive-overlay rule and shipped Button / Label / TextEdit / ScrollArea behaviour), and `(pressed, hovered)` to confirm `pressed` wins — i.e. the fill brush equals `palette.color(Highlight, Pressed)`, not `palette.color(Base, Hover)`. |
| AC4 | **Placeholder tracks state-resolved text colour.** When `text.is_empty() && !placeholder.is_empty()`, the placeholder is drawn at `disabled(maybe_disabled(palette.color(text_role, group), enabled))` — the state-resolved text colour passed through `maybe_disabled`, then through the fixed `disabled()` helper for the placeholder-ghost-dim. A recording-painter test toggles `(hovered, placeholder)` and asserts the placeholder brush colour equals `disabled(palette.color(Text, Hover))`. A second test toggles `(pressed, placeholder)` and asserts `disabled(palette.color(HighlightedText, Pressed))`. A third test toggles `(disabled, placeholder)` and asserts `disabled(maybe_disabled(palette.color(Text, Normal), false))` (composing the placeholder's `× 0.5` dim on top of the disabled `× 0.5` dim, yielding `≈ × 0.25` alpha — the #407 fold-in flowing through the placeholder branch). |
| AC5 | **Read-only overlay orthogonality.** With `read_only = true`, the `read_only_overlay(palette)` fill applies on top of every state's base fill; read-only text dimming via `text_role_color.with_alpha(READ_ONLY_TEXT_ALPHA)` applies on top of the state-resolved text colour. A recording-painter test toggles `(read_only, hovered)` and asserts both the overlay fill (a `Brush::solid` with `read_only_overlay(palette)` colour) and the hover-state base fill (`palette.color(Base, Hover)`) are captured in order. |
| AC6 | **Idle-enabled baseline preserved.** All five existing `line_edit_*` tests in `default_style_tests.rs` still pass unchanged — the new state flags default to `false` AND the existing tests construct LineEdits with `is_enabled() == true`, so `maybe_disabled` is a no-op on every colour and idle rendering produces the same event sequence and the same literal `palette.color(role, Normal)` lookups as before this spec. |
| AC7 | **Snapshot coverage — first-ever LineEdit goldens.** Nine new goldens under `quartzite-style/tests/snapshots/`: light variants `line_edit_idle.png`, `line_edit_hovered.png`, `line_edit_pressed.png`, `line_edit_focused.png`, `line_edit_disabled.png`, `line_edit_read_only.png`, `line_edit_placeholder.png` under `shared/`; dark variants `dark_line_edit_idle.png`, `dark_line_edit_focused.png` under the `dark_` prefix flow. `line_edit_disabled.png` is the visible #407 fold-in anchor. (Dark `hovered` / `pressed` goldens deferred per § Deferred row 1; combined-state goldens deferred per § Deferred row 2.) |
