# Design: Extract instruction-rewrite methodology into a permanent reference doc

**Issue:** #531
**Spec:** [`ai-docs/plans/2026-05-22-extract-instruction-rewrite-methodology.spec.md`](2026-05-22-extract-instruction-rewrite-methodology.spec.md)
**Date:** 2026-05-22

## Approach

Doc-only extraction. The chosen execution order is:

1. **Author the new reference doc first** (`ai-docs/instruction-file-validation.md`) by copying the seven methodology sections out of the source plan **verbatim**, with only H2 heading text restructured to the destination names from Spec Scope item 2. The source file is **not yet modified** at this point — both files coexist temporarily.
2. **Edit-in-place the source plan** to (a) strip the seven extracted H2 sections by **H2-grep pattern** (strip from `^## <source heading>$` to the line before the next `^## ` H2), (b) rewrite `## Citation in future PRs` to point at the new reference doc, and (c) rewrite the three internal self-references currently at lines 620 / 628 / 1012 to target either the new reference doc (methodology references) or the same-directory archived plan (historical decision context).
3. **`git mv` the stripped source plan** to `ai-docs/plans/done/2026-05-08-instruction-file-rewrite.md`. The `git mv` itself satisfies AC4 — both ends of the existing link in `done/2026-05-10-process-improvements.md` (which already reads `[2026-05-08-instruction-file-rewrite.md](2026-05-08-instruction-file-rewrite.md)`) now sit in `done/`. No text edit to `process-improvements.md` is needed; only a `realpath` verification step (folded into task 5).
4. **Add the AGENTS.md table row + the agent-docs-index.md verbose body** for the new reference doc.
5. **Verification gates** run as a single subtask at the end: AC6 grep, AGENTS.md `wc -c` budget check, AC8 relative-link `realpath` trace, `cargo build` + `cargo clippy --workspace --all-targets -- -D warnings`.

**Why this order:**

- The new doc must exist before the source plan loses its methodology body, so the rewritten Citation section + the rewritten internal self-references can target a doc that already exists in the working tree (avoids a half-state where the surviving plan's anchors point at a not-yet-written file). Git's diff tracking is unaffected — `git mv` preserves history regardless of edit order, as long as the rename is the last step on that file's path.
- The `git mv` lands AFTER the strip + Citation rewrite so the surviving file's relative paths (`../instruction-file-validation.md` from `ai-docs/plans/`) are fixed up to the post-move form (`../../instruction-file-validation.md` from `ai-docs/plans/done/`) in the same task that performs the rename, keeping the move-and-fixup atomic per file.
- The AGENTS.md row + agent-docs-index.md entry come after the doc-extraction subtasks so the row's existence reflects an already-written reference doc, not a forward-promise. This keeps each commit individually `gh pr view`-readable.
- Verification runs **last** so the AC6 grep sees the final state of all moved / rewritten references in one pass, not a transient mid-task state with stale stray refs.

**Rejected alternatives:**

- *Edit the source plan in place first, then create the new doc by copying from `done/`.* Rejected: leaves the source plan with broken internal anchors during the strip step (the `#methodology-limitations` anchor at line 1012 references a section that has already been stripped from the same file). Also makes the AC6 mid-task grep state confusing.
- *Do extraction and `git mv` in one subtask.* Rejected: `git mv` of a file that already has substantial pre-mv content edits in the same commit risks Git computing the change as delete + add (history loss) rather than rename + modify. Splitting strip-edit from rename keeps Git's rename detection inside the empirical 50% similarity threshold (the stripped plan is ~330 lines + ~330 unchanged lines vs the original ~1,354 lines — ~25% similarity by lines, well below the threshold, BUT the move and the strip live in different commits, so Git compares the move against the post-strip state, which is identical → 100% similarity at rename detection time).
- *Restructure section bodies during extraction (not just headings).* Rejected: Key decision Round 1 commits to verbatim extraction. The historical PR citations and worked examples are load-bearing concrete evidence — abstracting them destroys the methodology's testability.
- *Add a standalone "update path citations in `process-improvements.md`" subtask.* Rejected: the existing link strings in `process-improvements.md` lines 11 and 380 are already `[2026-05-08-instruction-file-rewrite.md](2026-05-08-instruction-file-rewrite.md)` — same-directory link form. Once task 5's `git mv` puts the target into `done/` alongside `process-improvements.md`, AC4 is satisfied automatically with **zero text edit**. A "rewrite identical string to identical string" subtask would produce an empty diff and inflate M artificially. Task 5 carries a `realpath` verification step to confirm AC4.

## Handoff plan

`M = 7` subtasks → three groups (3 + 3 + 1).

- **Entry into Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` begins Group A in fresh context.
- **Group A:** subtasks 1–3 — author the new reference doc (verbatim extraction), rewrite internal anchors / cross-references inside the new doc, and strip the source plan in place by H2 pattern. Three subtasks (at the 3-subtask cap).
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` resumes in Group B with fresh context.
- **Group B:** subtasks 4–6 — rewrite Citation + self-references in the surviving plan; `git mv` to `done/` + fix `../` paths + verify AC4 via `realpath`; add the AGENTS.md table row + agent-docs-index.md verbose body to register the new doc in the workspace index. Three subtasks (at the 3-subtask cap). Logical seam: "rename + register the new doc in workspace index".
- **Handoff after Group B:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` resumes in Group C with fresh context.
- **Group C:** subtask 7 — terminal group (1 subtask; within the 1..=3 range). Run verification gates (AC6 grep, AC7 `wc -c` budget, AC8 `realpath` trace, `cargo build` + `cargo clippy --workspace --all-targets -- -D warnings`).

## Risks

- **Risk: `git mv` rename detection fails because the strip edit removed > 50% of the file content in the same commit as the rename.** *Mitigation:* split strip-edit (task 3) and `git mv` (task 5) across separate commits (split implied by `Depends on: 4` chain). At the rename commit, the file's diff is empty (only path changes), so Git's rename detection reports 100% similarity. Pre-mv similarity at the strip commit is irrelevant to history preservation; only the rename commit's similarity is compared by `git log --follow`.
- **Risk: AC4 is accidentally re-implemented as a text-rewriting subtask in a future iteration, producing an empty diff.** *Mitigation:* the existing link strings in `done/2026-05-10-process-improvements.md` lines 11 + 380 are already `[2026-05-08-instruction-file-rewrite.md](2026-05-08-instruction-file-rewrite.md)` — same-directory form. AC4 is satisfied **automatically** by task 5's `git mv` with **zero text edit** to `process-improvements.md`. Task 5's final-action `realpath` verification confirms the link resolves. This Risks entry exists so a future reader does not reintroduce an empty-diff "update path citations" subtask.
- **Risk: AC6 grep returns unexpected hits the spec didn't enumerate (Spec Amendment trigger).** *Mitigation:* the design phase has already enumerated every current occurrence via `grep -rn '2026-05-08-instruction-file-rewrite' .` — the live state matches the spec's expected allow-set (the plan file's three internal self-refs + `process-improvements.md` × 2 + rename spec/design × 6 hits + this spec/design). No unexpected reference exists. If task 7's post-implementation grep surfaces a hit not in the § Test Design AC6 enumeration, `/task` Step 7 *Spec Amendment recipe* fires.
- **Risk: AGENTS.md char count crosses 40,000 after the row addition.** *Mitigation:* current size is 35,807 chars; the row text is `| \`ai-docs/instruction-file-validation.md\` | Dual-model instruction-file-clarity test methodology + bias taxonomy + subagent prompt templates. Read on demand. |` = ~170 chars including the leading `\n`. Post-add estimate: ~35,977 chars — well below both 40,000 and the 35,000 early-warning threshold's "next-task-headroom" intent (the file is already over the early warning, but the 40k hard cap has > 4 KB of headroom remaining). Task 6 includes the `wc -c` confirmation step.
- **Risk: Heading slug change breaks anchors in OTHER files that link to `#methodology-limitations` or `#historical-replay-testing-complement-to-v42`.** *Mitigation:* run `grep -rn 'methodology-limitations\|historical-replay-testing' . --exclude-dir=.git --exclude-dir=node_modules` during task 2 to enumerate all anchor consumers; rewrite each to the new doc's slug. Expected consumers from this investigation: the source plan's own Goal-section anchors (handled by task 4) and line 1012's anchor (handled by task 2 because line 1012 lives inside the extracted body). No external consumers found in `.claude/` or `ai-docs/` reference docs.
- **Risk: The new doc lands at > 1,000 lines and triggers a future `/ai-audit` concern.** *Mitigation:* per Key decisions row 1, `ai-docs/skill-size-exemptions.md` scopes to `.claude/skills/*/SKILL.md` only. Sibling `ai-docs/*.md` files (code-style.md at 477 lines, doc-convention.md at 615 lines) already exceed 200 lines without exemption — the project's de-facto convention for `ai-docs/` reference docs is "size driven by content, no soft target". No mitigation needed.
- **Risk: The verbatim extraction copies stale anchor / link syntax from the source plan that no longer resolves from the new location.** *Mitigation:* task 2 includes a full audit pass — read every `[text](target)` and `[text](#anchor)` in the new doc, verify each target. Relative paths in the extracted bodies (e.g. `(../agent-writing-style.md)` from the source plan's `ai-docs/plans/` location) need rewriting to the new location's resolution (`(agent-writing-style.md)` from `ai-docs/`).

## Test Design

This is a documentation-extraction task — no Rust code touched, no `#[cfg(test)]` modules added. Verification is structural:

- **Structural-completeness check (AC1):** after task 1, grep the new doc for each of the seven destination H2 headings from Spec Scope item 2. All seven must be present.
- **Verbatim-preservation check (task 1 internal):** spot-check the v5 workflow's load-bearing concrete sentences in the new doc — the v4.4 6/6 replay batch table, the Class A/B/C/D probe count tables, the worked examples (300-line / code-style.md / flat-file hypotheticals), the 8-row Methodology-limitations table — must appear unchanged from source lines (cross-spot-check at task 1 completion).
- **Anchor-resolution check (AC8 / task 2 audit / task 5 audit / task 7):** every relative link inside the new doc, the moved plan, and `process-improvements.md` lines 11 + 380 must resolve via `realpath`. AC8 explicitly requires the trace for one link inside the new doc; the broader audit covers every other link.
- **AC4 verification (task 5 final action):** from `done/2026-05-10-process-improvements.md`'s directory, resolve the literal link target `2026-05-08-instruction-file-rewrite.md` via `realpath` and confirm it points to the moved file (the `git mv` from task 5 is what satisfies AC4 — no text rewrite needed because the link is already in same-directory form pre-move).
- **AC6 grep gate (task 7) — expected post-rewrite set:** the exact command `grep -rn '2026-05-08-instruction-file-rewrite' . --exclude-dir=.git` returns:
  - **(a) `ai-docs/plans/done/2026-05-08-instruction-file-rewrite.md` — zero hits expected after task 4 rewrites the Citation section.** Task 4 rewrites the two block-quote citation templates currently at lines 620/628 to cite `ai-docs/instruction-file-validation.md` instead of `ai-docs/plans/2026-05-08-instruction-file-rewrite.md`. Line 1012's self-reference lives inside an extracted body that moves to the new doc at task 1, so it leaves the moved plan entirely. After tasks 3 + 4 + 5, the moved plan contains **zero** occurrences of the substring `2026-05-08-instruction-file-rewrite` inside its own body (the filename itself appears in the file's path, but `grep -rn` matches on file *contents*, not paths).
  - **(b) `ai-docs/plans/done/2026-05-10-process-improvements.md` lines 11 + 380** — both lines retain the literal string `2026-05-08-instruction-file-rewrite.md` as the link target (unchanged from current state); both now resolve correctly because both ends sit in `done/`.
  - **(c) `ai-docs/plans/done/2026-05-22-rename-code-review-to-project-review.spec.md` lines 9, 36, 47, 89** — frozen carve-out per spec Decision 4 / AC6 enumeration.
  - **(d) `ai-docs/plans/done/2026-05-22-rename-code-review-to-project-review.design.md` lines 32, 45** — frozen carve-out per spec Decision 4 / AC6 enumeration.
  - **(e) `ai-docs/plans/2026-05-22-extract-instruction-rewrite-methodology.spec.md`** — in-flight artefact, becomes `done/` at `/task` Step 12.
  - **(f) `ai-docs/plans/2026-05-22-extract-instruction-rewrite-methodology.design.md`** — also in-flight, becomes `done/` at `/task` Step 12.

  Line numbers in (b) / (c) / (d) are subject to drift between design and run-time — task 7 records the actual post-rewrite line numbers in its progress log. The set of *files* is exhaustive; any hit in a file not in this list triggers `/task` Step 7 *Spec Amendment recipe*.
- **AC7 char-budget gate (task 6 + task 7):** `wc -c AGENTS.md CLAUDE.md .claude/skills/**/*.md .claude/agents/**.md .claude/rules/*.md ai-docs/{code-style,doc-convention,context,agent-writing-style,corrections-log}.md` shows every file < 40,000 chars.
- **AC9 baseline sanity (task 7):** `cargo build` + `cargo clippy --workspace --all-targets -- -D warnings` pass (no code touched, but the gate is enumerated in the spec).
- **AC10 self-review (post-task-7):** `/task` Step 10 spawns `self-review` over the full PR diff before `git push`.
