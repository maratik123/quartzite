# Design: Rename `/code-review` skill to `/project-review`

**Issue:** #529
**Date:** 2026-05-22

## Approach

A pure instruction-file rename — no Rust source is touched. The diff splits cleanly into two operations performed in the listed order:

1. **Directory rename** via `git mv .claude/skills/code-review .claude/skills/project-review`. This preserves the `SKILL.md` git history chain (`git log --follow` proves the link). Doing the rename FIRST (before any token rewrite) keeps the rename and the edits as separate diff hunks that reviewers can read independently; the rename move is rendered as `R100` by git when the body is unchanged at that moment.
2. **Token sweep** across 15 individual files (plus the moved `SKILL.md` itself). Each file's `code-review` occurrences are rewritten to `project-review` (skill body / cross-references) or `/project-review` (skill invocation form). The two agent-file `description:` frontmatter fields and AGENTS.md § Communication line require a grammaticality re-read after substitution per the technical constraint in spec § Technical constraints.

The token sweep is grouped by concern, not by directory, so each subtask covers a logically coherent surface (the skill itself, its sibling agents, the rule index in AGENTS.md, the high-touch context-reset SKILL, the smaller instruction files, and the historical-narrative cells). This grouping aligns with the AGENTS.md Propagation Rule's "Review group" boundary and minimises cross-subtask coupling.

**Rejected alternatives:**

- *Single monolithic subtask.* Reviewers cannot inspect a 16-file diff as one unit. The Review-group propagation contract (AGENTS.md § Propagation Rule) is also more legible when the skill rename and its two sibling-agent updates ship as adjacent subtasks.
- *`sed -i` global substitution.* The two `description:` frontmatter lines require grammaticality re-reads; a blind substitution risks producing a sentence like "Invoked by /project-review" attached to text that no longer parses. Per-file `Edit` calls keep the grammaticality check explicit.
- *Defer historical-narrative rewrites (INDEX.md, deferred/*, settings.local.json) to a follow-up PR.* The user resolved the Round-1 Open question as "Rewrite all" (spec § Key decisions row 1); deferring would re-open that question.
- *Add a `pub use`-style compat alias / shim.* Forbidden by AGENTS.md § API Stability AXIOM (pre-publish, clean breaks). The directory rename is total; no `/code-review` invocation remains.
- *Compat-keep `.claude/skills/code-review/` as a stub pointing to the new path.* Same AXIOM. The slash-skill registry is discovered from the directory tree; a stub directory would re-register the old name.

## Handoff plan

`M = 6` (two groups, 3 + 3). Every-group `/context-reset` handoff per `.claude/skills/task/SKILL.md` Step 8 + `.claude/skills/task/reference.md` § *Every-group handoff (rationale)*.

- **Handoff into Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` enters Group A with fresh context.
- **Group A:** subtasks 1–3 — skill directory rename + `SKILL.md` body, Review-group sibling agents, AGENTS.md + context-reset SKILL high-touch sweep (3 subtasks; non-terminal group, exactly 3 per `(b)`).
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` resumes Group B with fresh context.
- **Group B:** subtasks 4–6 — remaining forward-living instruction files, historical-narrative rewrites, verification + PR-body authoring — terminal group (3 subtasks; within the 1..=3 range per `(d)`).

## Risks

- **AC6 grep exclusion list is subtle.** The six exclusion flags (`--exclude=learnings.md`, `--exclude=learnings-escalation-audit.md`, `--exclude=corrections-log.md`, `--exclude-dir=done`, `--exclude=2026-05-08-instruction-file-rewrite.md`, `--exclude='2026-05-22-rename-code-review-to-project-review.*'`) each defend a named carve-out. The sixth (`--exclude='2026-05-22-rename-code-review-to-project-review.*'`) covers THIS PR's own planning files (spec / design / progress / pr-body), which necessarily reference `code-review` because they describe the rename itself — analogous to the `--exclude=2026-05-08-instruction-file-rewrite.md` carve-out for the prior frozen plan. The matched files move to `ai-docs/plans/done/` at `/task` Step 12 (also covered by `--exclude-dir=done`) or are deleted post-merge (`.progress.md`, gitignored). **Mitigation:** subtask 6 runs the grep verbatim as quoted in the spec § AC6 cell; if any unexpected hit appears, the result is treated as a Spec Amendment trigger per `/task` Step 7 *Spec Amendment recipe*, not silently masked by adding a new exclusion.
- **Typo-source preservation in subtask 4.** Two files share a similar substring shape on the named lines, but the rewrite scope per file is different:
  - `learnings-escalation-audit.md` line 105 contains THREE `code-review` substring occurrences: the typo-source LHS `skillcode-review` (kept verbatim) AND TWO forward-living `skill:code-review` references — (i) the explanatory clause "the rule is now in `skill:code-review`" and (ii) the corrected-form RHS of the typo-correction example pair. BOTH forward-living references are rewritten to `skill:project-review`; only `skillcode-review` survives.
  - `corrections-log.md` line 15 contains exactly the typo-example pair: ONE typo-source LHS `skillcode-review` (kept verbatim) AND ONE forward-living `skill:code-review` (corrected-form RHS) → rewritten to `skill:project-review`. Confirmed at design time — no second forward-living reference on this line.
  **Mitigation:** per-file `Edit` calls with unique surrounding context that captures each `skill:code-review` occurrence individually without overlapping the `skillcode-review` literal. After each edit, a per-file `grep -n 'code-review' <file>` is expected to return ONLY the `skillcode-review` typo-source lines — that residue is exactly what AC6's exclusion flags (`--exclude=learnings-escalation-audit.md`, `--exclude=corrections-log.md`) cover. Any other residual `code-review` hit signals an incomplete rewrite.
- **Anchor heading in `context-reset/SKILL.md` (subtask 3).** The `## Compaction recovery (re-entry)` h2 heading on line 47 (or thereabouts) does NOT contain `code-review` and must remain bit-for-bit identical — other skills cross-link to it by exact heading text. **Mitigation:** the 8 `code-review` hits in this file are all in surrounding prose; the heading line itself has no `code-review` token so token-rewrite cannot accidentally touch it. Subtask 3 ends with an explicit `grep -n '## Compaction recovery' .claude/skills/context-reset/SKILL.md` confirming the anchor is present and unchanged.
- **Grammaticality of `description:` frontmatter (subtask 2).** Token substitution can leave a sentence syntactically valid but pragmatically odd ("Invoked by /project-review at the start of a whole-branch review" is fine; longer sentences in either file may not be). **Mitigation:** subtask 2's exit criterion includes a full per-file re-read of the post-edit `description:` line, treating the line as a single English sentence rather than a substring-edited template.
- **History preservation under `git mv` (AC1).** `git mv` followed by edits in the same commit can cause git's rename detection to fall below the 50% similarity heuristic if the body edits are extensive. The body edit count is 5 token swaps (≪ 50% body change), so detection holds. **Mitigation:** subtask 1 verifies `git status` shows `R100` (or `R9x`) for `.claude/skills/code-review/SKILL.md → .claude/skills/project-review/SKILL.md` after the move + edit, before staging. If detection fails, the recovery is to split into two commits (move-only commit + edit commit) — both still satisfy AC1's `git log --follow` requirement. **Branch-name precondition (AGENTS.md § Workflow AXIOM 1):** before any `git mv` or `Edit` is issued, the implementer MUST be on a feature branch — the canonical name for this PR is `feat/2026-05-22-rename-code-review-to-project-review`. Verify with `git branch --show-current`; if it returns `master`, run `git checkout -b feat/2026-05-22-rename-code-review-to-project-review` BEFORE any edit. AXIOM 1's recovery recipe applies if uncommitted edits already exist on local `master`.
- **README sweep negative finding (AC16).** Spec § Scope row 7 mandates documenting a zero-hit result in the PR body. **Mitigation:** subtask 6 runs both grep variants explicitly (`grep -rn 'code-review' README.md` and `grep -rn 'code-review' --include=README.md`) and writes the literal command + zero-hits result into the PR body so the negative finding is auditable.
- **Pre-publish API-stability constraint vs slash-command discoverability.** Users currently typing `/code-review` will see "skill not found" after merge. This is the intended clean break per AGENTS.md § API Stability AXIOM (no compat shims, no deprecation layer). **Mitigation:** none required; the smoke test in AC10 covers `/project-review` end-to-end so the new path is exercised before / after merge by the owner.
- **`ai-docs/learnings.md` boundary rule (AC11).** Boundary rule 2 in AGENTS.md prohibits writing a NEW learnings entry in the same turn as instruction-file edits (the exception for `/task` Steps 8–12 in-flow learning capture exists, but spec § Out of scope explicitly defers any rename-recording entry to a post-merge follow-up turn). **Mitigation:** subtask 6 verifies `git diff --stat ai-docs/learnings.md` reports zero changes before pushing. If the diff is non-empty, the entry is dropped before `git commit`.

## Test Design

Pure instruction-file rename — no Rust source touched, therefore no new `#[cfg(test)]` modules or integration tests. The "test plan" is the AC verification harness, not Rust unit tests.

- **AC1 (history preserved via `git mv`).** Verified by `git log --follow .claude/skills/project-review/SKILL.md | head -20` in subtask 6 — must show commits authored before this PR.
- **AC2, AC3, AC4, AC5 (per-file token grep).** Verified by `grep -n 'code-review' <file>` per touched file — expected: 0 hits in `SKILL.md`, `review-findings.md`, `self-review.md`.
- **AC6 (workspace grep gate).** Verified by the verbatim grep command quoted in spec § AC6 — expected: 0 lines.
- **AC7–AC9 (workspace gates).** Verified by `cargo fmt -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features`. Pure regression — no Rust diff exists, so these are sanity guards against `Cargo.lock` drift or an unrelated regression coincidentally landing in master between branch creation and push.
- **AC10 (PR body manual-verification section).** Authored in subtask 6 PR body; owner-executed post-merge.
- **AC11 (learnings.md unchanged).** Verified by `git diff --stat ai-docs/learnings.md` — expected: empty.
- **AC12 (cross-link resolves).** Verified by `realpath` from one rewritten link source (e.g. AGENTS.md Propagation Rule line 202's `.claude/skills/project-review/SKILL.md` reference) to the actual file — expected: path resolves to the post-rename file.
- **AC13, AC14, AC15 (historical narrative).** Verified by per-file `grep -n 'code-review' <file>` — expected: 0 hits in `.claude/settings.local.json`, INDEX.md narrative cells, `_inbox.md` line ~227, `ci-docs-workflow.md` line ~49. **AC13 caveat:** `.claude/settings.local.json` is gitignored (`.gitignore` line 3) — the grep is an **on-disk content check**, NOT a `git diff` check. The file will not appear in the PR diff, and `git status` will not flag it as modified after subtask 5's rewrite. The grep approach still works correctly because it reads the working-tree file directly.
- **AC16 (README sweep).** Verified by two grep variants noted under subtask 6; the zero-hits result is written into the PR body.

No fixtures or helpers are required beyond the standard `cargo` toolchain and POSIX `grep` / `wc` / `realpath` / `git`.
