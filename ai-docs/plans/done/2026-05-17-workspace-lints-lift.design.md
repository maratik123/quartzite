# Design: Lift per-crate doc-lint directives into `[workspace.lints.*]`

**Issue:** #460
**Date:** 2026-05-17 (amended 2026-05-18 — Subtask 1 surfaced test-target enforcement broadening; spec § Scope item 3 + AC20 added; design § Decomposition row 1 + § Risks + § Test Design Subtask 1 updated in place. Pre-check anchor, decomposition rationale, alternatives unchanged.)

## Approach

The spec is a placement-only refactor: 7 doc-lint directives currently duplicated across 15 `lib.rs` files lift into root `Cargo.toml`'s three `[workspace.lints.*]` tables (`rust` / `rustdoc` / `clippy`). Inheritance is already wired — every member crate's `Cargo.toml` carries `[lints] workspace = true` (live-verified across all 14 leaves + root). Workspace lints require Cargo 1.74+; the workspace pins `rust-version = "1.95"`, so the feature is unconditionally available.

Workspace-lint inheritance has **no per-target gating** — `[lints] workspace = true` opts every target in the crate into the workspace tables, including `tests/*.rs` integration test crates. Pre-lift `#![deny(missing_docs)]` lived inside `src/lib.rs` and thus only covered library targets; the lift broadens enforcement to test targets (intentional, NOT a severity change per spec § Out of scope's callout block). Live measurement during Subtask 1's first execution surfaced 17 integration test files lacking `//!` crate-level docs and producing `missing documentation for the crate` errors under `cargo test --workspace`. Spec § Scope item 3 + AC20 anchor the fix: each affected test file gets one descriptive `//!` line in the same Subtask 1 commit. This is a doc-coverage strict improvement; the chosen approach incrementally expands the project's documentation surface (rejected alternatives — per-target lint scoping via per-crate `[lints.rust]` blocks or `#![cfg_attr(test, allow(missing_docs))]` — would defeat the spec's centralization goal).

**Chosen plan** mirrors the spec's commit decomposition exactly:

1. **Add workspace lint tables + run the pre-check + add `//!` to integration test files + verify all gates green.** Tables go in root `Cargo.toml` between the existing `[workspace.lints.clippy]` and `[lints]` blocks. Pre-check (per AC6) runs *inside* this commit, before the per-crate strip, so the redundancy decision for the 4 pedantic-implied lints is anchored to live measurement against an unchanged source tree. **Ordering inside the commit:** (a) add the three workspace tables to root `Cargo.toml`; (b) run the AC6 pre-check (primary pedantic-suppression diff + cross-validation `jq` pipeline) — already executed in the WIP tree: only `undocumented_unsafe_blocks = "warn"` was kept, the 4 pedantic-implied candidates (`missing_errors_doc`, `missing_panics_doc`, `missing_safety_doc`, `doc_markdown`) were dropped; (c) drop the pedantic-implied entries per the pre-check result; (d) add a one-line `//! <description>` to every integration test file missing one (enumerated in spec § Scope item 3 + Subtask 1 row below); (e) run the 6 gates clean (`cargo build --workspace`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace`, `cargo fmt -- --check`, `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features`, `cargo build -p quartzite --no-default-features --features libm`); (f) commit. The commit message records the AC6 kept/dropped breakdown with the pre-check command output, and notes the test-file `//!` additions count.
2. **Strip the 7 directives from every `lib.rs`.** Edits are mechanical (delete the contiguous 7-line block; preserve surrounding `#![no_std]`, `#![cfg_attr(...)]`, `extern crate alloc;`, module-level `//!` docs). Two file-level wrinkles need per-file care:
   - `quartzite-renderer/src/lib.rs` currently lacks `#![deny(missing_docs)]` (live-grep confirmed). Post-lift it inherits the workspace deny; AC9 places any newly-surfaced renderer doc warnings in-scope to fix in *this commit*.
   - `quartzite-core/src/lib.rs` interleaves `#![doc = document_features::document_features!()]` and `#![cfg_attr(not(feature = "std"), no_std)]` with the lint block. The 7 lint lines must be excised while leaving the other directives undisturbed.
3. **Update instruction-file cross-references** per the Propagation Rule (AGENTS.md ↔ code-style.md pair, plus doc-convention.md). Six locations enumerated in the spec.

**Rejected alternatives:**

- *Single-commit lift.* Combines workspace-table addition with per-crate strip — loses the pre-check anchor point (you cannot run the pedantic-implied check against a tree where both halves have already changed) and loses the 3-commit narrative the spec prescribes (AC19). Rejected.
- *Shared prologue helper crate (e.g. `quartzite-prelude-lints`).* Adds a build-time dependency for what `[workspace.lints]` already solves natively. Rejected — workspace lints are the idiomatic Cargo-native mechanism (spec § Key decisions).
- *Lift `#![no_std]` / `#![cfg_attr(docsrs, feature(doc_cfg))]` as well.* These are crate-level attributes, not lints; they cannot live in `[workspace.lints.*]`. Out of scope per spec § Out of scope.
- *Defer instruction-file updates to a follow-up PR.* Would violate the Propagation Rule (`AGENTS.md` and `ai-docs/code-style.md` references would diverge from the code). Rejected.

**Pre-check anchor (AC6 mechanic).** Two complementary checks; both run inside commit 1, *after* adding the workspace tables but *before* stripping any per-crate directive. This timing is the only window where both `pedantic` and the four explicit `missing_*_doc` / `doc_markdown` warns coexist on the same tree, which is what makes the redundancy hypothesis testable. The 5 lint codes (`missing_errors_doc`, `missing_panics_doc`, `missing_safety_doc`, `doc_markdown`, `undocumented_unsafe_blocks`) form the filter; `undocumented_unsafe_blocks` is always kept (not in `clippy::pedantic`).

- **Primary (conclusive) check — pedantic-suppression diff.** Temporarily set `pedantic = { level = "allow", priority = -1 }` in the workspace clippy table; re-run `cargo clippy --workspace -- -D warnings`. Any of the 4 lints that *still* fire are independently enabled by the explicit warn entry → keep. Any that go quiet are pedantic-implied → drop. Revert the temporary `pedantic = "allow"` flip before commit. This is conclusive because it isolates the explicit-warn contribution from the pedantic-group contribution; the previous "they both push the same warning out" ambiguity disappears.
- **Cross-validation — `jq`-pipeline lint-code enumeration.** Run `cargo clippy --workspace --message-format=json -- -D warnings 2>&1 | jq -r 'select(.message?.code?.code?) | .message.code.code' | sort -u | grep -E '^clippy::(missing_errors_doc|missing_panics_doc|missing_safety_doc|doc_markdown|undocumented_unsafe_blocks)$'` against the *unchanged* (pedantic=warn) tree. This surfaces which of the 5 lints fire at all but cannot distinguish source — useful as a sanity-cross-check against the primary check's drop list. The two checks should agree on which of the 4 are pedantic-implied.

The four lints with disagreement (if any) should be kept (conservative). The commit-1 message records both checks' output and the kept/dropped breakdown as justification.

## Risks

- **Pedantic-implication drift.** A future clippy upgrade could remove one of the 4 lints from `pedantic`, silently downgrading enforcement. **Mitigation:** AC6 requires the kept/dropped breakdown plus the pre-check command output in commit 1's message. A future clippy bump can re-run the same pipeline to confirm coverage hasn't drifted.
- **Renderer missing-doc surface.** `quartzite-renderer` may have undocumented public items that the workspace-level `missing_docs = "deny"` will surface as new errors. **Mitigation:** AC9 puts these in-scope to fix in commit 2 of the same PR; expect to add `///` doc comments to currently-undocumented public items in `quartzite-renderer/src/**`. The fix is doc-only (no behaviour change), but extends the commit-2 diff beyond just `lib.rs` stripping. If the surface is large (>10 new items), the design-time estimate underestimates commit-2 scope — flag during implementation but stay in-scope (the spec explicitly authorises this).
- **Test-target enforcement broadening (Subtask 1 — surfaced live 2026-05-18).** Workspace lints have no per-target gating: `[lints] workspace = true` applies the workspace tables to library, binary, integration test, example, and bench targets alike. Pre-lift `#![deny(missing_docs)]` lived in `src/lib.rs` and thus only covered library targets; the workspace-level lift broadens `missing_docs = "deny"` to **every** target in every member crate that opts in. Live measurement during the first Subtask 1 execution surfaced 17 integration test files producing `missing documentation for the crate` errors under `cargo test --workspace`. **Mitigation:** Subtask 1 (per the updated decomposition row) adds a one-line `//!` crate-doc to each affected test file in the same commit as the workspace-table additions, so the commit's 6 gates pass green. AC20 verifies the addition. The same broadening rationale applies to the other lifted lints (`broken_intra_doc_links` from `[workspace.lints.rustdoc]`, `undocumented_unsafe_blocks` from `[workspace.lints.clippy]`) — in practice they do not fire on test code in the current tree (no `unsafe` blocks lacking `// SAFETY:` in `tests/*.rs`; no intra-doc links in test files). Subtask 1 verifies live by running the full 6-gate suite after the `//!` additions; if any incidental `undocumented_unsafe_blocks` or `broken_intra_doc_links` warning surfaces in test code, it is in-scope to fix in the same Subtask 1 commit (treat as a continuation of the workspace-table addition, not a new subtask). The same broadening applies to `examples/*.rs` if any are declared as workspace members — live grep at amendment time shows no `examples/*.rs` warrants attention (none surfaced under `cargo test --workspace` in the WIP execution); if a future example crate is added, the workspace deny will propagate to it on first compile.
- **Subtle non-lint directive deletion.** `quartzite-core/src/lib.rs` interleaves several non-lint `#![...]` attributes with the 7-line lint block (`#![doc = document_features::document_features!()]`, `#![cfg_attr(not(feature = "std"), no_std)]`, `#![cfg_attr(docsrs, feature(doc_cfg))]`). Bulk regex deletion could over-match. **Mitigation:** edit each file with targeted `Edit` operations on the exact 7-line (or 6-line, for renderer) lint block; verify with `git diff --stat` that the diff is roughly `-7 * N` lines (or `-6 + N` for renderer) plus any added doc comments for AC9.
- **Pre-check command brittleness.** The `jq` cross-validation depends on `cargo clippy --message-format=json` emitting `.message.code.code` for fired lints. If clippy's JSON shape changes between versions, the pipeline could silently report empty — a false-negative would hide a lint that ought to be kept. **Mitigation:** the primary pedantic-suppression diff (now ordered first per § Approach → Pre-check anchor) does NOT depend on the JSON shape — it only reads clippy's terminal exit / warning output. The two checks should agree on which lints are pedantic-implied; any disagreement defaults to *keep* (conservative).
- **Instruction-file size cap.** AGENTS.md is already under tight char-budget pressure (35 000 early warning, 40 000 hard cap per the AGENTS.md axiom). The Linter-posture / Documentation rewrites in Subtask 3 should be net-neutral or net-shorter (replacing two prose mentions with one workspace-level mention is shorter). **Mitigation:** Subtask 3 closes with a `wc -c` check; if any file crosses 35 000 the rewrite is over-budget and needs to be tightened before commit.
- **AC19 commit-count enforcement.** The 3-commit decomposition is a hard requirement (AC19). Squashing or splitting violates it. **Mitigation:** each subtask = exactly one commit; design-review verdict gates this before implementation starts.
- **Renderer-only new warnings causing AC10 test-count drift.** AC10 requires `cargo test --workspace` clean with net delta = 0. Adding doc comments cannot introduce or remove tests, but a stray new `//! ` module-level `///` example doctest could. **Mitigation:** when fixing AC9-surfaced renderer warnings, prefer plain `///` summaries over `# Examples` blocks (the convention permits this where the new items are not new public surface — these are existing public items getting docs, not new public items per the [`ai-docs/code-style.md` § Documentation](../code-style.md#documentation) `# Examples`-on-new-public-items rule). If a doctest is unavoidable, mark it `no_run` to avoid runtime cost without changing the test count.

## Test Design

This task is a placement-only configuration refactor with no production code behaviour change. There is no new unit test to write — the acceptance criteria themselves are the test plan, executed via the workspace gates that AGENTS.md already mandates. Per-subtask validation:

- **Subtask 1.** No production source code change; the only `.rs` edits are one-line `//!` crate-doc additions to integration test files (no `#[cfg(test)]` module touched, no test count drift, no behavioural impact). Validation is gate-execution: `cargo build --workspace`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace`, `cargo fmt -- --check`, `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features`, `cargo build -p quartzite --no-default-features --features libm`. Plus the two AC6 pre-checks in the order specified in § Approach → Pre-check anchor: (i) primary pedantic-suppression diff (temporarily flip `pedantic = "allow"`, re-run clippy, observe which of the 4 lints still fire vs go quiet, revert), and (ii) `jq`-pipeline cross-validation (`cargo clippy --workspace --message-format=json -- -D warnings 2>&1 | jq -r 'select(.message?.code?.code?) | .message.code.code' | sort -u | grep -E '^clippy::(missing_errors_doc|missing_panics_doc|missing_safety_doc|doc_markdown|undocumented_unsafe_blocks)$'`). Plus AC20 verification: enumerate every integration test file under `**/tests/*.rs` and workspace-root `tests/*.rs` and confirm each carries a `//!` line. A reliable one-liner is `for f in $(find . -path ./target -prune -o -type f -name '*.rs' -print | grep -E '/tests/[^/]+\.rs$'); do grep -q '^//!' "$f" || echo "MISSING: $f"; done` — output empty = PASS. Cross-check with `cargo test --workspace` and `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features` both passing under `[workspace.lints.rust] missing_docs = "deny"` in effect (any test file lacking `//!` would produce `missing documentation for the crate` and fail both gates).
- **Subtask 2.** No behavioural code change; only deletion of `#![...]` attribute lines (plus AC9-mandated `///` doc additions on previously-undocumented `quartzite-renderer` public items, if any). Validation:
  - All 6 build/clippy/test/fmt/doc/no-default gates from Subtask 1.
  - AC1: `rg '^#!\[deny\(missing_docs\)\]' --type rust` returns 0 hits.
  - AC2: `rg '^#!\[deny\(rustdoc::broken_intra_doc_links\)\]' --type rust` returns 0 hits.
  - AC3: `rg '^#!\[warn\(clippy::(missing_errors_doc|missing_panics_doc|missing_safety_doc|doc_markdown|undocumented_unsafe_blocks)\)\]' --type rust` returns 0 hits.
  - AC7: `rg -c '^\[lints\]$' --include='Cargo.toml' .` shows exactly 15 hits (14 leaves + root facade); each `Cargo.toml` retains `workspace = true` on the next line.
- **Subtask 3.** Pure markdown edits → no Rust compilation impact, but re-run the doc gate (cheap; ensures intra-doc-link-style code blocks in the markdown have not introduced compilation-time noise). Plus the AGENTS.md char-budget check: `wc -c AGENTS.md ai-docs/code-style.md ai-docs/doc-convention.md` must report each file below 40 000 chars (and ideally below 35 000 for AGENTS.md per the early-warning gate).

No new test fixtures, helpers, or `#[cfg(test)]` modules are introduced.
