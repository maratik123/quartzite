# Per-widget clip-rect

**Source:** issue #397
**Date:** 2026-05-27
**Tracked in:** #397

Plumb per-widget clip-rects through `quartzite_style_dispatch::dispatch_paint` so a `ScrollArea` (and future clipping containers) can confine its child subtree's painting to its own bounds. Today the dispatch helper drives `save` / `translate` / `restore` around each non-root child but never calls `Painter::clip_rect`, so content larger than its `ScrollArea` parent paints over the parent's neighbours.

The `Painter::clip_rect` primitive already exists end-to-end (`quartzite-paint-api`, the Vello backend in `quartzite-renderer`, recording / no-op painters in tests). What's missing is the dispatch-time **policy**: when, where, and on what rect to invoke it.

## Scope

1. Extend the `AsWidget` trait (emitted by the `#[derive(Extend)]` macro for the `WidgetBase` root in `quartzite-macros`) with a new default-`None` method `children_clip_rect(&self) -> Option<Rect>` (returns `None` for widgets that do not clip their children). `WidgetBase`'s own default and every non-`ScrollArea` built-in (`Button`, `Label`, `TextEdit`, `LineEdit`, `Container`) inherit the `None` default and require no code change.
2. Override `children_clip_rect` on `ScrollArea` so it returns `Some(content_rect)`, where `content_rect` is in `ScrollArea`'s local coordinate frame (origin `(0, 0)` at the `ScrollArea`'s top-left).
3. Add a `content_rect()` accessor on `ScrollArea` returning the inner area to which child painting is clipped (the full local-space rect in v1 — `Rect::new(Point::ZERO, self.geometry().size())`; insets for scrollbar chrome when `#315` lands).
4. Extend `quartzite_style_dispatch::dispatch_paint::visit` so, for each visible child, after `painter.save()` and **before** `painter.translate(child.geometry().origin())`, it calls `painter.clip_rect(rect)` when the **parent** widget's `children_clip_rect()` returns `Some(rect)`. The full per-visible-child sequence is `save() → clip_rect(parent_clip_rect) → translate(child_origin) → visit(child) → restore()`. The existing `save`/`restore` envelope around the child guarantees the clip is popped when the subtree completes (the renderer-side `clips` stack in `vello_painter.rs` already pops nested clip layers on `restore`).
5. The clip rect is in the **parent's local coordinate frame** (issued after the parent's translate is already in effect and before the child's `translate` runs against the painter — so the rect arguments live in the same coordinate frame the parent paints in).
6. Add a dispatch-crate unit test that extends the existing recording-painter shape (`RecordingPainter` in `quartzite-style-dispatch/src/dispatch.rs` tests) with a `ClipRect(Rect)` event variant and asserts: (a) `ClipRect` appears exactly once between `Save` and `Translate(content_origin)` (i.e. before the child's translate, after the parent's save) when the `ScrollArea` has a visible content child; (b) zero `ClipRect` events when `content_widget == None`; (c) the recorded clip rect equals `scroll_area.content_rect()` (full local-space rect, zero inset); (d) the AC5/AC8 save/restore-pairing invariants from `2026-05-13-renderer-style-dispatch.spec.md` still hold with the new `ClipRect` event interleaved.
7. Add a `quartzite-widgets` unit test asserting `ScrollArea::content_rect()` returns the expected `Rect` for representative `geometry()` values, and a unit test asserting `<NonClippingWidget>::children_clip_rect()` returns `None` (covering the default-`None` path on the trait).

## Out of scope

- Scroll-offset translation. `ScrollArea` has no scroll-offset field today; the source spec's `## Out of scope` defers scrolling and per-content-rect dispatch beyond a single `translate`. This spec is clip-only.
- Scrollbar track / thumb rendering. Tracked separately under #315. This spec ships before #315; when chrome lands, the `content_rect()` body changes to inset for the chrome — the trait surface and dispatch wiring stay put.
- Damage / dirty-rect tracking (deferred row #396 — unrelated; intersects with clip-rects only in a future repaint-optimization pass).
- Hit-testing clip-awareness (events that fall outside a `ScrollArea`'s clip rect should be ignored when input plumbing lands — deferred row #395).
- Painter-side clip-rect intersection semantics. The Vello backend already composes nested clip layers via its `clips` stack; this spec relies on that existing contract and adds no new `Painter` methods.
- Letting custom widgets (those whose `AsWidget` is hand-rolled rather than `#[derive(Extend)]`-generated) clip their children. Such widgets keep returning the default `None` from `children_clip_rect` and are unaffected; if a custom widget ever wants to clip, it can implement the trait method directly in its hand-rolled `impl AsWidget` block. v1 ships only the `ScrollArea` override (via the `#[clip_rect(method = "content_rect")]` field annotation on its `WidgetBase` field — see Q1).

## Deferred

- Per-widget *content-rect-aware* dispatch shape change — passing the parent's clip rect into the child's paint as a hint so the child can size to it (e.g. content auto-fitting to the viewport). The clip-only behaviour here is sufficient for v1; auto-fit is a layout concern, not a paint concern. | future layout work | new issue when layout plumbing grows.
- Generalising `content_rect()` to a richer "frame model" (separate accessors for inner-rect, border-rect, header-rect, etc.). Today's single `content_rect` is enough for clipping; richer decomposition is style-system work. | not blocking v1 | new issue when more than one widget needs per-region accessors.
- Hit-testing clip-rect awareness (clicks outside a `ScrollArea`'s clip rect should not reach its `content_widget`) | belongs with the hit-testing pass tracked under #395 | follow-up on that issue.

## Key decisions

| Question | Decision |
|---|---|
| Q1: Where does the clip policy live? | **Trait method.** New `AsWidget::children_clip_rect(&self) -> Option<Rect>` default-`None` emitted by the `#[derive(Extend)]` macro on `WidgetBase` (alongside the existing `widget_view` / `children` extra methods at root-only emission). `ScrollArea` annotates its `widget_base: WidgetBase` field with `#[clip_rect(method = "content_rect")]`; the `#[derive(Extend)]` macro emits the `fn children_clip_rect(&self) -> Option<Rect> { Some(self.content_rect()) }` override onto the existing macro-generated `impl AsWidget for ScrollArea` block. A hand-written second `impl AsWidget for ScrollArea` block is not possible (Rust E0119: coherence forbids two trait impls for the same type). Generalises to every future clipping container without touching `dispatch_paint`. (Round 1, user-confirmed; coherence fix per design review.) |
| Q2: What kind of rect does `ScrollArea` clip to in v1? | **`content_rect` accessor.** `ScrollArea` exposes `content_rect()` returning the inner area to which child painting is clipped. Today (no chrome) the body equates to "the full local-space rect"; when #315 lands, the body insets for chrome. Forward-compatible — the trait surface and dispatch wiring do not change. (Round 1, user-confirmed.) |
| Q3: Concrete shape of `ScrollArea::content_rect()` in v1 | **Zero inset.** `Rect::new(Point::ZERO, geometry().size())` — full local-space rect, no chrome inset (no chrome exists yet). Simplest body, no magic numbers, no style-system entanglement. Snapshot test asserts clipping at the outer edge. When `#315` lands, the body insets for the chrome — the trait surface and dispatch wiring stay put. (Round 3, user-confirmed.) |
| Q4: Coordinate frame of the returned `Rect` | **Parent's local coordinate frame** (origin `(0, 0)` at parent top-left — the same space `children_clip_rect()` returns the rect in). `clip_rect(rect)` is called AFTER `painter.save()` but BEFORE `painter.translate(child_origin)`. This means the dispatch sequence for each visible child is: `save() → clip_rect(parent_children_clip_rect) → translate(child_origin) → visit(child) → restore()`. The widget author returns a rect in their own coordinate space without needing to know any child's offset. |
| Q5: Where in the dispatch sequence is `clip_rect` called? | After `painter.save()`, **before** `painter.translate(child.geometry().origin())`. The full per-visible-child sequence is `save() → clip_rect(parent_clip_rect) → translate(child_origin) → visit(child) → restore()`. `painter.restore()` after the child subtree pops both the translate **and** the clip layer atomically — relies on the existing `clips` stack in `vello_painter.rs` (`save` pushes a per-frame `0` counter, every `clip_rect` increments it, `restore` pops that many `pop_layer` calls). |
| Q6: Visibility short-circuit interaction | Unchanged. The existing `WidgetState::Visible` check on the child still skips the whole `save`/`translate`/`clip_rect`/recurse/`restore` envelope when the child is hidden; no clip layer is pushed if the child is invisible. |
| Q7: Resolver-miss interaction | Unchanged. If `resolver.resolve(child_id)` returns `None`, no clip is pushed (the current resolver-miss path skips the entire `save`/`translate`/recurse/`restore` block). |
| Q8: No `Painter` API change | Zero new `Painter` methods. `clip_rect` is already there. |
| Q9: How does `dispatch_paint` consult the new trait method? | Through the **parent** widget reference resolved in `visit`. Pseudocode: ``let maybe_clip = widget.children_clip_rect();`` evaluated once per parent; threaded into the child loop so each child receives the same parent clip (modulo their own `translate`). No per-child trait dispatch. |

## Technical constraints

- The codegen change is in `quartzite-macros/src/extend/codegen.rs::emit_root_trait_and_impl` — the existing `if self_ident == "WidgetBase"` block that already emits `widget_view` and `children` grows a third extra trait method `children_clip_rect`, with a default body returning `None`. Following the existing pattern, the root-side `impl AsWidget for WidgetBase` block does **not** override it (default body suffices). `ScrollArea` opts in via a field-level `#[clip_rect(method = "content_rect")]` annotation on its `widget_base: WidgetBase` base field; the `#[derive(Extend)]` macro reads the annotation and emits `fn children_clip_rect(&self) -> Option<Rect> { Some(self.content_rect()) }` onto the existing macro-generated `impl AsWidget for ScrollArea` block. A hand-written second `impl AsWidget for ScrollArea` block is not possible — Rust E0119 (coherence) forbids two trait impls for the same type, and the macro already emits one. The `#[clip_rect(method = "<ident>")]` field-level-annotation approach is the chosen path: opt-in (silent default for every other widget), keeps the override declaration co-located with the widget definition, and adds one parse path + one codegen test in `quartzite-macros`.
- The dispatch change is in `quartzite-style-dispatch/src/dispatch.rs::visit`. The clip-rect call sits between `painter.save()` and `TranslateGuard::new(painter, origin)` — i.e. BEFORE the translate, so the rect lives in the parent's local coordinate frame (the parent's translate is already in effect, the child's translate has not yet run). Threaded via the existing `painter` parameter at the recursion site; the parent's `children_clip_rect()` is read once per parent before the child loop and applied to each child uniformly.
- The Vello backend's `clip_rect` does `scene.push_clip_layer` and increments the per-`save` `clips` counter; `restore` pops `clip_count` layers and the outer `xform`. The new code path relies on this contract being correct (`clip_rect_save_restore` and `clip_rect_increments_active_clip_count` tests already cover it).
- Painter mocks in the existing tests already implement `clip_rect` (recording / no-op stubs). The new dispatch test extends `RecordingPainter`'s `PaintEvent` enum with a `ClipRect(Rect)` variant — purely a test-only change.
- Doc gate (`RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features`) clean. The new trait method `children_clip_rect` carries a first-line `///` doc and an example (the `Extend` codegen already emits self-contained doctest preambles — the new method follows the same pattern). `ScrollArea::content_rect()` carries a `# Examples` block.
- Lint gate (`cargo clippy --workspace --all-targets -- -D warnings`) clean on changed crates.
- File size: `dispatch.rs` is well within the 200–400 line target; the new clip-rect threading adds a handful of lines.
- Magic-number policy (`AGENTS.md § Code Style` → *Magic numbers*): no magic numbers in v1 — `content_rect()` returns the zero-inset full local rect via `Rect::new(Point::ZERO, self.geometry().size())`. When `#315` lands and chrome inset is needed, the inset value goes into a module-level `pub const` rather than appearing inline.

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | `AsWidget::children_clip_rect(&self) -> Option<Rect>` exists on the `AsWidget` trait (emitted by the `Extend` macro at the `WidgetBase` root) and has a default body returning `None`. |
| AC2 | `WidgetBase`, `Button`, `Label`, `TextEdit`, `LineEdit`, `Container` (every non-`ScrollArea` built-in) return `None` from `children_clip_rect` (default-trait body inherited; no override added). A unit test asserts this for at least one representative built-in (e.g. `Button`). |
| AC3 | `ScrollArea` overrides `children_clip_rect` to return `Some(self.content_rect())`. A unit test asserts the return is `Some(Rect::new(Point::ZERO, scroll_area.geometry().size()))`. |
| AC4 | `ScrollArea::content_rect() -> Rect` exists and returns `Rect::new(Point::ZERO, self.geometry().size())` (full local-space rect, zero inset) in the `ScrollArea`'s local coordinate frame. A unit test asserts `content_rect()` matches this for representative `geometry()` values (including a zero-size geometry and a non-zero-size geometry). |
| AC5 | Given a tree `ScrollArea { content_widget: Some(Label) }` where both nodes are visible, `dispatch_paint` records the event sequence `[FillRect(area), Save, ClipRect(content_rect), Translate(label_origin), FillRect(label), Restore]` (i.e. `ClipRect` appears exactly once, AFTER `Save` and BEFORE `Translate(label_origin)`), with the clip rect equal to `scroll_area.content_rect()`. |
| AC6 | Given a tree `ScrollArea { content_widget: None }`, `dispatch_paint` records zero `ClipRect` events (no child to clip). |
| AC7 | Given a tree `ScrollArea { content_widget: Some(Label) }` where the `ScrollArea` is hidden, `dispatch_paint` records zero paints and zero `ClipRect` events (visibility short-circuit unchanged). |
| AC8 | Given a tree `ScrollArea { content_widget: Some(Label) }` where the `Label` is hidden, `dispatch_paint` records the `ScrollArea`'s paint, **zero** `ClipRect` events (no `save`/`translate`/`clip_rect` envelope when the child is invisible), and zero `Label` paint. |
| AC9 | A non-clipping container — e.g. `Container { Label, Button }` — records **zero** `ClipRect` events. Only `children_clip_rect`-returning-`Some` widgets emit clips. |
| AC10 | Save/restore pairing invariant from the original dispatch spec (AC5 of `2026-05-13-renderer-style-dispatch.spec.md`) still holds: every `Save` in the recording has a matching `Restore`. The new `ClipRect` event sits AFTER `Save` but BEFORE `Translate` (not between `Translate` and the child's paint), and never outside a `Save`/`Restore` pair. |
| AC11 | Adding a new clipping-container widget = overriding `AsWidget::children_clip_rect` on the new widget; `dispatch_paint` is unchanged. The design phase asserts this property via a fixture (e.g. a test-only `ClippingWidget`) that overrides `children_clip_rect` and is exercised by `dispatch_paint`. |
| AC12 | An end-to-end snapshot test using a `ScrollArea` whose `content_widget` extends beyond its `geometry()` shows the content visually clipped at `content_rect()`. The snapshot uses the existing `vello_painter` end-to-end path (not the mock painter). Location — see *Open questions*. |
| AC13 | `cargo build`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, and `RUSTDOCFLAGS="-D warnings -D missing-docs" cargo doc --no-deps --workspace --all-features` are all clean on the changed crates. |

## Open questions

- Snapshot-test location (AC12): the new clipping behaviour deserves a visual snapshot (not just a recording-painter trace) to catch end-to-end Vello clip-layer regressions. Whether that snapshot lives in `quartzite-style-dispatch/tests/` (with a new Vello-backend dev-dep) or in `quartzite-style/tests/snapshots.rs` (where the renderer-style integration tests already live) is a design-phase decision. The latter is cheaper but routes the clipping test through `DefaultStyle`, which means the test asserts the integrated behaviour, not the dispatch layer in isolation.
- Whether `TranslateGuard` should grow a sibling `ClipTranslateGuard` (or be extended in place) to encapsulate the `save` + `clip_rect` + `translate` + later-`restore` envelope. Sensible default = inline the `clip_rect` call between the parent's `save` and the existing `TranslateGuard` constructor (i.e. before the translate); design phase reconfirms.
- Doctest shape for the macro-generated `children_clip_rect` (the `Extend` codegen builds self-contained doctest preambles — the new method's preamble has to bring `Rect` and `Option` into scope; design phase nails down the exact body).
