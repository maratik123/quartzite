# Design: Fix `missing_const_for_fn` (promote 59 eligible fns to `const fn`, remove workspace allow)

**Issue:** #479
**Date:** 2026-05-19

## Approach

Promote all 59 clippy-flagged sites to `const fn` uniformly across `src/`, `tests/`, and `examples/`, then remove the workspace-level `missing_const_for_fn = "allow"` from root `Cargo.toml`. The lint is opt-in nursery and only fires on already-eligible functions, so promotion is mechanical: prepend `const` to the existing `fn` keyword (preserving visibility, generics, `#[inline]`, and other attributes). Per-item `#[allow(clippy::missing_const_for_fn, reason = "…")]` is held as a fallback for any site that — against expectation — fails one of the workspace gates after the bulk promotion; each such allow carries a written justification.

Decomposition follows **crate-cluster batches** rather than a single sweep, for two reasons. First, batching produces reviewable commit boundaries so the reviewer can spot-check disposition correctness per cluster instead of scanning 59 hunks at once. Second, intermediate clippy runs scoped per cluster (still under `missing_const_for_fn = "warn"` locally) surface any compile failure or per-item-allow requirement closer to its trigger, before the next cluster lands. The workspace-level `"allow"` line stays in place across subtasks 1–5; only subtask 6 flips it to removed and runs the full deny-warnings gate.

**Rejected alternatives:**

- **One single "promote everything" subtask.** Rejected: 59 hunks in one commit obscures per-cluster disposition signal and forces the reviewer to rebuild the survey table in their head. Splitting by crate cluster gives natural review chunks while keeping the PR scope (issue #479's "single PR") intact.
- **Per-crate subtask (one subtask per crate).** Rejected: 10 crates + workspace = 11 subtasks, well over the 7-subtask scope cap in `.claude/agents/design.md` § Rules. Crate clustering by hit-count and theme keeps it at 6 coding subtasks.
- **Per-item `#[allow]` as the default, promotion as the exception.** Rejected by the spec (round-1 decision): clippy already verified eligibility, so promotion is the correct default and `#[allow]` is the fallback only for unanticipated failures.
- **Removing the `"allow"` first and chasing the resulting `-D warnings` failures.** Rejected: same end state but optimises for compile-error-driven workflow rather than survey-driven; the survey table in the spec is already the authoritative work list, and flipping the allow last keeps each intermediate subtask buildable with `cargo clippy --workspace --all-targets -- -D warnings`.

**Macro round-trip note.** Of the 59 hits, 8 are inside `#[object_impl]` / `#[object_part]` / `#[slot]` / `#[invokable]` blocks (`quartzite-macros/tests/object_impl.rs` ×5, `examples/hello_object.rs` ×1, `examples/combined.rs` ×1, plus methods on test fixtures). The proc-macro parser stores them as `syn::ImplItem::Fn(fn_item)` and re-emits via `emit_impl_block`, which round-trips the full `Signature` including `constness`. Promotion is therefore syntactically safe through the macro. Any macro-emitted wrapper code that calls the promoted method at runtime continues to compile because `const fn`s are callable at runtime.

**Doc gate / `no_std + libm` reach.** `quartzite-paint-api` hits (`src/font.rs` ×3, `src/brush.rs` ×2) sit on the `--no-default-features --features libm` build path; promotion of plain getters here is safe (no float ops), but subtask 6 re-runs `cargo build -p quartzite --no-default-features --features libm` to confirm. Feature-gated modules (`serde`-gated `snapshot`, `style`, `widgets`) are covered by the `--all-features` doc gate in subtask 6.

## Handoff plan

`M = 6` (two groups, 3 + 3):

- **Group A:** subtasks 1–3 — independent per-crate promotions in `quartzite-core`, `quartzite-events`, and `quartzite-renderer` (the three largest hit-count crates).
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent /task resumes in Group B with fresh context.
- **Group B:** subtasks 4–6 — terminal group (3 subtasks; within the 1..=3 range). Covers the remaining promotions across the paint/style/widgets/runtime/geometry/macros-tests/examples clusters plus the workspace-allow removal and final gate matrix.

Per `.claude/skills/task/SKILL.md` Step 8, the entry into Group A also runs in its own `/context-reset` subagent (every-group handoff contract).

## Risks

- **Macro round-trip strips `const`.** Mitigation: subtask 5's scoped clippy gate (`cargo clippy --workspace --all-targets -- -D warnings -A clippy::missing_const_for_fn -W clippy::missing_const_for_fn`) re-emits *warnings* for any unresolved hit. If the 8 macro-wrapped sites still warn after promotion, fall back to per-item `#[allow(clippy::missing_const_for_fn, reason = "macro re-emits without `const` constness — promotion ineffective")]` on those sites and capture the finding as a learning entry per AGENTS.md *Corrections Log* — Boundary rule 2 in-flow exception.
- **`const fn` body contains a call to a non-`const` function under a cfg branch (`std`/`libm`/`target_os`).** Specifically `quartzite-geometry/src/lib.rs:27` `round_f32` has `cfg(feature = "std")` calling `f32::round` and `cfg(not(feature = "std"))` calling `libm::roundf`. Clippy fired against the default-features check (`f32::round` is `const` since 1.83), but `libm::roundf` is not `const`. Mitigation: subtask 6's `cargo build -p quartzite --no-default-features --features libm` gate catches this. Fallback if it fails: per-item `#[allow(clippy::missing_const_for_fn, reason = "libm::roundf is not const fn on the no_std path")]` at the call site, with a tracking comment.
- **Doc gate (`--all-features`) introduces feature-gated callers that require `const`-context invocation.** Mitigation: subtask 6 runs the full `RUSTDOCFLAGS` doc gate. If a doctest under `--all-features` breaks, the failure is local to the affected `///` example and either (a) the doctest is corrected, or (b) the promotion is rolled back to per-item `#[allow]`.
- **Per-crate `[lints]` block already opts into `workspace = true`.** Adding inline `#[allow(clippy::missing_const_for_fn, reason = "…")]` at item level remains permitted (Cargo rejects only the *workspace overlay* `[lints.clippy]` table when `workspace = true`); item-level `#[allow]` attributes are an entirely different mechanism and stay supported. No mitigation needed; flagged here so the design review doesn't flag it as a concern.
- **CI cache invalidation.** A `Cargo.toml` change (subtask 6) invalidates the workspace lint-config cache, causing a full re-check. Mitigation: none required — single-shot CI cost is acceptable for the audit completion.
- **PR-body summary drift.** Subtasks 1–5 each touch a different file set; the PR body's per-disposition count (promotion/per-item-allow breakdown) must reflect the final state, not the intermediate per-subtask state. Mitigation: AC8 in the spec requires per-disposition count in the PR body; the `/task` workflow's Step 11 (PR-body sync) compares the final commit's diff against AC8 before opening the PR.

## Test Design

No new tests are written. The promotion is mechanical and the existing test suite is the test plan:

- **Location:** Workspace-wide existing tests under each affected crate's `#[cfg(test)] mod tests` blocks and `tests/` integration test directories.
- **Entry point:** No specific entry point — every existing test exercises at least one callable code path. Promotion of `fn` → `const fn` is non-behavioural; `const fn`s are still callable at runtime with identical semantics.
- **Scenarios:**
  - **Happy path:** Each subtask's scoped `cargo test -p <crate>` run exercises every existing test in the affected crate, confirming the promoted fns remain callable at runtime with identical results.
  - **Error / edge cases:** None expected — `const fn` is strictly additive (compile-time callable + runtime callable). The risk is *compile failure*, not runtime divergence; compile failures surface in the scoped `cargo clippy` / `cargo build` runs.
  - **Cross-cfg coverage:** Subtask 6's final gate matrix exercises the default-features, `--all-features` doc gate, and `--no-default-features --features libm` paths. This is the only place where the `no_std + libm` build path for `quartzite-paint-api` is exercised, so any cross-feature promotion regression surfaces here.
- **Fixtures / helpers needed:** None. Existing fixtures (`quartzite-renderer/tests/support/mod.rs`, `quartzite-style/tests/snapshots.rs`'s `harness_or_skip`, `quartzite-core/tests/object_safety.rs`'s `_assert_object_safe_*`) continue to work unchanged after their helper fns become `const fn`.

If subtask 5 or 6 surfaces a site that cannot be promoted (macro round-trip, `libm::roundf`, or an unforeseen `--all-features` doctest failure), the disposition becomes per-item `#[allow(clippy::missing_const_for_fn, reason = "…")]` and no new test is added — the existing test suite continues to cover the unchanged runtime behaviour.
