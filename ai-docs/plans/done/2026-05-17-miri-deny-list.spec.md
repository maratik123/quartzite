# Miri deny-list inversion (workspace-wide + per-test opt-out)

**Source:** issue #436
**Date:** 2026-05-17
**Tracked in:** #436

## Scope

1. **Invert `.github/workflows/miri.yml`** from an opt-in `-p`/`--test` allow-list (the v1 / v2 shape from #422 / #431) to a deny-list shape: Miri runs across the whole workspace by default, and individual tests / files / crates opt OUT at the test source (or — for irreducible whole-crate cases — at the workflow level with a documented `# Why excluded:` reason).
2. **Default opt-out shape: per-test `#[cfg_attr(miri, ignore = "<reason>")]`.** The test stays in the Miri test harness's discovery list, surfaces in the harness's `ignored` count, and the reason string is visible in the run summary. Reason strings are honest and one of the documented categories (interpreter budget / FFI / subprocess / GPU init / isolation-violating syscall / proc-macro host / other-named).
3. **Fallback opt-out shape: per-file `#![cfg(not(miri))]`.** Used only when the entire integration test file depends on something Miri cannot reach (whole-file FFI, subprocess shell-out, GPU init), AND a top-of-file comment block documents why per-test was not sufficient. Two existing files already follow this shape and stay as-is:
   - `quartzite-widgets/tests/no_style_dep.rs:18` — shells out to `cargo tree` (subprocess + isolation).
   - `quartzite-runtime/tests/timer.rs:20` — wall-clock-bounded timer assertions exceed Miri's interpreter overhead.
4. **Crate-level workflow exclusions: ONLY for irreducible cases.** Two crates remain excluded at the workflow level via `--exclude` (or its equivalent), each justified by a `# Why excluded: <reason>` comment immediately above the exclusion clause in `miri.yml`:
   - **`quartzite-renderer`** — prod-deps `winit` / `wgpu` / `vello` reach the lib, no `--lib`/`--test` filter can side-step that.
   - **`quartzite-macros`** — proc-macro crate; Miri cannot run a proc-macro host, but its integration tests CAN be Miri'd. The exclusion is therefore **scoped to the proc-macro lib target**, NOT the integration tests — see Scope §6. (Final shape — `--exclude quartzite-macros` then re-include integration tests, vs `--workspace` + per-test attrs on the proc-macro lib — is a design-phase call.)
5. **The two transitive renderer dev-dep crates `quartzite-widgets` and `quartzite-style` are NOT excluded at the workflow level under v3.** Their renderer dev-dep is only pulled into the build graph for test targets that reference the renderer (currently: `tests/snapshots.rs` in each, and `tests/support_internals.rs` in widgets). Each such test target carries either per-test `#[cfg_attr(miri, ignore = "<reason>")]` on every `#[test]` fn, OR per-file `#![cfg(not(miri))]` if the whole file is GPU-coupled. The current allow-list invocations (`--lib -p quartzite-widgets`, `--lib -p quartzite-style`, `--test no_style_dep`, `--test re_exports`, `--test third_party_paint`) are subsumed by the workspace-wide invocation once the renderer-touching test files carry the right opt-out attribute.
6. **First-Miri-run tagging strategy: pre-emptive exhaustive sweep in v1.** Before flipping the workflow command, the design + implementation phases enumerate every test the new `--workspace` invocation would flag (compile failure, interpreter budget, FFI, isolation violation, etc.) and tag each at the source with `#[cfg_attr(miri, ignore = "<reason>")]` or `#![cfg(not(miri))]`. The first post-merge master Miri run is expected green (modulo `continue-on-error: true`) — NOT used as a tagging-discovery probe. Rationale:
   - Discovery via failed master runs has already failed the project once (#431 found ~160 missing tests after a manual audit; the issue body cites this).
   - `continue-on-error: true` masks new findings in the CI summary — using master as the probe defeats the purpose of the v3 maintenance contract.
   - The implementation phase has access to the same toolchain locally; the audit recipe is mechanical.
   - See Scope §7 for the audit recipe.
7. **Audit recipe (binding for the design phase).** The design agent records, and the implementation step executes:
   - **Static enumeration.** For every workspace crate not in the workflow-level exclusion list, list every `#[test]` fn (lib + integration tests + doctests where applicable) via `rg -n '^\s*(#\[(?:tokio::)?test(?:\(.*\))?\]|#\[rstest(\(.*\))?\])' --type rust <crate>/src/ <crate>/tests/`.
   - **Per-test triage.** For each fn, classify into one of:
     (a) Miri-clean — leave untouched.
     (b) Interpreter budget / wall-clock bounded / stress / long-loop — tag `#[cfg_attr(miri, ignore = "<reason>")]` with reason starting `"interpreter budget — "`.
     (c) FFI / GPU / subprocess / OS-isolation-violating — promote to per-file `#![cfg(not(miri))]` if the whole file is in that class; otherwise per-test `cfg_attr` with reason starting one of `"FFI — "`, `"GPU init — "`, `"subprocess — "`, `"isolation — "`.
     (d) Proc-macro host — only applicable if `quartzite-macros` lib stays in-workspace; per-test if the lib has any `#[test]` fns at all (it currently does not).
   - **Local dry-run.** Before commit, run `cargo +nightly-2026-05-01 miri test --workspace --exclude quartzite-renderer [--exclude quartzite-macros]` locally and confirm exit 0. The dry-run command (and any per-crate / per-test escape valve invoked) is recorded in the PR body so reviewers can reproduce.
8. **`MIRIFLAGS` set is unchanged from v2.** The cumulative `-Zmiri-tree-borrows -Zmiri-ignore-leaks -Zmiri-disable-isolation` env applies to the workspace-wide invocation. No new flag added.
9. **`continue-on-error: true` posture is preserved verbatim.** The flip to `false` remains the separately-tracked deferred follow-up to #422 — not advanced by this spec.
10. **`actionlint .github/workflows/miri.yml` exit 0** before `git add` per AGENTS.md *Build & Test* AXIOM. Master-only-comment AXIOM continues to apply; the existing `# Why master-only:` header block is preserved verbatim.
11. **Documentation home: new file `ai-docs/miri-policy.md`.** Referenced from `AGENTS.md § Build & Test` as a single-line row (mirroring how `ai-docs/dependency-versions.md` is referenced from `AGENTS.md § Dependency Versions`). Two-row entry: one row for the per-test default + reason-string convention, one row for the per-file fallback + the workflow-level exclusion list. The miri-policy file body documents the audit recipe (Scope §7) so future contributors don't re-discover it. **AGENTS.md MUST NOT absorb the prose body** — AGENTS.md is currently 33,457 chars (~1,500 chars under the 35,000 early-warning band) and absorbing the policy body would breach the AXIOM.
12. **`ai-docs/plans/INDEX.md`** gains an active-plan row per `/task` Step 4 convention; standard Step 12 done-move applies. No other INDEX movement.

## Out of scope

- **Flipping `continue-on-error: true` → `false`.** Separately-tracked deferred follow-up to #422; this spec does not advance that flip.
- **Adding or removing `MIRIFLAGS`.** v3 inherits the cumulative v2 flag set. If the workspace-wide sweep surfaces a new failure class, response follows the AC8 envelope of the v1 / v2 specs (cfg_attr / cfg / MIRIFLAGS / follow-up issue) but is recorded in a follow-up PR — not absorbed into this spec.
- **Switching Tree Borrows → Stacked Borrows.** Out of scope; TB rationale lives in #422 spec.
- **Running Miri per-PR.** Master-only-comment AXIOM in `miri.yml` still applies (10–30× latency cost vs `cargo test`).
- **Cross-target Miri** (Windows / macOS / big-endian / 32-bit). Already deferred per #424.
- **Doctest Miri coverage.** `cargo miri test` does not Miri-execute doctests by default; v3 does NOT change that. Doctests stay covered by the standard `cargo test --workspace --doc` gate.
- **Bench / example Miri coverage.** Benches (`harness = false` criterion binaries) and examples are not `#[test]` targets; Miri does not run them and v3 does not change that.
- **`quartzite-renderer` test re-inclusion.** Permanently excluded at workflow level under v3, same as v1 / v2. The whole rendering surface is FFI by construction.
- **Auto-generated `[workspace.metadata.miri]` or `cargo-miri` config-file approach.** v3 uses CLI flags only; config-file forms are not introduced.
- **Renaming or moving the existing `#![cfg(not(miri))]` opt-outs** in `quartzite-widgets/tests/no_style_dep.rs` and `quartzite-runtime/tests/timer.rs`. They stay as-is and become the documented fallback recipe.

- **AGENTS.md `## Build & Test` AXIOM extension** to name Miri as a peer of `cargo build` / `cargo test` / `cargo clippy --workspace -- -D warnings` | not advanced by this spec because AGENTS.md is already in the 33k–35k band and v3 cannot afford the extra body | **no — recorded here so a future post-extraction pass can revisit**.

## Technical constraints

- **AGENTS.md AXIOM — `actionlint` MUST pass before `git add`** on the modified `.github/workflows/miri.yml`. (Build & Test § AXIOM.) Same gate as v1 / v2.
- **AGENTS.md AXIOM — master-only workflow guard.** The pre-existing `# Why master-only:` comment block in `miri.yml` is preserved verbatim; v3 does not weaken or extend its scope claim. Miri stays master-only.
- **AGENTS.md AXIOM — instruction-file 35,000-char early warning.** AGENTS.md is at 33,457 chars (`wc -c` 2026-05-17). The Miri policy body MUST live in a new `ai-docs/miri-policy.md` referenced from AGENTS.md, not absorbed inline. Mirrors the existing `ai-docs/dependency-versions.md` pattern.
- **AGENTS.md § Dependency Versions** — no new action-version pins introduced by v3. The workflow's `actions/checkout@v6`, `actions-rust-lang/setup-rust-toolchain@v1`, and the nightly-pin `nightly-2026-05-01` are unchanged. If the design agent decides to bump the nightly pin (e.g., to pick up a Miri feature), the live-registry-lookup rule applies per the AXIOM.
- **Audit recipe — static-enumeration regex (Scope §7).** The default form is `rg -n '^\s*(#\[(?:tokio::)?test(?:\(.*\))?\]|#\[rstest(\(.*\))?\])' --type rust <crate>/src/ <crate>/tests/`. Design agent may tighten the regex if a workspace crate uses a non-standard `#[test]`-like attribute; whatever form is picked, the design doc records the exact regex used so the implementation step (and any future audit) is reproducible.
- **Reason-string category prefix list is closed under v3.** Six prefixes — adding a seventh requires editing `ai-docs/miri-policy.md`. The implementation step does not invent new prefixes silently.
- **`quartzite-macros` is `proc-macro = true`.** Miri cannot run the proc-macro lib (the host invokes it native at expansion time); however, each `tests/*.rs` integration test is its own ordinary test binary that Miri CAN interpret if its `use` declarations don't pull the renderer. The existing v2 allow-list (`extend`, `meta_enum`, `object`, `object_impl`) is the renderer-free subset; `via_facade.rs` stays excluded under v3 either via `--exclude quartzite-macros` + a sibling re-include step OR (if the design agent picks the `--workspace` form) via `#![cfg(not(miri))]` at the top of `via_facade.rs`.
- **`quartzite-renderer` lib has prod-deps on `winit`/`wgpu`/`vello`.** `cargo miri test --workspace` would attempt to compile and Miri-interpret the renderer crate; Miri cannot handle these crates. Therefore `--exclude quartzite-renderer` (or its equivalent — design picks) is structurally unavoidable at the workflow level. This is exactly the issue body's bullet 4 "(a) keep crate-level exclusion in `miri.yml` for irreducible FFI/proc-macro reasons (rare)" carve-out.
- **`quartzite-widgets` / `quartzite-style` Cargo.toml** both have `[dependencies]` empty of renderer and `[dev-dependencies]: quartzite-renderer = { path = ... }` — confirmed by the v2 design. Under v3, the workspace-wide invocation compiles their lib + every integration test binary; renderer-touching test files MUST carry per-test `cfg_attr` or per-file `cfg(not(miri))` because the dev-dep IS pulled into the build graph of those test target binaries.
- **Tagging budget — initial sweep.** The audit recipe (Scope §7) is a one-time bulk operation. The design phase records the expected file-touch count (an honest order-of-magnitude estimate, not a hard cap) so the implementation step's progress is grep-able. The v2 widening surfaced ~160 tests; v3 may surface more or fewer once `--workspace` exposes the previously-excluded surfaces. The implementation step's commit message names the actual count.
- **The two existing `#![cfg(not(miri))]` files** are already-correct exemplars under v3. They are NOT re-tagged at the per-test level (per-file is the right shape for them per Key Decisions § *Fallback opt-out shape*). Their top-of-file comment blocks are NOT rewritten unless the design phase finds the comment fails the v3 recipe (≥ 3 lines documenting why per-test wasn't sufficient + category + alternative coverage).
- **The widgets snapshot harness** (`quartzite-widgets/tests/snapshots.rs`, `tests/support_internals.rs`) and **style snapshot harness** (`quartzite-style/tests/snapshots.rs`) all `use support::*` from a `support/mod.rs` that reaches the renderer dev-dep. Per-file `#![cfg(not(miri))]` is the right shape for these three files; per-test would force every test to carry the same attribute and still leave the `mod support;` import to fail Miri compilation. Design phase records this as a worked example of "when per-file is the right call".

## Open questions

- **Macros-crate inclusion mechanic** — two equally-valid shapes, design picks:
  (a) `--exclude quartzite-macros` at the workspace step + a sibling `cargo miri test -p quartzite-macros --test extend --test meta_enum --test object --test object_impl` step (mirrors the v2 shape but is now the only `--test` allow-list survivor).
  (b) Keep the macros crate in `--workspace` (Miri compiles the integration tests but skips the proc-macro lib because proc-macro libs aren't ordinary Miri targets — design phase verifies this empirically via local dry-run); `via_facade.rs` carries `#![cfg(not(miri))]` at the file head.
  Either form satisfies AC1 + AC2. Picking (b) reduces workflow surface to a single cargo invocation; picking (a) keeps the per-test allow-list visible at the workflow level for the one remaining case.
- **`cargo miri test --workspace` empirical behaviour on the proc-macro crate.** Whether Cargo's resolver handles a proc-macro lib silently under `--workspace` or whether Miri errors on it is something the local dry-run (AC8) settles. Design phase records the observed behaviour before the implementation step commits the final workflow shape.
- **`scripts/check-miri-tags.sh`** — an automated audit script that intersects `rg '#\[test\]'` against Miri's actual reported run-list. Out of scope for v3 per Deferred §3; recorded here so it does not need re-discovery. Probable v4 candidate once a stabilisation-window's worth of Miri runs have informed the false-positive rate.
- **Doctest Miri coverage** — `cargo miri test --workspace` does not Miri-interpret doctests by default. Whether to add `--doc` (cost: doctests would also need triage + tagging if they use Miri-hostile patterns) is out of scope for v3; the existing `cargo test --workspace --doc` gate continues to cover them under native execution.
- **AGENTS.md § Build & Test AXIOM extension** — adding a third AXIOM naming Miri as a peer of `cargo build` / `cargo test` / `cargo clippy --workspace -- -D warnings` is appealing but cannot happen in this spec because AGENTS.md is at 33,457 chars (~1,500 under the 35k early-warning band). Deferred per Deferred §4; resurface after a future AGENTS.md extraction pass restores headroom.
