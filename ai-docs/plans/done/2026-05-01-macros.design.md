# Design: quartzite-macros — Proc-Macro Crate

**Issue:** 2026-05-01-macros.spec.md
**Date:** 2026-05-01

## Approach

### Summary

Implement a standalone `proc-macro = true` crate (`quartzite-macros`) with four public items:

- `#[derive(Extend)]` — hierarchy composition via field attributes `#[root]`, `#[base]`, `#[mixin]`
- `#[derive(Object)]` — property + signal metadata from `#[prop(...)]` / `#[signal]` field attributes
- `#[object_impl]` — attribute macro on an `impl` block; assembles final `MetaObject` and `impl Object`
- `#[derive(MetaEnum)]` — enum reflection metadata

All macros work on `TokenStream` (syntax only); no type resolution is performed. All emitted code
references `::quartzite_core::` absolute paths.

### Crate structure

```
quartzite-macros/
  Cargo.toml
  src/
    lib.rs              # proc-macro entry points only; delegates to submodules
    extend/
      mod.rs            # parse + codegen for Extend derive
      parse.rs          # ExtendInput: DeriveInput → validated IR
      codegen.rs        # emit TokenStream from IR
    object/
      mod.rs            # parse + codegen for Object derive
      parse.rs          # ObjectInput IR
      codegen.rs
    object_impl/
      mod.rs            # parse + codegen for object_impl attribute
      parse.rs          # ObjectImplInput IR
      codegen.rs
    meta_enum/
      mod.rs            # parse + codegen for MetaEnum derive
      parse.rs
      codegen.rs
    util.rs             # shared helpers: span errors, ident manipulation
```

Each submodule exports one function `expand(input: DeriveInput) -> TokenStream` (or equivalent)
called from `lib.rs`. This keeps unit-testing of IR parsing and codegen straightforward without a
full proc-macro harness.

### Dependency choices

| Dep | Version constraint | Reason |
|---|---|---|
| `syn` | `2`, features `["full", "extra-traits"]` | full AST; `extra-traits` for `Eq` on AST nodes in tests |
| `quote` | `1` | quasiquote |

| `heck` | `0.5` | snake_case conversion for accessor names; string-only, no runtime cost in proc-macro context; widely used in the ecosystem alongside `syn`/`quote` toolchains — **accepted** |

Dev-dependencies: `pretty_assertions` for readable test diffs, `trybuild` for compile-error
snapshot tests — **accepted**.

### `Base` suffix stripping decision

**Decision: strip `Base` suffix when it exists.**

Rationale: `WidgetBase` is the struct name because it holds widget data, but the capability trait
is `AsWidget`. Stripping is done purely on identifier text;
the rule is: if the type name ends with `Base` (case-sensitive), strip it before prepending `As`.
Otherwise prepend `As` directly.

Examples:
- `WidgetBase` → trait `AsWidget`
- `ObjectBase` → trait `AsObject`
- `Button` → trait `AsButton`
- `MyDatabase` → trait `AsMyDatabase` (ends in `e`, not `Base`)
- `Base` alone → `compile_error!` (degenerate; produces trait name `"As"`)

This convention is documented in a `/// # Naming convention` doc comment in `util.rs`.

### Accessor method naming

The accessor method name in each `As{X}` trait is the **snake_case of the original struct type
name** (before any `Base` stripping). This is consistent with how `quartzite-core` defines its
own traits (e.g. `AsObject` has `fn object_base(&self) -> &ObjectBase`).

Examples:
- `struct ObjectBase` → trait `AsObject` → accessor `fn object_base(&self) -> &ObjectBase`
- `struct WidgetBase` → trait `AsWidget` → accessor `fn widget_base(&self) -> &WidgetBase`
- `struct Button` → trait `AsButton` → accessor `fn button(&self) -> &Button`
- `struct Foo` → trait `AsFoo` → accessor `fn foo(&self) -> &Foo`

Mutable accessor: each trait also generates `fn {accessor}_mut(&mut self) -> &mut {OrigType}`.

Helper in `util.rs`: `fn accessor_name(type_ident: &Ident) -> Ident` — converts the original
type ident to snake_case (using `heck::ToSnakeCase`). The `trait_name` function (derived from the
stripped ident) and `accessor_name` (derived from the original ident) are two separate functions
— the implementation must not conflate them.

**Unambiguous rule for AC1:** `struct Foo` → trait `AsFoo` → accessor `fn foo(&self) -> &Foo`.
The accessor is `snake_case(original_ident)`, so `Foo` (already one word, no uppercase transition)
→ `foo`. Not `foo_base`, not the stripped name — the original ident.

### `#[derive(Extend)]` design

**IR (`ExtendInput`):**

```rust
struct ExtendInput {
    vis: Visibility,
    ident: Ident,
    generics: Generics,            // kept for future; generic structs are out of scope now
    is_root: bool,                 // #[root] present on the struct
    base_field: Option<BaseField>, // exactly one #[base] field
    mixin_fields: Vec<MixinField>, // zero or more #[mixin] fields
    other_items: Vec<Field>,       // remaining fields, attrs cleaned
}

struct BaseField { ident: Ident, ty_ident: Ident, ty: Type }
struct MixinField { ident: Ident, ty_ident: Ident, ty: Type }
```

Both `ty_ident` (the plain type name, e.g. `WidgetBase`) and `ty` (the full `Type` for codegen)
are stored to avoid re-parsing the type at codegen time.

**Parsing rules (validated in `parse.rs`):**
1. Must be a named-field struct; tuple struct or enum → `compile_error!`.
2. Generic type parameters or lifetime parameters → `compile_error!("generic structs not yet supported by #[derive(Extend)]")`.
3. Count `#[base]` fields; if ≥ 2 → `compile_error!("at most one #[base] field allowed")`.
4. If `is_root == false && base_field.is_none() && mixin_fields.is_empty()` → `compile_error!("#[derive(Extend)] requires #[root], at least one #[base], or at least one #[mixin] field")`.
5. Strip helper attributes (`#[root]`, `#[base]`, `#[mixin]`) from the output struct definition to avoid "unknown attribute" errors downstream. The derive macro re-emits the struct verbatim with those attributes removed.

**Codegen decision table:**

| Condition | Generated code |
|---|---|
| `is_root && base_field.is_none()` | Trait `As{Self}` (no supertrait) with `fn {acc}(&self) -> &{Self}` + `fn {acc}_mut(&mut self) -> &mut {Self}`. `impl As{Self} for {Self}` returning `self` / `self`. |
| `is_root && base_field.is_some()` | See **New hierarchy level** below. |
| `!is_root && base_field.is_some()` | `impl As{Parent} for {Self}` delegating to `self.base_field` (no new trait). Mixin leaf impls. |
| `!is_root && base_field.is_none() && !mixin_fields.is_empty()` | Mixin leaf impls only. |

Where `{Parent}` means the trait derived from the `#[base]` field's type name via `as_trait_name`.

**New hierarchy level (`is_root && base_field.is_some`):**

When `#[derive(Extend)] #[root]` processes a struct that itself extends a parent hierarchy level
(i.e. has a `#[base]` field), the macro must generate all three of:

1. The new trait with supertrait:
   ```rust
   pub trait As{Self}: As{Parent} {
       fn {acc}(&self) -> &{Self};
       fn {acc}_mut(&mut self) -> &mut {Self};
   }
   ```

2. Self-referential impl:
   ```rust
   impl As{Self} for {Self} {
       fn {acc}(&self) -> &{Self} { self }
       fn {acc}_mut(&mut self) -> &mut {Self} { self }
   }
   ```

3. **Blanket impl for transitive ancestor satisfaction:**
   ```rust
   impl<T: As{Self}> As{Parent} for T {
       fn {parent_acc}(&self) -> &{ParentType} {
           self.{acc}().{parent_acc}()
       }
       fn {parent_acc}_mut(&mut self) -> &mut {ParentType} {
           self.{acc}_mut().{parent_acc}_mut()
       }
       fn as_any(&self) -> &dyn ::core::any::Any { self }
       fn as_any_mut(&mut self) -> &mut dyn ::core::any::Any { self }
   }
   ```

   `T` is the concrete type, so returning `self` is correct — `self` refers to the `T` instance,
   which implements `Any`. Delegating through an accessor chain (e.g.,
   `self.{acc}().as_any()`) would cause infinite recursion for root types where the accessor
   returns `self` itself. The direct `self` form is the standard Rust pattern for `Any` impls.

Item 3 is the **blanket impl** — it is generated by the macro alongside the trait definition, in
the same expansion. It allows any future concrete type (e.g. `Button`) that implements `As{Self}`
to automatically satisfy `As{Parent}` without the concrete-type macro needing to emit a second
delegation impl.

**Why the blanket impl cannot live in `quartzite-core`:** `As{Self}` (e.g. `AsWidget`) is itself
generated by the macro. `quartzite-core` does not know about user-defined hierarchy levels and
cannot provide a blanket impl that references a trait it does not define. Therefore the blanket
impl must be co-located with the trait definition — generated in the same macro expansion that
introduces `As{Self}`.

**Terminal root (no `#[base]` field):** A `#[root]` struct with no `#[base]` field (e.g.
`ObjectBase`) is the terminus of a hierarchy chain. It generates no blanket impl — it is the
deepest level. Its self-ref impl directly satisfies any supertrait demands imposed by child levels.

**Example — `WidgetBase` processed by `#[derive(Extend)] #[root]` (has `#[base] object: ObjectBase`):**

```rust
// 1. Trait (supertrait = AsObject, which quartzite-core defines)
pub trait AsWidget: ::quartzite_core::AsObject {
    fn widget_base(&self) -> &WidgetBase;
    fn widget_base_mut(&mut self) -> &mut WidgetBase;
}

// 2. Self-ref impl
impl AsWidget for WidgetBase {
    fn widget_base(&self) -> &WidgetBase { self }
    fn widget_base_mut(&mut self) -> &mut WidgetBase { self }
}

// 3. Blanket impl — generated here, not in quartzite-core
impl<T: AsWidget> ::quartzite_core::AsObject for T {
    fn object_base(&self) -> &::quartzite_core::ObjectBase {
        self.widget_base().object_base()
    }
    fn object_base_mut(&mut self) -> &mut ::quartzite_core::ObjectBase {
        self.widget_base_mut().object_base_mut()
    }
    fn as_any(&self) -> &dyn ::core::any::Any { self }
    fn as_any_mut(&mut self) -> &mut dyn ::core::any::Any { self }
}
```

Now `Button` only needs `impl AsWidget for Button` — it inherits `AsObject` via the blanket impl.

**Mixin impls:** For each `#[mixin] field: MixinType`, emit only:
```rust
impl As{MixinType} for {Self} {
    fn {mixin_acc}(&self) -> &{MixinType} { &self.field }
    fn {mixin_acc}_mut(&mut self) -> &mut {MixinType} { &mut self.field }
}
```
No supertrait constraints on mixin impls (prevents diamond-problem). The mixin type does not
participate in the object hierarchy chain.

**Re-emitting the struct:** The derive macro re-emits the original struct definition with `#[root]`,
`#[base]`, `#[mixin]` stripped from struct-level attrs and from each field's attrs. All other attrs
(including `#[doc]`, `#[cfg]`, `#[allow]`, etc.) are preserved verbatim.

### `#[derive(Object)]` design

**IR (`ObjectInput`):**

```rust
struct ObjectInput {
    ident: Ident,
    props: Vec<PropField>,
    signals: Vec<SignalField>,
}

struct PropField {
    ident: Ident,
    ty: Type,
    notify: Option<Ident>,   // signal name for notify
    read_only: bool,
    stored: bool,            // default true
    designable: bool,        // default true
    user: bool,
    constant: bool,
}

struct SignalField {
    ident: Ident,
    args_ty: Type,           // the Args in Signal<Args>
}
```

**Generated items (in a hidden `mod __quartzite_{TypeName}` module):**

- `pub static __PROPS__{TypeName}: &'static [::quartzite_core::PropertyMeta]` — array literal built from `PropField`s.
- `pub static __SIGNALS__{TypeName}: &'static [::quartzite_core::SignalMeta]` — array literal built from `SignalField`s.
- `pub fn __read_property_{TypeName}(this: &{TypeName}, name: &str) -> ::core::option::Option<::quartzite_core::Value>` — match on name, call `::quartzite_core::IntoValue::into_value(this.field.clone())` (or equivalent conversion).
- `pub fn __write_property_{TypeName}(this: &mut {TypeName}, name: &str, val: ::quartzite_core::Value) -> bool` — for writable props: convert + assign + emit notify signal if `notify` is set; for `read_only` props: return `false`; for `constant` props: return `false`.
- `pub fn __connect_signal_dynamic_{TypeName}(this: &mut {TypeName}, name: &str, cb: ::std::boxed::Box<dyn ::core::ops::Fn(&[::quartzite_core::Value])>) -> ::core::option::Option<::quartzite_core::ConnectionId>` — match on signal name; for each `#[signal] field_name: Signal<Args>` field, generate a typed wrapper closure that adapts the erased `Box<dyn Fn(&[Value])>` into the `Fn(&Args)` expected by `Signal::connect`:
  ```rust
  match signal_name {
      "field_name" => Some(this.field_name.connect(move |args: &Args| {
          cb(&[ /* convert each Args element to Value */ ])
      })),
      _ => None,
  }
  ```
  The macro knows `Args` from parsing the `Signal<Args>` field type; it generates one arm per `#[signal]` field.

**Why a hidden module:** avoids polluting the user's namespace with generated names; the
`#[object_impl]` macro references these fns by absolute path within the module.

**`#[signal]` extraction:** The macro expects the field type to be a path ending in `Signal` with
one angle-bracketed argument. It inspects only the last segment of the path (so both `Signal<...>`
and `quartzite_core::Signal<...>` work). If the pattern does not match, it emits `compile_error!`.

**`#[prop(constant)]` implies no notify:** validated at parse time; if both `constant` and
`notify = ...` are present, emit `compile_error!("constant property cannot have a notify signal")`.

**Notify emit form:** When `notify = signal_name` is set, `__write_property` emits the signal as:

```rust
let __notify_val = this.field.clone();
this.signal_name.emit(&(__notify_val,));
```

The value is cloned into a local binding first to avoid holding an immutable borrow of `this.field`
while `this.signal_name.emit` requires a mutable borrow of `this`. The argument is a reference to
a tuple `(T,)` — a single-element tuple — matching `Signal<(T,)>`, which is the canonical
`Signal<Args>` form for single-value notifications. `Signal::emit` takes `&Args` (not `Args`), so
the reference is required. This is consistent with `quartzite-core`'s `Signal<Args>` where `Args`
is always a tuple type.

**`PropertyMeta` flags:** `stored`, `designable`, `user`, `constant`, `read_only` are mapped to
a `PropertyFlags` bitfield or boolean fields as defined in `quartzite-core::PropertyMeta`. The
macro reads the `PropertyMeta` fields' names from the spec; if `quartzite-core` uses a different
layout, only `codegen.rs` must change.

**`#[prop]` with no options** defaults: `read_only = false`, `stored = true`, `designable = true`,
`user = false`, `constant = false`, `notify = None`.

### `#[object_impl]` design

This is an attribute macro on an `impl` block (not a derive).

**IR (`ObjectImplInput`):**

```rust
struct ObjectImplInput {
    self_ty: Type,
    self_ty_ident: Ident,     // extracted from self_ty for name generation
    methods: Vec<MethodItem>,
    other_items: Vec<ImplItem>,  // pass through unchanged
}

struct MethodItem {
    ident: Ident,
    is_slot: bool,       // retained for future use (connection-target metadata); currently has no effect on codegen output
    is_invokable: bool,
    params: Vec<ParamMeta>,      // (name, type) pairs excluding &self/&mut self
    ret_ty: ReturnType,
    block: Block,
    attrs: Vec<Attribute>,       // non-slot, non-invokable attrs preserved
}

struct ParamMeta {
    ident: Ident,
    ty: Type,
}
```

**Generated items (emitted in the same scope as the user's `impl` block):**

- `static __METHODS__{TypeName}: &'static [::quartzite_core::MethodMeta]` — from slots + invokables.
- `fn __invoke_method_{TypeName}(this: &mut {TypeName}, name: &str, args: &[::quartzite_core::Value]) -> ::core::option::Option<::quartzite_core::Value>` — match dispatch; convert each arg via `::quartzite_core::FromValue::from_value(args[i].clone())`; call the method; wrap return via `::quartzite_core::IntoValue::into_value`. If arg count is wrong or conversion fails, return `None` (no panic).
- `static META_{TypeName}: ::std::sync::OnceLock<::quartzite_core::MetaObject>` — initialized lazily.
- `impl ::quartzite_core::Object for {TypeName}` — delegates `meta_object()`, `read_property()`, `write_property()`, `invoke_method()`, `connect_signal()` to the generated fns.
- The original impl block items are re-emitted with `#[slot]` / `#[invokable]` attributes stripped.

**`OnceLock` init expression:**

```rust
META_{TypeName}.get_or_init(|| ::quartzite_core::MetaObject {
    class_name: ::core::stringify!({TypeName}),
    properties: __quartzite_{TypeName}::__PROPS__{TypeName},
    signals:    __quartzite_{TypeName}::__SIGNALS__{TypeName},
    methods:    &__METHODS__{TypeName},
    enums:      &[],
})
```

**Arg conversion in dispatch:** each parameter is converted using
`::quartzite_core::FromValue::from_value(args[i].clone())`. If the index is out of range or
conversion fails, `__invoke_method` returns `None` (not a panic). This is a deliberate safety
choice: dynamic invocation with wrong arity is a caller bug, not an unrecoverable error.

**Parsing `self_ty_ident`:** `#[object_impl]` receives a raw `TokenStream` for the `impl` block.
The `self_ty` is the type after `impl` (potentially with path segments). `self_ty_ident` is
extracted as the last path segment's ident. If `self_ty` is not a simple path (e.g. it is a
reference or pointer type), emit `compile_error!`.

### `#[derive(MetaEnum)]` design

Applied to plain C-like enums (unit variants only; tuple/struct variants → `compile_error!`).

**Generated:**

- `static __ENUM_{TypeName}: ::quartzite_core::EnumMeta` — name + array of
  `::quartzite_core::EnumEntry { name: &str, value: i64 }`.
- `impl ::quartzite_core::IntoValue for {TypeName}` — `Value::Int(self as i64)`.
- `impl ::quartzite_core::FromValue for {TypeName}` — tries to match `Value::Int(n)` against
  variant discriminants; returns `Err(::quartzite_core::TypeError { expected: "{EnumName}", got: val.type_name() })` on no match (using `Value::type_name()` which returns a `&'static str` naming the active variant).

Discriminant values: extracted from explicit discriminants if present; otherwise auto-incremented
from 0 (mirroring Rust's default). The macro reads each `Variant.discriminant` field from syn's
`DeriveInput`; for auto-increment it maintains a counter.

### Utility helpers (`util.rs`)

```rust
/// Strips the `Base` suffix from `name` if it ends with `Base` (case-sensitive).
/// "Base" alone returns "" — callers must check for this and emit a compile_error!.
fn strip_base_suffix(name: &str) -> &str

/// Derives the `As{X}` trait ident from a struct type ident.
/// Strips Base suffix, then prepends "As".
fn as_trait_name(type_ident: &Ident) -> Ident

/// Returns the accessor method name: snake_case of the original type ident.
/// E.g. ObjectBase → object_base, WidgetBase → widget_base, Button → button, Foo → foo.
/// Uses heck::ToSnakeCase. This is the ORIGINAL ident, not the stripped one.
fn accessor_name(type_ident: &Ident) -> Ident

/// Returns the hidden module ident: __quartzite_{TypeName}.
fn hidden_mod_ident(type_ident: &Ident) -> Ident

/// Emits a compile_error! at the given span.
fn emit_compile_error(span: Span, msg: &str) -> TokenStream
```

`heck` is added as a non-proc-macro dependency for string case conversion. It has no runtime
cost in proc-macro context and is widely used in the ecosystem (used by `syn`, `quote` toolchains).

workspace structure, not on `quartzite-core` types.

with no benefit.

## Risks

- **`#[root]` / `#[base]` / `#[mixin]` attribute stripping:** Helper attributes not in a known
  registry cause `rustc` "unknown attribute" errors on the re-emitted struct. The derive macro must
  strip them from both struct-level `attrs` and each field's `attrs`. Risk: easy to miss one site.
  Mitigation: dedicated compile-pass integration test that verifies the emitted struct compiles
  without unknown-attribute errors.

- **Accessor naming divergence:** The accessor name is `snake_case(original_type_ident)`, not
  `snake_case(stripped_trait_name)`. These are the same for non-`Base` types (`Button` → `button`)
  but differ for `Base`-suffixed types (`ObjectBase`: original = `object_base`, stripped = `object`).
  The correct rule must be consistently applied everywhere in codegen; a wrong rule produces trait
  method names that don't match `quartzite-core`'s hand-written trait definitions.
  Mitigation: integration test that uses the macro with a `quartzite-core` dev-dependency and calls
  the accessor by name.

- **Blanket impl orphan rules:** The blanket impl `impl<T: AsWidget> AsObject for T` is generated
  alongside `AsWidget`. This compiles because `AsWidget` is defined in the same expansion. However,
  if a consumer crate defines its own blanket impl over `AsObject`, the two could conflict. This is
  an inherent limitation of the blanket-impl pattern.
  Mitigation: document that downstream crates must not define their own blanket impls for the
  generated hierarchy traits.

- **Blanket impl `as_any` delegation:** `quartzite-core::AsObject` may include `fn as_any(&self) -> &dyn std::any::Any`. The blanket impl must delegate this too. If `quartzite-core` adds methods
  to `AsObject` in the future, the blanket impl codegen must be updated correspondingly.
  Mitigation: centralise all blanket-impl method bodies in `extend/codegen.rs`; keep in sync with
  `quartzite-core::AsObject` definition.

- **Ancestor chain — naming convention fragility:** Parent trait name is derived purely from the
  `#[base]` field's type identifier. If a user writes `base: my_mod::WidgetBase` (path with
  module), the macro must still extract `WidgetBase` as the ident. Mitigation: use the last
  path segment's ident only (same approach as for `Signal` extraction).

- **`Signal<Args>` pattern matching:** The macro parses `Signal<(i32,)>` from the field type AST.
  It must work for both `Signal<...>` and `quartzite_core::Signal<...>`. Mitigation: inspect last
  path segment only; emit `compile_error!` if the pattern doesn't match.

- **`OnceLock` in `no_std` builds:** `std::sync::OnceLock` is stable since Rust 1.70 but requires
  `std`. If the consumer crate is `no_std`, the generated `impl Object` will not compile.
  Mitigation: documented known limitation (consistent with `quartzite-core`'s own deferral of
  `MetaObject` in `no_std`).

- **`#[object_impl]` without `#[derive(Object)]`:** The generated `__invoke_method` fn references
  `__quartzite_{TypeName}::__PROPS__{TypeName}` etc. If `#[derive(Object)]` was not applied, the
  hidden module does not exist and the error message from rustc is unhelpful.
  Mitigation: cannot detect at macro-expand time; document in a `//! # Macro interaction` comment
  that both must be applied to the same type.

- **Generic structs:** Out of scope per spec. The parse step emits `compile_error!` if `generics`
  has any type or lifetime parameters, rather than silently generating incorrect code.

- **`Base` degenerate case:** `strip_base_suffix("Base")` → `""` would produce trait `"As"`.
  Mitigation: `as_trait_name` checks for empty result and emits `compile_error!("type name 'Base'
  alone is too generic; choose a more descriptive name")`.

## Open Questions

1. **`super_meta` wiring — RESOLVED:** `MetaObject` has no `super_meta` field. The actual fields
   are `class_name`, `properties`, `signals`, `methods`, `enums`. Inheritance chain is tracked at
   the trait level by `AsObject` supertraits (generated by `#[derive(Extend)]`), not in
   `MetaObject`. The `#[object_impl]` codegen uses `enums: &[]` for types without declared enums.

2. **Should `#[derive(Object)]` require `#[derive(Extend)]`?** Currently independent. Making it
   mandatory would require type resolution (detecting `AsObject` impl presence), which is out of
   scope. Recommendation: keep independent; enforce by convention and documentation.

3. **`heck` version pin:** Accepted. `heck` `0.5` is the current stable release and is a
   transitive dependency of several proc-macro ecosystem crates. No manual snake_case conversion
   needed.

4. **`trybuild` for compile-error tests:** Accepted. Standard tool for proc-macro error snapshot
   testing; widely used, stable API. Added as dev-dependency.
