Palette state groups — Hover, Pressed, FocusRing

Visual reference for palette-state-groups.proposal.md · issue #402

Light theme = Palette::default · Dark theme = DARK_PALETTE · Cells tagged DERIVED are computed from Normal via the rule in section 01. The FocusRing role is new in this proposal.

01The matrix — every cell, both themes

Each row is a ColorRole; each column is a ColorGroup. Faded cells mirror Normal byte-for-byte. Cells tagged DERIVED are computed at lookup time via: 

Hover(c)   = c.blend(WindowText.Normal, 0.06)
Pressed(c) = c.blend(WindowText.Normal, 0.16)

Light theme: WindowText.Normal = #000000, so hover and pressed both darken (6 % and 16 %). Dark theme: WindowText.Normal = #E8E8E8 (Mercury), so the same factors lighten by the same amounts. v1 ships no explicit overrides — every derived cell follows the formula above. Themes that want different values shadow the cell via Palette::with_role(role, group, color).

04Why FocusRing is its own role

The default FocusRing seed equals Highlight × Normal in both themes — so the byte output of button_focused.png does not change. The reason the slot exists is to let themes diverge when accessibility, palette mood, or contrast budgets demand it, without forking DefaultStyle.

Themes set the divergent value via Palette::default().with_role(ColorRole::FocusRing, ColorGroup::Normal, ...). The two examples above (amber and magenta) are illustrative only — not part of any shipped palette.
